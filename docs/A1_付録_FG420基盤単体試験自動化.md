## A1.1 目的と対象

- **目的**：FG420 が出力する信号（正弦波・方形波・パルス等）を試験条件どおりに自動設定・出力し、
  **基盤（基板）単体の入出力特性を再現性高く試験**する。
- **対象機器**：横河 **FG420**（アービトラリ／ファンクションジェネレータ、**2 チャネル**）。
  - 兄弟機 FG410 は 1 チャネル。**FG420 は 2ch** のため、**チャネル指定**が要点（A1.4）。
  - 主な波形：正弦波・方形波・パルス・ランプ・各種パラメータ可変波形・ノイズ・DC・任意波形。
- **試験の基本形**：FG420 で **刺激信号を印加** → 基盤の応答を測定器（オシロ等）／基盤自身で取得 →
  TestStand で **合否判定**。試験条件を変えて再利用できるシーケンスにする。
- **RAMScope との併用**：本基盤試験では FG420 の刺激に対する基盤（マイコン）の応答確認に
  **RAMScope（RAM 計測、[10](./10_RAMScope実装方針.md)）も利用する**。
  RAMScope はベンチ試験（本編メインプロジェクト）でも使うため、**RAMScope の VI 実体は
  本編メインプロジェクトの `30_RAMScope` に1つだけ置き、本基盤試験プロジェクトからは
  参照して使う**（コピーしない。[03](./03_LabVIEW環境構築.md) 3.5.1「自プロジェクトの成果物を
  別プロジェクトから参照する場合」参照）。FG420 と RAMScope を組み合わせたフローVIは、
  本基盤試験プロジェクト側に別途作成する（[10](./10_RAMScope実装方針.md) STEP4 参照）。

## A1.3 環境構築（着手前の準備）

本編 [03_LabVIEW環境構築.md](./03_LabVIEW環境構築.md) と同じ要領で行う。FG420 固有点のみ記載。

1. **NI-VISA** をインストール（USBTMC / GPIB を VISA で扱う基盤）。
2. **FG420 の LabVIEW ドライバ**を横河サイトから入手し、`instr.lib` に配置
   （または VI Package Manager / 提供インストーラで導入）。本編 [03](./03_LabVIEW環境構築.md) 3.3 の
   バージョン互換性（古い対応表記でも新 LabVIEW で再コンパイルされる）も同様に適用。
3. **接続確認**：
   - USB なら NI MAX に USBTMC デバイスとして見えること、GPIB ならアドレスが見えることを確認。
   - `Open VISA Test Panel` で **`*IDN?`**（ドライバの `IDN` VI 相当）を送り、機器識別が返ることを確認。
   - VISA リソース名を記録（A1.2 の形式）。
4. ビット数（32/64bit）を LabVIEW・Runtime・ドライバで揃える。
5. ドライバ付属の **`VI Tree.vi`** を開くと、利用可能な全 VI が一覧配置されているので最初に確認する。

## A1.4 FG420 制御 VI の設計方針

本編 [05_VI設計方針と共通仕様.md](./05_VI設計方針と共通仕様.md) の共通仕様に準拠する。

### ドライバ VI の粒度 ＝ 本資料の「1イベント1VI」と相性が良い
- 本ドライバの VI は **「1 設定 = 1 VI」**（例：`FREQ`＝周波数だけ、`VOLT`＝振幅だけ）。
  これは本資料の **1イベント1VI** 方針とそのまま一致する。
- 実装の選択肢：
  - **(a) ドライバ VI を TestStand から直接呼ぶ**（最短）。
  - **(b) 共通 I/O（`Status.ctl` / `TestError.ctl`）を付けた薄いラッパ VI にする**
    （本編のエラー／ステータス運用に揃えたい場合）。
  - → 基盤試験では **(a) を基本**とし、判定・トレースを厚くしたい操作だけ (b) でラップするのが効率的。

### チャネル指定（FG420 = 2ch）

`CHAN Mode` でモードを選択してから各設定 VI を呼ぶのが基本フロー。

| CHAN Mode 値 | 意味 | 典型的な使い方 |
|--------------|------|----------------|
| `INDependent` | 2ch 独立モード（デフォルト） | 通常の 2ch 個別制御。ch1・ch2 を独立して設定する |
| `PHAse` | 2 相モード | ch1/ch2 の位相関係を管理。`PHAS`＋`PHAS Init` で位相同期 |
| `TONE` | 周波数差一定モード | `CHAN Delt` で周波数差（Ch2−Ch1）を設定 |
| `RATio` | 周波数比一定モード | `CHAN Rat` で Ch1:Ch2 の整数比（各 1〜9999999）を設定 |
| `DIFFerential` | 差動出力モード | ch1/ch2 を差動出力として使用 |

- **2ch を同じ設定で一括投入**したい場合は `INST Coup`=`ALL` を先に設定する（`ALL`：同時設定有効、`NONE`：同時設定無効）。
  設定後に ch1 へ送った設定が ch2 にも同時反映される。
- **各設定 VI（`FREQ`/`VOLT` 等）のチャネル指定方法**：個別 VI にチャネル選択入力は明示されていない。
  `CHAN Mode`=`INDependent` で独立制御する場合、チャネル切替は機器側の選択 Cmd（または `INST Coup`）で制御される。
  詳細は `IMFG410-63JA` 各 VI ページで確認する。
- **2ch の位相同期**は **`PHAS`（位相設定）＋ `PHAS Init`（位相同期実行）**。

### 共通方針
- **試験条件は TestStand 側で変数管理**（波形・周波数・振幅などを変数化）。
- **内部待ち時間は VI に埋め込まない**（同期／待ちは TestStand 側、本編 [11](./11_TestStandシーケンス構築手順.md)）。

## A1.5 使用する主なドライバ VI（基盤試験で常用）

`IMFG410-63JA` の VI 一覧から、基盤単体試験で使う代表 VI を用途別に抜粋。

> **VI の実ファイル名は `YKFG400 ` プレフィックス付き**。
> VI 一覧の短い名前（`Initialize` / `FUNC` / `FREQ` / `VOLT` / `OUTP` …）は、
> 実体ファイルでは **`YKFG400 Initialize.vi` / `YKFG400 FUNC.vi` / `YKFG400 FREQ.vi` …** となる
> （FG410/FG420 共通ドライバのため接頭辞は `YKFG400`）。以降、本書では短い名前で表記する。

### A1.5.0 ドライバ VI の共通入出力パターン（TestStand 引数マッピングの要）

本ドライバの **設定系 VI は「設定」と「問合せ（読み戻し）」を 1 つの VI で兼ねる**。
入出力の作りがほぼ共通なので、ここを理解すると全 VI を同じ要領で TestStand から呼べる。

**共通の入力**
| 入力 | 型 | 意味 |
|------|----|------|
| `Set <項目>`（例 `Set Frequency`） | Enum：`Input` / `Minimum` / `Maximum` | **`Input`＝下の値を設定**／`Minimum`・`Maximum`＝設定可能な最小・最大値を設定（問合せ時はその min/max を返す） |
| `<項目>`（例 `Frequency`） | 数値 | `Set …＝Input` のとき実際に送る設定値（**設定範囲・分解能は VI ごと**） |
| `Units`（例 `Units(Hz)`） | Enum | 値の単位（必要な VI のみ） |
| `Read` | Boolean | 問合せ（読み戻し）を行うか |
| （標準）VISA リファレンス in / error in | — | 機器ハンドルとエラー伝搬 |

**共通の出力**
| 出力 | 意味 |
|------|------|
| `Query <項目>`（例 `Query Frequency`） | `Read=True` のとき現在値を返す。`Read=False` のときは**無効値**（VI により `0`／`999`／`空白`） |
| （標準）VISA リファレンス out / error out | 後段へ引き回し |

**選択肢系 VI の入力例**（列挙値はそのまま渡す）
- 波形・変調波形：`Function type` = `SINusoid` / `SQUare` / `TRIangle` / `PRAMp` / `NRAMp` / `NOISe` / `USER`
  （`USER` 選択時は `Memory No.` 0〜128 を併せて指定。0＝エディットメモリ）
- 変調源：`Source type` = `INTernal` / `EXTernal`
- ON/OFF 系（例 変調有効）：`State` = `ON` / `OFF`（問合せは `0`=連続発振 / `1`=変調 を返す）

> **TestStand 側の指針**：通常は各 VI で `Set …=Input`・`Read=False`（設定のみ）で使い、
> 値は TestStand 変数から渡す。検証で読み戻したいステップだけ `Read=True` にし、`Query …` を記録・判定に使う。
> Min/Max を使うと「設定可能上下限の取得」もでき、**範囲ガード**（A1.9）に利用できる。

#### 個別 VI の入出力（判明分）
| VI（`YKFG400 …`） | 主な入力 | 主な出力 / 備考 |
|-------------------|----------|------------------|
| `Initialize` | `IDCheck`（ID 照合するか）, `Reset`（リセットするか） | 内部で `*RST` 相当。VISA ref / error |
| `Close` | （VISA ref） | 操作 VI 終了・VISA セッションを閉じる |
| **`FREQ`（搬送波＝出力周波数。中核）** | `Set Frequency`{Input/Min/Max}, `Frequency`(**0.01µHz〜30MHz**, 分解能 **0.01µHz**), `Units(Hz)`, `Read` | `Query Frequency`（Read=False で `0`）。※`AM Freq` 等の**変調周波数とは別 VI** |
| **`VOLT`（振幅＝出力レベル。中核）** | `Set Amplitude`{Input/Min/Max}, `Amplitude`(**0〜20Vp-p（開放/Hi-Z）/ 0〜10Vp-p（50Ω）**, 分解能 0.1mVp-p（<1Vpp）/1mVp-p（≥1Vpp）), `Units`, `Read` | `Query Amplitude`（Read=False で `0`）。**振幅上限は負荷設定で変化**（`OUTP Load`） |
| `AMPL Unit`（振幅の単位選択） | `Unit`{`VPP`/`VPK`/`VRMS`/`DBV`/`DBM`/`USER`}＝Vpp/Vpk/Vrms/dBV/dBm/ユーザ | `Query Unit`（Read=False で空白） |
| **`VOLT Offs`（DC オフセット。中核）** | `Set Offset`{Input/Min/Max}, `Offset`(**±10V（開放/Hi-Z）/ ±5V（50Ω）**, 分解能 0.1mV（≤±499.9mV）/1mV（≥±0.5V）), `Units(V)`, `Read` | `Query Offset`（Read=False で `99`）。**範囲は負荷設定で変化**（`OUTP Load`）。単位は V / USER |
| `AM Freq`（変調周波数。周波数系の典型例） | `Set Frequency`{Input/Min/Max}, `Frequency`(0.1mHz〜100kHz, 5桁/0.1mHz), `Units(Hz)`, `Read` | `Query Frequency`（Read=False で `0`）※これは**内部変調**周波数 |
| `AM Func`（例：波形選択の典型） | `Function type`{SIN/SQU/TRI/PRAMp/NRAMp/NOISe/USER}, `Memory No.`(0〜128) | `Query Function`（Read=False で空白） |
| `AM Sour`（例：源選択の典型） | `Source type`{INTernal/EXTernal} | `Query source` |
| `AM Stat`（例：ON/OFF の典型） | `State`{ON/OFF} | `Query state`（0=連続/1=変調） |
| `AM`（例：深度など値設定の典型） | `Set Depth`{Input/Min/Max}, `Depth`(0.0〜100%, 0.1%) | `Query Depth`（Read=False で `999`） |
| **`OUTP`（出力 ON/OFF。中核）** | `Output(OFF)` = **True**（出力 ON）/ **False**（出力 OFF）[Boolean、キャプションを`ON`/`OFF`にカスタマイズ、デフォルト=False(OFF)], `Read` | `Query State`（Read=True: **0**=OUT OFF / **1**=OUT ON；Read=False: 常に **9**）。共通の `Set …`{Input/Min/Max} パターン**ではなく**、ON/OFF キャプション付き Boolean の直指定 |

> 上の `AM *` は**入出力パターンの代表例**。`FREQ`（周波数）・`VOLT`（振幅）・`VOLT Offs`（オフセット）は
> **共通の `Set <項目>`{Input/Min/Max}＋値＋`Read` パターン**。`OUTP`（出力 ON/OFF）は
> やや異なり **`Output(OFF)`（Boolean、キャプションON/OFF）＋`Read` の 2 入力**（`Set …` 列はなし）。
> ※ 当初 Enum 型と誤って案内していたが、定数化した際の表示（`T`/`F`＝Booleanの省略表示）から
> Boolean であることが判明したため訂正（A1.6.1 STEP4 参照）。
> 中核 VI の確定状況：`FREQ`（済）, `VOLT`（済）, `VOLT Offs`（済）, `OUTP`（済）, `CHAN Mode`/`INST Coup`（未確定→A1.12）。

## A1.6 VI の作り方（ドライバ利用）

本編 [06_VIの作り方_手順.md](./06_VIの作り方_手順.md) をベースに、FG420 では**ドライバ VI を組み合わせる**。

### 基本パターン（ブロックダイアグラム）
```
Initialize ─▶(refnum/error)─▶ FUNC ─▶ FREQ ─▶ VOLT ─▶ VOLT Offs ─▶ OUTP(ON) ─▶ … ─▶ OUTP(OFF) ─▶ Close
            （VISAリファレンスと error in/out を数珠つなぎ：実行順序を確定。本編 04 のデータフロー）
```
- ドライバ VI は **VISA リファレンスと標準の error in/out** を持つので、本編 [04](./04_VIの仕組み_LabVIEW基礎.md)
  4.4/4.6 のとおり**リファレンスとエラーを引き回す**だけで順序とエラー伝搬が成立する。

### 薄いラッパ VI にする場合（任意）
1. テンプレート VI（本編 6.6）を複製。
2. 該当ドライバ VI（例：`YKFG400 FREQ.vi`）を配置し、入力を配線。
   - **設定用途では `Set …` を `Input`、`Read` を `False` に固定**し、外には「設定値」と「ch」だけを出す
     （A1.5.0 の共通パターン）。読み戻し検証用は `Read=True` 版を別途用意してもよい。
3. ドライバの error out を `TestError.ctl`（機器名 `FG420`）/ `Status.ctl` に変換。
   共通サブVI **`Error_To_TestStatus.vi`**（本編 [06](./06_VIの作り方_手順.md) 6.1.2）を呼ぶだけでよい
   （`機器名` 入力に `"FG420"` を配線）。
4. コネクタペインを共通の並びで割り当て（本編 6.4）。
   - 推奨ラッパ（括弧内は実 VI）：
     `FG420_Init`(=`YKFG400 Initialize`) / `FG420_Set_Func`(=`YKFG400 FUNC`) / `FG420_Set_Freq`(=`YKFG400 FREQ`) /
     `FG420_Set_Ampl`(=`YKFG400 VOLT`) / `FG420_Set_Offset`(=`YKFG400 VOLT Offs`) / `FG420_Output`(=`YKFG400 OUTP`) /
     `FG420_Set_Phase`(=`YKFG400 PHAS` + `YKFG400 PHAS Init`) / `FG420_Close`(=`YKFG400 Close`)。

### 補足：SCPI 直叩き（ドライバを使わない場合のみ）
ドライバが使えない環境では VISA で SCPI を送る（本編 [06](./06_VIの作り方_手順.md) 方式B）。
**ドライバが提供されている本案件では不要**。必要時のみ、ドライバの各 VI 名（`FUNC`/`FREQ`/`VOLT`/`OUTP` 等）に
対応する機器コマンドを `IMFG410-63JA`／機器マニュアルで確認して用いる。

## A1.6.1 段階的な構築手順（まず TestStand を使わず単体確認）

中核 VI（`FREQ`/`VOLT`/`VOLT Offs`/`OUTP`/`CHAN Mode` 等）はすべて確定済み（A1.12）のため、

### STEP 0：プロジェクトの土台を作る

本編 [03_LabVIEW環境構築.md](./03_LabVIEW環境構築.md) 3.5.1〜3.5.3 と同じ要領で、
本案件専用のプロジェクトフォルダを用意する（本編の `AutoTestSystem` とは別プロジェクト＝別案件）。

```
C:\LabVIEW work\FG420_TestSystem\        ← プロジェクトルート（実フォルダ）
├─ FG420_TestSystem.lvproj
├─ 00_Common\        … Status.ctl / TestError.ctl（本編と同じ型定義。コピーして流用）
└─ 10_FG420\         … 自作VI（ラッパVI・フローVI）のみをここに保存
```

> 🔴 **`instr.lib` のドライバ VI（`YKFG400` フォルダ）はコピーしない**：
> ドライバは NI 標準の `instr.lib`（例：`C:\Program Files\National Instruments\LabVIEW 20XX\instr.lib\YKFG400\`）
> に置いたままにする。LabVIEW は起動時に `instr.lib` を自動スキャンするため、
> **関数パレット（右クリック→計測器I/O、または検索窓に `YKFG400`）から直接ドラッグして使える**。
> `10_FG420` にコピーして実体を2箇所に分散させると、将来ドライバが更新された際に
> 「どちらが正か」分からなくなる（サードパーティ製ドライバの扱いは本編 [03](./03_LabVIEW環境構築.md)
> 3.5.1 の Vector XL／PPX ドライバと同じ考え方）。
> `10_FG420` に置くのは、その `YKFG400 *.vi` を**呼び出す自作のラッパ VI**
> （`FG420_Init.vi` 等）だけでよい。ラッパ VI 内でドライバ VI を使うと、
> プロジェクトエクスプローラの「依存項目」に該当ドライバ VI が**自動的に**現れる
> （手動追加は不要）。

1. `C:\LabVIEW work\FG420_TestSystem\` を作成し、`00_Common`・`10_FG420` サブフォルダを作る。
2. LabVIEW でプロジェクトを保存 → `FG420_TestSystem.lvproj` として上記ルートに保存。
3. 本編プロジェクトで作った `Status.ctl`／`TestError.ctl` を `00_Common` にコピーする
   （別プロジェクトなので実ファイルごとコピーが必要。中身は同じ型定義でよい）。
4. `00_Common`・`10_FG420` を「自動更新フォルダ」としてプロジェクトへ追加（本編 3.5.3 参照）。
5. ドライバ（`instr.lib\YKFG400\`）が関数パレットに現れるか確認。
   ラッパ VI 作成後は「依存項目」に自動で反映されるため、この時点では見えなくても問題ない。

### STEP 1：LabVIEW を開く前に、実機で通信確認（A1.3 の再確認）

VI を書く前に、**ハードウェアと通信できることを VI 抜きで確認**しておく（問題の切り分けを容易にする）。

> **実機が手元に無い場合**：STEP1 の通信確認は後回しにしてよい。STEP0・STEP3・STEP4
> （プロジェクト作成・ラッパ VI 作成・フロー VI 作成）は実機無しで進められる
> （ブロックダイアグラムの配線・保存は実機接続と無関係）。
> - STEP4 の `FG420_Flow_Test.vi` は実機無しでも一度実行してみるとよい。
>   `FG420_Init.vi`（`Initialize`）が存在しない VISA リソースに対して**必ず VISA エラーを返す**ため、
>   これを利用して「エラー発生時に `OUTP`(OFF)→`Close` が確実に実行されるか」という
>   A1.9 の安全要件を、**実機を使わずに（意図せず）検証できる**（天然のエラー注入テスト）。
> - 実機入手後は、VISA リソース名を実機の値に差し替えて再実行するだけでよい。

1. NI MAX で FG420 が USBTMC／GPIB デバイスとして認識されているか確認。
2. `Open VISA Test Panel` で `*IDN?` を送り、機器識別文字列が返ることを確認 → VISA リソース名を記録。
3. ドライバの `VI Tree.vi` を開いて、A1.5 の VI が実際にパレットに存在することを目視確認。

### STEP 2：「全部乗せ」の1本のVIでまず物理的な波形出力を確認する（ラッパ化より先）

A1.6 の「薄いラッパ VI」を作り込む**前に**、まずドライバ VI を直接つないだ**単一の VI**で
実際に FG420 から波形が出ることを確認する。ここで先にラッパ化すると、配線ミスなのか
ラッパの作り方の問題なのか切り分けにくくなるため、**最初は生のドライバ VI を直結**する。

```
[VISA リソース名(定数)]
      │
      ▼
YKFG400 Initialize ──▶ YKFG400 FUNC(SINusoid) ──▶ YKFG400 FREQ(1000Hz, Set=Input, Read=False)
      ──▶ YKFG400 VOLT(1.0Vpp, Set=Input, Read=False) ──▶ YKFG400 VOLT Offs(0V, Set=Input, Read=False)
      ──▶ YKFG400 OUTP(Output=ON)
      ──▶ [Wait 1000ms]
      ──▶ YKFG400 OUTP(Output=OFF) ──▶ YKFG400 Close
（VISA リファレンスと error in/out を全 VI で数珠つなぎ。A1.6 の基本パターンそのもの）
```

- フロントパネルには波形・周波数・振幅・オフセットの数値/Enum 制御器を並べ、
  **定数ではなく試験条件として直接触れる**ようにしておく（後で TestStand 変数に置き換える前提）。
- **オシロ等の測定器がまだ無くても、テスタ／オシロの単体（プローブ当てるだけ）で
  実際に波形が出ているか目視確認できれば OK**。この段階の目的は「ドライバと配線が
  正しく機能するか」の確認であり、合否判定はまだ組み込まない。
- ここで問題が出た場合は、A1.12 の残課題（ch 切替方法・Ethernet 可否など）を疑う前に、
  まず `Read=True` にして `Query …` の値を見る、`SYST Err` を挟む、等でドライバ層の
  応答を確認する。

### STEP 3：確認が取れたら、個別ラッパ VI に分解する（A1.6 の「薄いラッパ」化）

STEP 2 で物理動作を確認できたら、`10_FG420\` に個別 VI として分解する。
**全 VI の実端子を Ctrl+H で確認済み**（下表）。以降、新しい VI を作るたびにこの表を更新していく。

**共通パターン（全VIで同じ）：** `FG420_Init.vi`（本編 [06](./06_VIの作り方_手順.md) 6.1.2）で確立した型を踏襲。

1. `10_FG420` に新規VI作成 → フロントパネルに入出力配置。
2. ドライバVIを1個配置し、VISA参照を in→out 貫通配線。
3. ドライバの`Error Out`を`Error_To_TestStatus.vi`（機器名`"FG420"`）へ接続、3出力を個別に配線。
4. **`Units`／`Set …(Input)`／`Read`など、常に同じ値に固定したい端子は右クリック→「定数に変更」**
   （制御器のままフロントパネルに残すと、次のコネクタペイン割当の対象に紛れ込みやすい。
   本編 [06](./06_VIの作り方_手順.md) 6.4.1 の判断基準を参照）。
   **⚠️ `FG420_Output.vi`は例外**：`Read`は他VI同様に定数化してよいが、`Output(OFF)`
   自体は「値そのもの」が呼び出し側ごとに変わる試験条件なので**制御器のまま**にする
   （定数化すると、何度呼び出しても同じ値しか渡せなくなり、ON/OFFの切り替えができなくなる）。
   他VIの`Set …(Input)`のような「モード選択」ではなく「設定値」に相当するため、
   機械的に定数化しないよう注意。
5. **コネクタペイン割当**（本編6.4・6.4.1）：VISAリファレンス(in/out)・試験条件の値
   （周波数／振幅／チャンネル等）・`error in/out`・`実行結果ステータス`・`エラー情報`のみを割り当てる。
   手順4で定数化した端子は自動的に割当対象から外れる。`Query…`系の出力（`Read=False`固定時は
   常に無効値）も割り当てない。入出力の並びは全VIで統一する（本編6.4手順3）。
6. 保存。

### STEP 4：ラッパ VI を組み合わせて「フロー確認 VI」を1本作る（引き続き TestStand 不使用）

`10_FG420\` に **`FG420_Flow_Test.vi`** を新規作成し、STEP 3 のラッパ VI を
A1.8 の典型フロー順に呼び出す。**この VI 単体で実行すれば、TestStand 無しで
一連の試験フローが通しで動くこと**を確認できる状態にする。

```
FG420_Init
  → FG420_Set_Func → FG420_Set_Freq
  → FG420_Set_Load（★振幅/オフセットより先に呼ぶ。範囲が負荷設定に依存するため。STEP3.3/3.4/3.5参照）
  → FG420_Set_Ampl → FG420_Set_Offset
  → FG420_Output(ON)
  → Wait（フロントパネルの数値制御器で待ち時間を試験条件として与える）
  → （応答測定：オシロ等が未接続なら、この段階はダミーの数値制御器で代用してもよい）
  → （合否判定：しきい値との比較。オシロ未接続ならスキップ可）
  → FG420_Output(OFF)
  → FG420_Close
```

> **Wait の組み方**：LabVIEW標準の`Wait (ms)`関数（プログラミング→タイミング）には
> `error in`/`error out`端子が無いため、置くだけでは「`Output(ON)`の後・`Output(OFF)`の前」
> という実行順序を保証できない。**フラットシーケンス構造**で挟んで順序を強制する。
> 1. フロントパネルに`待ち時間(ms)`（数値制御器）を追加し、他の試験条件と同様にコネクタ
>    ペインへ割り当てる。
> 2. 関数パレット→プログラミング→構造→**フラットシーケンス構造**を配置し、2フレームに分ける。
> 3. フレーム1に`FG420_Output(ON)`、フレーム2に`Wait (ms)`（`待ち時間`制御器を配線）を置く。
> 4. エラークラスタのワイヤは各フレームの境界を貫通させて配線する（`Wait`自体に接続する
>    必要はなく、素通りでよい）。
> 5. その後（計測・判定フレームがあれば追加）、`FG420_Output(OFF)`を配置する。
>
> フラットシーケンスは「左のフレームが完了するまで右のフレームは開始しない」という
> 実行順序を保証するため、`Wait`にエラー端子が無くても正しく直列実行される。

> **`FG420_Output.vi`への配線は Boolean 定数（`True`＝ON／`False`＝OFF）でよい**。
> `Output(OFF)`端子は当初 Enum 型と案内していたが誤りで、実際は **Boolean にカスタム
> キャプション（`ON`/`OFF`）を設定した端子**（Ctrl+H表示`Output(OFF)`の`(OFF)`は
> 「デフォルト値=False、キャプション=OFF」を示していた）。右クリック→「定数を作成」で
> 作った定数を選択すると、表示が小さいうちは`T`/`F`（True/Falseの省略表示）に見えるが、
> これはBoolean定数である証拠であり、Enumではない。四隅のハンドルで幅を広げれば
> `ON`/`OFF`のフルキャプションが表示される場合がある。
> ただし**定数（Constant）はブロックダイアグラム上だけの存在でフロントパネル実体を
> 持たない**ため、制御器/表示器が持つ「プロパティ→外観タブ」のようなキャプション編集
> 機能自体がない（右クリックメニューにも「外観」は出てこない）。広げても`T`/`F`の
> ままなら、それ以上見た目は変えられないので割り切ってよい。型変換は発生しておらず
> 値（True=ON／False=OFF）は正しく配線されているため、Boolean定数のままで問題ない。

- **エラー情報／実行結果ステータスの配線**：チェーン中の各ラッパ VI（`FG420_Set_Func.vi`等）
  自身が持つ`実行結果ステータス`／`エラー情報`出力は、`FG420_Flow_Test.vi`の中では
  **途中段では配線しない**（各ラッパVI内部で個別に`Error_To_TestStatus.vi`を呼んでいるのは
  そのVI単体をTestStandの1ステップとして単独利用する場合の保険であり、複数VIを直列で
  つなぐ場合は不要）。`error in`にエラーが入っていれば後続VIは実処理をスキップして
  そのままエラーを通す（標準のLabVIEWエラー伝播）ので、**`error out`だけをチェーンで
  次々に渡し**、チェーンの最後（`FG420_Close`の後）でもう一度`Error_To_TestStatus.vi`を
  1回だけ呼んで、`FG420_Flow_Test.vi`全体としての`実行結果ステータス`／`エラー情報`／
  `error out`を出す。どのステップで失敗しても元のエラー（発生源のコード・メッセージ）が
  そのまま伝播しているため、最後の1回の変換で失敗箇所まで追跡できる。
- フロントパネルの制御器（波形・周波数・振幅・オフセット・待ち時間等）が
  **そのまま TestStand 変数化の対象リスト**になる（A1.7 手順2 の前倒し確認）。
- **エラー注入テスト**：あえて VISA リソース名を誤らせる等でエラーを発生させ、
  それでも `FG420_Output(OFF)` → `FG420_Close` が実行される（Cleanup 相当の処理が
  機能する）ことをこの段階で確認しておく（A1.9 の安全要件を TestStand 導入前に検証）。
  ※ TestStand 無しの単一 VI では「必ず実行される Cleanup」を自前で作る必要がある点に注意
  （エラークラスタを見て分岐しつつ、**Output(OFF) と Close だけは条件によらず必ず通る**
  ように配線する、または LabVIEW の「エラー処理付きサブVI」テンプレート／Timed Sequence 等で保証する）。

> **試験用 PC へ渡して確認してもらう場合**（EXE ビルドでの配布）：
> 本編 [03](./03_LabVIEW環境構築.md) 3.6 の手順（開発 PC でのビルド → 試験用 PC への
> Run-Time Engine/NI-VISA 導入 → VISA リソース名の再確認）に従う。

### STEP 5：TestStand への移行（A1.7 へ）

STEP 4 の `FG420_Flow_Test.vi` が単体で問題なく動作したら、初めて A1.7 の手順へ進む。
STEP 4 のフロントパネル制御器がそのまま「試験条件変数」の一覧になっているため、
TestStand 側の変数設計（A1.7 手順2）はほぼそのまま転記できる。サブシーケンス化
（`SubSeq_FG設定`／`SubSeq_出力ON`／…）は、STEP 3 のラッパ VI をそのまま
`Sequence Call`／`Action` ステップとして呼ぶだけでよい。

## A1.7 TestStand シーケンス構築手順

本編 [11_TestStandシーケンス構築手順.md](./11_TestStandシーケンス構築手順.md) に準拠。

1. **LabVIEW Adapter** を設定し、ドライバ VI（またはラッパ VI）を呼べるようにする。
2. **試験条件を変数化**（FileGlobals / Parameters）：
   - `波形種別`、`周波数`、`振幅`、`オフセット`、`位相`、`チャネル`、`負荷Z`、`判定しきい値` 等。
   - 条件を CSV / プロパティファイルで管理し、`Property Loader` で読み込むと条件変更が容易。
3. **イベント単位のサブシーケンス化**（本編 11.5）：
   - `SubSeq_FG設定`（`FUNC`→`FREQ`→`VOLT`→`VOLT Offs`→（`PHAS`/`PHAS Init`）→（`OUTP Load`））
   - `SubSeq_出力ON`（`OUTP` = ON）
   - `SubSeq_応答測定`（オシロ等で取得、または基盤からの読み出し）
   - `SubSeq_判定`
   - `SubSeq_出力OFF`（`OUTP` = OFF）
4. **MainSequence** で `Sequence Call` により順序を構成。条件で並び替え・流用。
5. **合否判定**：測定値と `判定しきい値` を比較し、ステップ Status（Pass/Fail）を設定。
   エラーは `SYST Err`／ステータスレジスタ（`OPER*`/`QUES*`）で確認。
6. **同期／非同期・待ち**は TestStand 側で明示（出力安定待ちは `Wait`、設定確定は `OPC`/`WAI`）。
7. **レポート**：試験条件・設定値・測定値・合否を記録（本編 11.7）。

## A1.8 基盤単体試験の典型フロー（例）

```
Setup    : Initialize（*IDN?確認） / OUTP Pon=OFF / 測定器Init / 条件ロード
Main
  ├ SubSeq_FG設定: FUNC(波形) → FREQ(周波数) → VOLT(振幅) → VOLT Offs(オフセット)
  │               → (OUTP Load 整合) → (2ch時: CHAN Mode / PHAS / PHAS Init)
  ├ SubSeq_出力ON: OUTP(ON)   （+ 必要なら TRIG でバースト/単発発行）
  ├ Wait（出力・基盤の安定待ち：時間は条件変数）
  ├ SubSeq_応答測定（オシロ波形 / 基盤の出力値取得）
  ├ SubSeq_判定（測定値 vs しきい値 → Pass/Fail）
  └ SubSeq_出力OFF: OUTP(OFF)
Cleanup  : OUTP(OFF)（全ch） / Close / 測定器Close   ← 異常時も必ず実行
```

- 複数条件（周波数スイープ等）は、条件配列で **For ループ** で回すか、機器内蔵スイープ（`FREQ*`/`SWE*`）を使う。
- 2ch を使う試験は、`CHAN Mode` を設定のうえ ch1/ch2 を設定・`OUTP`、必要なら `PHAS Init` で位相同期。

## A1.9 異常系・安全

本編 [12_異常系処理とシャットダウン設計.md](./12_異常系処理とシャットダウン設計.md) の考え方を適用。

- **Cleanup で必ず `OUTP`=OFF（全ch）→ `Close`** を実行（異常終了でも出力を残さない）。
- **`OUTP Pon`=OFF** に設定（電源投入時に出力 OFF＝予期せぬ印加を防止）。
- 基盤に過大入力を与えないよう、**振幅・オフセットの上限を試験条件側でガード**（範囲チェック）。
  振幅は **0〜20Vpp（開放）/ 0〜10Vpp（50Ω）**、オフセットは **±10V（開放）/ ±5V（50Ω）** で、
  いずれも **負荷設定により上限が変わる**点に注意。
- **`OUTP Load`（負荷インピーダンス）を基盤条件に合わせる**（不整合で実効レベルがずれる／上限も変わる）。
- 異常時のエラー（機器名 `FG420`・`SYST Err` 内容）を `TestError.ctl` で TestStand へトレース。

## A1.12 残課題（着手時に確認）

### 確定情報の凡例（2種類の「確定」を区別する）

本付録では2種類の「確定」を区別する。**両者は信頼度が異なる**ため、実装時は区別して扱うこと。

| 凡例 | 意味 | 信頼度 |
|------|------|--------|
| ✅ **マニュアル確認済み** | `IMFG410-63JA` の当該VI専用ページのスクリーンショットで確認 | 高（ただし端子の網羅性はページの記載次第）|
| ✅ **Ctrl+H確認済み** | LabVIEW上で実際にVIのヘルプ表示（Ctrl+H）を見て、コネクタペインの全端子を直接確認 | **最も高い**（実装に使う端子が漏れなく分かる）|
| 🟡 **類推（未確認）** | 別の類似VI（`AM Func`等）のパターンから推測した内容 | **低い。実際と食い違うことがある**（`FUNC`のCh?端子見落としが実例）|

**方針**：これから各VIを実際にLabVIEWで作成する際は、**必ずCtrl+Hで実端子を確認してから配線する**。
本ドキュメントの記載が「類推」のままの項目は、Ctrl+Hのスクリーンショットを見せてもらった時点で
「Ctrl+H確認済み」に更新し、記載を実物に合わせて修正する（`FUNC`のケースと同様）。
