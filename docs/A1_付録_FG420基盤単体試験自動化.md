# 付録 A1. FG420 を用いた基板単体試験 自動化手順（VI / TestStand）

> **本付録の役割**：ファンクションジェネレータFG420を使用し、基板へ刺激信号を印加する自動試験の構成と着手手順を定義する。
>
> 本付録は本編の設計方針を流用する。新規VIの詳細手順は[00A](./00A_LabVIEW実装資料の記述ルール.md)の「目的 → 入出力 → 配置関数 → 配線順 → 単体テスト」に従う。
>
> 横河提供LabVIEWドライバを使用する場合も、「ドライバVIを呼ぶ」だけで終わらせず、正式なVI名、入力端子、出力端子、接続順、単体テストを記載する。

---

## A1.1 目的と対象

### 目的

FG420が出力する正弦波、方形波、パルス等を試験条件どおりに設定し、基板の入出力特性を再現性高く評価する。

### 対象

| 項目 | 内容 |
|---|---|
| 機器 | 横河FG420、2チャンネルファンクションジェネレータ |
| 刺激信号 | 正弦波、方形波、パルス、ランプ、ノイズ、DC、任意波形 |
| 測定 | オシロ、基板自身の出力、必要に応じてRAMScope |
| 判定 | TestStandで条件管理、合否判定、レポート |

FG410は1チャンネル、FG420は2チャンネルのため、公開APIの入力へChannel指定を持たせる。

### RAMScopeとの併用

RAMScope VI実体は本編メインプロジェクトの`30_RAMScope`へ1セットだけ置く。本付録用プロジェクトへコピーせず、既存VIを参照する。

```text
FG420で刺激信号を出力
  → DUT応答をオシロまたはRAMScopeで取得
  → TestStandで合否判定
```

## A1.2 機器構成とインタフェース

| 項目 | 内容 |
|---|---|
| リモートI/F | USB（USBTMC）またはGP-IB |
| 制御方法 | 横河提供LabVIEWドライバのVIを呼ぶ |
| ドライバ資料 | `IMFG410-63JA`を確認 |
| VISAリソース例 | USB：`USB0::0x0B21::0x****::<SERIAL>::INSTR` |
| VISAリソース例 | GPIB：`GPIB0::<アドレス>::INSTR` |

Ethernet制御の可否は対象機器仕様で確認する。未確認のインタフェースを採用済みとして記載しない。

---

## A1.3 環境構築

### 0. 目的

LabVIEWからFG420ドライバを呼び、VISA接続と機種識別ができる状態にする。

### 1. 導入するもの

| 項目 | 用途 | 確認方法 |
|---|---|---|
| NI-VISA | USBTMC / GPIB通信 | NI MAXで認識確認 |
| FG410/FG420 LabVIEWドライバ | 機器操作VI | `VI Tree.vi`とサンプルを確認 |
| LabVIEW 64bit | VI開発 | 版とbit数を記録 |
| TestStand | 試験フロー | Adapter設定を確認 |

### 2. 操作手順

1. NI-VISAをインストールする。
2. FG420ドライバをメーカー提供手順で導入する。
3. LabVIEWの`instr.lib`または導入先へドライバVIが配置されたことを確認する。
4. FG420をUSBまたはGPIBで接続する。
5. NI MAXで対象VISAリソースを確認する。
6. VISA Test Panelを開く。
7. `*IDN?`またはドライバのIDN相当VIを実行する。
8. 応答文字列、VISAリソース名、確認日を記録する。
9. `VI Tree.vi`を開き、利用可能な公開VI名を一覧化する。
10. 代表サンプルを実行し、Open → 設定 → Output → Closeの順序を確認する。

### 3. 完了条件

- [ ] NI MAXでFG420を認識する
- [ ] 機種識別応答を取得する
- [ ] `VI Tree.vi`を開ける
- [ ] LabVIEW 64bitでドライバVIの壊れた実行矢印がない
- [ ] 開発PCと試験PCの導入差分を記録する

## A1.4 FG420公開APIの設計

### なぜ薄いラッパを作るのか

横河ドライバVIは「1設定=1 VI」の粒度であり、本システムの1イベント1VI方針と合わせやすい。ただし、TestStandへ直接公開するとStatus、TestError、命名、Verify方法が他機器と異なる。

次のどちらかを操作ごとに選ぶ。

| 方式 | 使用条件 |
|---|---|
| ドライバVIをTestStandから直接呼ぶ | 単純な設定で、共通Statusが不要な場合 |
| 共通公開APIで薄くラップする | Verify、ログ、Status、TestErrorを統一する場合 |

### 作成候補VI

| VI | 主な入力 | 主な出力 | 役割 |
|---|---|---|---|
| `FG420_Init.vi` | VISA Resource、Reset、error in | VISA Ref、機種情報、Status、error out | 接続・機種確認 |
| `FG420_Waveform_Set.vi` | VISA Ref、Channel、波形種別 | VISA Ref、設定結果 | 波形選択 |
| `FG420_Frequency_Set.vi` | VISA Ref、Channel、Frequency | VISA Ref、読返値 | 周波数設定とVerify |
| `FG420_Amplitude_Set.vi` | VISA Ref、Channel、Amplitude、Offset | VISA Ref、読返値 | 振幅・Offset設定 |
| `FG420_Phase_Set.vi` | VISA Ref、Channel、Phase | VISA Ref、読返値 | 位相設定 |
| `FG420_Output_On.vi` | VISA Ref、Channel | VISA Ref、状態 | 出力ON |
| `FG420_Output_Off.vi` | VISA Ref、Channel | VISA Ref、状態 | 出力OFF |
| `FG420_Close.vi` | VISA Ref、error in | error out | 出力OFF後にClose |

各VIを実装するときは、メーカー提供VIの正式名を`配置する関数およびSubVI等`の表へ記載する。

## A1.5 共通配線ルール

1. `error in.status`を外側Case Structureへ接続する。
2. Trueケースでは機器操作をせず、VISA Refと元エラーを後段へ渡す。
3. Falseケースでメーカー提供VIを呼ぶ。
4. Channel、波形、周波数等の入力を、メーカーVIの正式な入力端子へ接続する。
5. VISA Refとerror clusterをドライバVI間で直列接続する。
6. 設定後に読出しVIがある場合は読み返してVerifyする。
7. 最後のerror clusterを`Error_To_TestStatus.vi`へ接続する。
8. 公開APIの全端子をコネクタペインへ割り当てる。

「FrequencyをValueへ接続する」のような省略をせず、`Frequency`入力を`<メーカーVI名>`の`<正式端子名>`へ接続すると記載する。

## A1.6 単体テスト

### 正常テスト

1. Channel 1へ1 kHz、1 Vppの正弦波を設定する。
2. Output Onを実行する。
3. オシロで周波数、振幅、Offsetを測定する。
4. FG420設定値、読返値、オシロ実測値を記録する。
5. Output Offを実行し、出力が停止することを確認する。

### 2チャンネルテスト

Channel 1と2へ異なる値を設定し、チャンネル指定の配線取り違えがないことを確認する。

```text
CH1: 1 kHz、1 Vpp
CH2: 2 kHz、2 Vpp
```

### 異常テスト

| 条件 | 期待結果 |
|---|---|
| Channel範囲外 | 入力不正エラー、機器操作なし |
| 周波数範囲外 | ドライバまたはローカル検証エラー |
| VISA切断 | 通信エラーとTestError |
| 既存error in | 機器操作なし、元エラー保持 |
| Cleanup | 前段エラーでもOutput OffとCloseを試行 |

## A1.7 TestStand基本フロー

```text
Setup
  FG420_Init.vi
  FG420_Waveform_Set.vi
  FG420_Frequency_Set.vi
  FG420_Amplitude_Set.vi

Main
  FG420_Output_On.vi
  Wait
  DLM5058_Acquire_Start / RAMScope_Log_Start
  DUT試験イベント
  計測・判定
  FG420_Output_Off.vi

Cleanup
  FG420_Output_Off.vi
  FG420_Close.vi
```

試験条件はParametersまたはProperty Loaderで管理し、VIへ固定値を埋め込まない。

---

## A1.8 本付録の更新ルール

- メーカーVI名と端子は実際の`VI Tree.vi`とドライバヘルプで確認する。
- 未確認のVI名を推測で記載しない。
- 詳細VIを追加する場合は00Aの確認表でレビューする。
- FG420固有の情報だけを本付録へ記載し、RAMScope詳細を複製しない。
- 実機試験結果を入力値、測定方法、期待値、実測値で残す。
