# 04. VI 設計方針と共通仕様

## 4.1 VI 設計の基本方針

### 1イベント1VI

試験のイベントごとに 1 つの VI を作成する。

| 例（イベント） | VI 名（例） |
|----------------|-------------|
| RAMScope 計測開始 | `RAMScope_Log_Start.vi` |
| RAMScope 計測停止 | `RAMScope_Log_Stop.vi` |
| RAMScope リセット | `RAMScope_Reset.vi` |
| オシロ計測開始 | `DLM5058_Acquire_Start.vi` |
| オシロ波形保存 | `DLM5058_Save_Waveform.vi` |
| 温度ロガー計測開始 | `MX100_Log_Start.vi` |
| 高圧電源 電圧設定 | `RZX_Voltage_Set.vi` |
| 高圧電源 出力ON | `RZX_Output_On.vi` |
| 負荷電流ランプ | `Load_Current_Ramp.vi` |
| 低圧電源 電圧設定 | `PPX_Voltage_Set.vi` |
| CAN 制御モード送信 | `CAN_Send_Mode.vi` |

**メリット**
- 並び替えが容易（TestStand 側でステップ順を変えるだけ）
- テスト仕様の変更に強い（1 VI の修正で済む）
- 別試験への流用が容易

> 命名規則：`<機器/対象>_<動作>.vi`（英数字）。フォルダ（ライブラリ）で機器ごとに整理する。

## 4.2 入出力の共通仕様（コネクタペイン）

すべての制御 VI で、入出力の「型」と「並び」を統一する。
→ TestStand 側のステップ作成が定型化でき、流用しやすくなる。

### 入力（Controls）

| 端子 | 型 | 説明 |
|------|----|------|
| **機器リファレンス in** | VISA / セッション参照 | 接続済みの機器ハンドル（Setup で確立して引き回す） |
| **試験条件（可変）** | 数値/Enum 等 | 電圧条件・電流条件・制御モード番号・Ramp 時間 など |
| **error in** | error cluster | 標準のエラークラスタ（前段エラーを引き継ぐ） |

代表的な試験条件入力（例。必要に応じ追加）：

| 入力 | 管理元 | 目的 |
|------|--------|------|
| 電圧条件 | TestStand（試験条件） | 変数化し様々な電圧条件の試験を実施 |
| 電流（負荷条件） | TestStand（負荷条件） | 変数化し様々な負荷条件の試験を実施 |
| 制御モード番号 | TestStand（試験条件） | CAN でマイコンに送る動作モード。条件に合わせ遷移条件を設定 |
| Ramp 時間 | TestStand（試験条件） | 機器応答特性／試験条件に応じ電流・電圧の変化速度を変更 |

### 出力（Indicators）

| 端子 | 型 | 説明 |
|------|----|------|
| **機器リファレンス out** | VISA / セッション参照 | 後段 VI へ引き回す |
| **実行結果ステータス** | Enum（型定義 `Status.ctl`） | TestStand が次ステップ進行／中断を判断 |
| **エラー情報** | クラスタ（型定義 `TestError.ctl`） | どの機器で何が起きたかをトレース |
| **計測値**（必要な VI のみ） | 数値/配列 | 現在出力電流値・波形・温度・RAM 値 など。ログ／TestStand へ |
| **error out** | error cluster | 標準のエラークラスタ |

> **内部待ち時間は VI に入れない**：同期・非同期・条件分岐・待ち時間は TestStand 側で
> 明示的に設計する。VI は「呼ばれたら即実行して返す」ことに徹する
> （例外＝非同期で動かす負荷ランプ VI。[07](./07_負荷電流VIと並列処理.md) 参照）。

## 4.3 ステータスの型定義（`Status.ctl`）

実行結果ステータスは Enum 型定義として共通化する。例：

| 値 | 意味 | TestStand の扱い |
|----|------|------------------|
| `OK` | 正常完了 | 次ステップへ進む |
| `Warning` | 警告（継続可） | 記録して継続 |
| `Error` | 異常（中断） | 試験中断 → Cleanup へ |
| `Timeout` | 応答タイムアウト | 異常扱い |

## 4.4 エラー情報の型定義（`TestError.ctl`）

エラー内容を TestStand に送り、トレース可能にする。クラスタ項目（例）：

| 項目 | 型 | 説明 |
|------|----|------|
| `機器名` | String | 例：`DLM5058`, `RZ-X 高圧模擬1`, `RAMScope` |
| `エラーコード` | I32 | 機器固有 or 自前定義 |
| `エラーメッセージ` | String | 内容（人が読める文字列） |
| `発生時刻` | Timestamp | タイムスタンプ |
| `致命度` | Enum | `Recoverable` / `Fatal` |

## 4.5 標準のエラー伝播

- LabVIEW 標準の **error in / error out クラスタ** を全 VI に配線する。
- error in にエラーが入っている場合、VI は実処理をスキップしてエラーを通す
  （`Case Structure` の `No Error` / `Error` でガード）。
- 機器固有のエラーは error out と「エラー情報（`TestError.ctl`）」の両方に反映し、
  TestStand 側でステータス判定とトレースができるようにする。

## 4.6 リファレンス（接続ハンドル）の引き回し

- 機器の接続（VISA Open / セッション確立）は **TestStand の Setup で 1 回だけ** 行い、
  リファレンスを FileGlobals 等に保持する。
- 各操作 VI はそのリファレンスを入力で受け取り、毎回 Open/Close しない（高速化・安定化）。
- クローズ（VISA Close / セッション解放）は **Cleanup で最後に 1 回** 行う。
