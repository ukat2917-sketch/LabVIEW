# 3. IS8000で確認済みの設計事実

## 3.1 APIが2系統

**確定:**

- User Library: `IS8000SDK.dll`を用いてIS8000へ新しいDAQ Source/File Sourceを追加する。
- Control API: 外部ApplicationからgRPCでIS8000を操作する。Control Application作成に`IS8000SDK.dll`は不要。

この境界を設計正本とする。

## 3.2 User Library開発条件

入手した現行ManualではUser LibraryはC#/.NET 8/64bitを前提とする。

## 3.3 Control API

入手済みproto/help/sampleで、Device/DataSource、Tab、Monitor、Record、SaveFolder、Waveform、Project等のAPIが確認できている。

**未確定:**

- `MDF` recordingの実際のMDF version / `.mf4`可否
- File nameを外部から直接指定できるか
- Recording artifact生成完了を確実に判定する最終手順
- Timestampの絶対時刻Source
- DLM5000が対象IS8000 Versionでどの範囲まで標準Data Source/Control対象になるか

# 4. RAMScopeで確認済みの設計事実

入手したRev.5.0 API仕様書では以下を確認済み。

- Target MCU RAM Read/Write機能がAPI基本機能に含まれる。
- `RAMScopeGT150MemoryRead/Write`
- `RAMScopeGT150ContinualyMemoryRead/Write`
- GT17x `RAMScopeGT170ScenarioWriteStart/Stop`
- Memory Read/WriteはMeasurement中にも利用可能。
- Measurement中のMemory Read/Writeは測定周期末に実行される。
- Scenario WriteはPRO License対象。
- Packet TimestampはMeasurement startを0とする20 ns countとして記載されている。

## 4.1 bitness競合

**Critical open issue:**

Rev.5.0 PDFは32bit native/WOW64と記載する一方、既存本編は対象環境で`RAMScopeVP_API_x64.dll`を採用している。

Projectでは次を実機/実ファイルで再確認する。

```text
RAMScope I.K. Version
RAMScopeVP_API DLL file name
PE bitness
Header revision
Export symbols
Runtime dependencies
```

既存本編のx64実装を、古いPDF記載だけを理由に変更しない。
