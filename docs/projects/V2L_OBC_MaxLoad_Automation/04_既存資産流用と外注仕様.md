# 04. 既存資産流用と外注仕様

**最終整理日:** 2026-09-03  
**State:** Design draft

---

## 1. 流用方針

本Projectは既存LabVIEW本編の資産をコピーして派生実装を増やさない。

```text
Common / Shared
├─ Status / TestError / error cluster思想
├─ CANalyzer ActiveX Adapter
├─ CANalyzer Session Registry
├─ RAMScope Driver / Parser / Logging
├─ TestStand Setup/Main/Cleanup原則
└─ Safety / Cleanup原則

Project specific
├─ Chroma最大負荷Adapter要求
├─ WT5000/MX100/IS8000統合
├─ DLM5000 Oscilloscope Adapter
├─ INCA/ETK Adapter
├─ Project Run Manifest
├─ Cross-recorder synchronization
└─ V2L/OBC試験Sequence
```

Project固有要求のためにShared VIの意味を変えない。Shared APIで不足する機能はProject側にExtension要求として記録し、共通化するかは別レビューで決める。

**オシロスコープはYokogawa DLM5000シリーズをProject標準機種としてFixし、DLM5000 AdapterはProject specificとして設計する。**

# 2. CANalyzer流用

## 2.1 そのまま流用する設計

- [`../../09_CAN通信の実装.md`](../../09_CAN通信の実装.md)

新規実装が必要でも、既存Session Registryを迂回して別Application Refを開かない。

# 3. RAMScope流用

## 3.1 そのまま流用する設計

RAMScopeの正本は[`../../10_RAMScope実装方針.md`](../../10_RAMScope実装方針.md)。以下を流用する。

- Connect / Init / Set Condition
- Measurement / Logging lifecycle
- Builder / Parser
- Error conversion
- Thin DLL Wrapper思想
- TDMS保存
- `PoC_RAMScope_Main.vi`
- `PoC_RAMScope_Logging_Main.vi`

Project側でRAMScopeの既存VI名・I/O・layerを独自変更しない。

## 3.2 Project Extension候補

オンライン適合のためのMemory Read/WriteおよびScenario Writeは、既存正本に未実装ならProject Extensionとして追加検討する。

ExtensionをSharedへ昇格する場合も、`薄いWrapper → Service/Public API`の既存layer規則へ従う。

# 4. TestStand流用

[`../../11_TestStandシーケンス構築手順.md`](../../11_TestStandシーケンス構築手順.md)の原則をそのまま使う。

```text
Device SubVI PoC
   ↓
Public API PoC
   ↓
TestStandからPublic APIを1個呼ぶ
   ↓
Setup
   ↓
Main
   ↓

```

本ProjectでもTestStandからThin DLL Wrapper、COM Ref、gRPC Stubを直接呼ばない。

# 5. Cleanup流用

[`../../12_異常系処理とシャットダウン設計.md`](../../12_異常系処理とシャットダウン設計.md)の思想を流用し、本Project固有機器についてSafe Orderを追加する。

例:

```text
Abort Requested
  ↓
Stop DUT stimulus / calibration scenario
  ↓
Stop high-power load transition
  ↓
Chroma Load OFF
  ↓
Chroma Source Output OFF
  ↓
Stop DLM5000 acquisition / save required artifact
  ↓
Recorder Stop
  ↓
Flush / Save / Hash artifact
  ↓
Disconnect device adapters
```

実際の順序はDUT電気安全要件と設備Interlock仕様で確定する。

# 6. 外注するDriver/Adapterの設計粒度

商社/ベンダーへ依頼する場合、単に「LabVIEWから操作できること」ではなく次を成果物契約へ含める。

## 6.1 必須成果物

1. LabVIEW Source VI / lvclass / typedef
2. Vendor API Wrapper層
3. Public Adapter API
4. Example / PoC VI
5. TestStand呼出し例
6. Error Code mapping表
7. Version compatibility表
8. Build/Install手順
9. Runtime dependency一覧
10. SimulationまたはMock手段
11. Unit Test / PoC Test項目
12. API Source Traceability
13. Known limitations
14. Cleanup/Abort動作仕様

ベンダーSDK/DLLの再配布可否はライセンスに従い、再配布不可物は成果物に直接含めず入手手順を記載する。

---

## 6.2 Public API I/O契約

最低限、各Public APIは次を返す。

```text
Status
TestError
error out
Device/Session ID
Operation-specific output
Vendor Error Code (必要時)
```

内部ReferenceはTestStandへ返さない。

# 7. Adapter単体受入試験

各AdapterはTestStand統合前に単体PoCを完了する。

## 7.1 共通Acceptance

- [ ] 初回Connect成功
- [ ] 10回以上のConnect/Close繰返しでResource leakなし
- [ ] Version/Model/Serial取得
- [ ] Configuration適用
- [ ] Start/Stop繰返し
- [ ] Communication cable断/Process終了等の異常検知
- [ ] incoming error時の動作が規定されている
- [ ] AbortからCleanupできる
- [ ] Closeを複数回呼んでも危険動作しない
- [ ] Error sourceにDevice/Operation情報を含む
- [ ] Simulationまたは実機なし確認手段がある

---

# 8. DAQ/Recorder受入試験

- [ ] 指定Channel数で開始できる
- [ ] 連続1時間以上のData loss監視
- [ ] Sample/Block countを検証できる
- [ ] Buffer overflowを検出できる
- [ ] Recorder artifact pathを取得できる
- [ ] Run IDをartifactまたはmanifestへ紐付けられる
- [ ] Stop後にFileがflush完了したことを判定できる
- [ ] Data file hashを保存できる
- [ ] Channel configuration snapshotを保存できる

長時間条件は実試験Durationに合わせて最終決定する。

# 9. Synchronization PoC

同期は感覚値ではなく計測する。

最低限100回程度のStart/Marker操作で次を記録する。

```text
Host send timestamp
Host acknowledgement timestamp
Vendor marker timestamp
Hardware marker timestamp (存在時)
Observed offset
Observed jitter
min / max / p95 / p99
```

結果から各Data Sourceに`Synchronization Class`と`Known Uncertainty`を割り当てる。

# 14. Project完了条件

ProjectのDriver phaseを完了と判断する条件は次。

1. 全対象機器のAdapter APIがFreezeされている。
2. 各Adapter単体PoCがPASSしている。
3. Run ManifestへVersion/Config/Artifactを記録できる。
4. 主要DAQの時間差/ジッタが測定済みである。
5. Abort時に全高電力系を安全停止できる。
6. CANalyzer/RAMScope既存資産を複製せず利用できている。
7. TestStandはPublic APIだけを呼んでいる。
8. 1 Runの全artifactをRun IDから追跡できる。
9. DLM5000の主制御経路がDirectまたはIS8000のどちらかへFreezeされている。
