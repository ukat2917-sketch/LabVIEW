# 07. 機器別 VI 構築手順

各機器の制御 VI の作り方を機器ごとにまとめる。
共通の入出力仕様・エラー処理は [05](./05_VI設計方針と共通仕様.md) / [06](./06_VIの作り方_手順.md) を前提とする。

> 実際の通信コマンド（SCPI 等）は機器のプログラミングマニュアルに従うこと。
> 本書のコマンド例は構築イメージを示すもの。

## 7.1 オシロスコープ DLM5058（横河）— 電圧・電流計測

**接続**：Ethernet（VISA TCPIP / LXI）

**作る VI**

| VI | 処理概要 |
|----|----------|
| `DLM5058_Init.vi` | VISA Open、`*IDN?` 確認、初期設定（時間軸・チャンネル） |
| `DLM5058_Config.vi` | レンジ・カップリング・トリガ条件を試験条件に応じ設定 |
| `DLM5058_Acquire_Start.vi` | 取り込み開始（`:STARt` 等） |
| `DLM5058_Acquire_Stop.vi` | 取り込み停止（`:STOP`） |
| `DLM5058_Save_Waveform.vi` | 波形データを取得・ファイル保存（CSV/バイナリ） |

**手順**
1. NI MAX で VISA リソースを確認（[03](./03_LabVIEW環境構築.md)）。
2. 計装ドライバが提供されていればそれを利用。無ければ SCPI を VISA Write/Read。
3. 波形保存 VI は **ファイル名に試験条件・日時を含める**（例：`<試験ID>_<条件>_<日時>.csv`）。
4. 異常系：エラー発生後に計測中の場合は **計測停止 → エラーと分かる名前でデータ保存**
   （[12](./12_異常系処理とシャットダウン設計.md)）。

## 7.4 高圧模擬電源 / 高圧負荷電源 RZ-X2-100K-H（高砂）

**接続**：Ethernet（LAN／TCP-IP、SCPI + IEEE488.2 共通コマンド）。**出力により接続台数が変わる（×3 等）**。

**作る VI**

| VI | 処理概要 |
|----|----------|
| `RZX_Init.vi` | 接続・初期化（台数分） |
| `RZX_Voltage_Set.vi` | 電圧設定（試験条件＝電圧条件） |
| `RZX_Current_Limit_Set.vi` | 電流制限設定 |
| `RZX_Output_On.vi` | 出力 ON |
| `RZX_Output_Off.vi` | 出力 OFF |
| `RZX_Read.vi` | 出力電圧・電流のモニタ |

**手順／注意**
- **複数台対応**：使用台数を入力（試験条件の「使用台数」変数）で受け取り、
  リファレンス配列に対して For ループで設定する設計にする。
  → 出力に応じて台数が変わっても同じ VI で対応できる。
- 並列・同期運転（マスタ/スレーブ）構成の場合、メーカー仕様に従い設定順序を守る。
- **異常系：高圧系は一番はじめに落とす**（大きな事故につながる可能性があるため）。
  Cleanup の先頭で `RZX_Output_Off.vi`（[12](./12_異常系処理とシャットダウン設計.md)）。

### 7.4.1 SCPI 機器の VI 作成に必要な情報（何をマニュアルから読み取るか）

SCPI 対応機器（RZ-X2 のほか PPX36-3・DLM5058 も同様）の VI を作るために必要な情報は
次の 3 つに分類できる。**「コマンド一覧」だけでは不足**で、①〜③ が揃って初めて実装できる。

| # | 必要な情報 | マニュアルの場所 | 実装で使う箇所 |
|---|-----------|----------------|---------------|
| ① | **SCPI コマンド一覧**（設定・問い合わせ・実行コマンド） | プログラミングマニュアルのコマンドリファレンス章 | 各 VI が送信する文字列 |
| ② | **通信仕様**：ポート番号・終端文字（LF/CR+LF）・接続方式（生 TCP ソケットか VXI-11/LXI か） | 「デジタル通信で使う」等の通信章 | VISA リソース名・シリアル設定 |
| ③ | **ステータス／エラーモデル**：`SYST:ERR?` の有無、ステータスレジスタ構成 | ステータスレジスタ章 | エラー確認・同期処理 |

**RZ-X2 について確認済みの通信仕様（マニュアル「デジタル通信で使う」章より）：**
- LAN ポート（RJ-45）、プロトコルは **TCP/IP**
- コマンド形式は **IEEE488.2 共通コマンド + SCPI 準拠コマンド**
- ケーブルは CAT5e 相当（ストレート／クロスどちらも可）。ノイズ環境ではシールド付き短距離を推奨
- リモート接続中は前面パネル操作がロックされる（UNLOCK/ALARM/DISPLAY/LOCAL キー以外無効）
- ⬜ **ポート番号・終端文字は未確認**（マニュアル同章の続きページで要確認）

> 🔴 **安全上の重要注意（マニュアル記載）**：
> **LAN コネクションをリモート制御中に切断した場合、本機は切断直前の設定状態・出力状態を保持する。**
> つまり制御 PC がハング／LAN ケーブルが抜けても**高圧出力は出続ける**。
> 自動試験システムでは「**LAN 通信監視機能設定手順**」（マニュアル記載）に従って通信監視を
> 有効化し、**意図しない切断時に出力を自動停止させる設定を必須とする**こと。
> この設定は `RZX_Init.vi` の初期化処理に含める。

### 7.4.2 SCPI VI 作成の詳細手順（RZ-X2 を例に）

#### STEP 1：コマンド抽出表を作る

コマンドリファレンス章から、**作りたい VI（1イベント1VI）ごとに必要なコマンドを抜き出して表にする**。
全コマンドを網羅する必要はなく、試験で使う操作に対応するものだけでよい。

| VI | 送信コマンド（例。実際の構文はRZ-X2マニュアルで確認） | 応答の有無 |
|----|------------------------------------------------|----------|
| `RZX_Init.vi` | `*IDN?`（機種確認）→ `*RST`（初期化）→ `*CLS`（ステータスクリア）→ LAN監視設定 | `*IDN?` は応答あり |
| `RZX_Voltage_Set.vi` | `SOUR:VOLT <値>` → `SOUR:VOLT?`（設定確認） | 確認クエリは応答あり |
| `RZX_Current_Limit_Set.vi` | `SOUR:CURR <値>` → `SOUR:CURR?` | 同上 |
| `RZX_Output_On.vi` | `OUTP ON` → `OUTP?` | 同上 |
| `RZX_Output_Off.vi` | `OUTP OFF` → `OUTP?` | 同上 |
| `RZX_Read.vi` | `MEAS:VOLT?` / `MEAS:CURR?` | 応答あり（測定値） |

> **コマンドの見分け方**：
> - 末尾に `?` が付くもの＝**クエリ**（応答が返る。Write の後に Read が必要）
> - `?` なし＝**設定/実行コマンド**（応答なし。Write のみ）
> - `*` で始まるもの＝**IEEE488.2 共通コマンド**（`*IDN?`/`*RST`/`*CLS`/`*OPC?` 等。ほぼ全SCPI機器共通）
> - SCPI は階層構造（`SOURce:VOLTage` 等）。大文字部分だけの**短縮形**（`SOUR:VOLT`）が使える

#### STEP 2：VISA リソースを決める（接続方式により2通り）

②の通信仕様で確認した接続方式によって、VISA リソース名の形式が変わる：

| 接続方式 | VISA リソース名 | 備考 |
|---------|----------------|------|
| VXI-11 / LXI 対応 | `TCPIP0::<IPアドレス>::INSTR` | NI MAX の自動検出に出てくる場合はこちら |
| 生 TCP ソケット | `TCPIP0::<IPアドレス>::<ポート番号>::SOCKET` | **ポート番号がマニュアルで必要**。終端文字の設定も必須 |

- NI MAX でまず `TCPIP0::<IP>::INSTR` を試し、検出されなければ SOCKET 方式にする。
- SOCKET 方式の場合、VISA プロパティで **Termination Character（通常 LF=0x0A）を有効化**する。
  これを忘れると Read がタイムアウトまで返ってこない（最初のハマりどころ）。

#### STEP 3：共通の下位 VI を 2 つ作る（全 SCPI 機器で流用）

各機器 VI の中身を毎回組むのではなく、**下位 VI（SubVI）2 つに集約**する：

```
SCPI_Write.vi   … VISA Write のラッパ
  in : VISAリファレンス、コマンド文字列、エラーin
  out: VISAリファレンス、エラーout
  処理: コマンド文字列に終端文字を付けて VISA Write

SCPI_Query.vi   … Write + Read のラッパ（クエリ用）
  in : VISAリファレンス、コマンド文字列、タイムアウト、エラーin
  out: VISAリファレンス、応答文字列、エラーout
  処理: VISA Write → VISA Read（終端文字まで読む）
```

> 05章の共通仕様（エラークラスタの伝搬・Status/TestError 出力）はこの下位 VI に実装しておく。
> 上位 VI（`RZX_Voltage_Set.vi` 等）は「コマンド文字列を組み立てて `SCPI_Write/Query` を呼ぶ」
> だけの薄い構造になり、量産が容易になる。

#### STEP 4：上位 VI の実装パターン（例：`RZX_Voltage_Set.vi`）

```
[電圧値 DBL 入力]
    ↓ Format Into String（例: "SOUR:VOLT %.2f"）
    ↓ SCPI_Write.vi                        ← 設定コマンド送信
    ↓ SCPI_Query.vi（"SOUR:VOLT?"）        ← 設定値の読み返し
    ↓ 応答を DBL に変換し、設定値と比較     ← 設定確認（Set→Verify パターン）
    ↓ 不一致なら TestError=True
[Status / TestError / エラーout 出力]
```

> **Set→Verify パターンを標準にする**：設定コマンドは応答がないため、送信しただけでは
> 「実際に設定されたか」が分からない。**直後に対応するクエリで読み返して照合する**ことで、
> 通信欠落・範囲外値の丸めを検出できる。高圧電源では特に必須。

#### STEP 5：エラー確認と同期

- **`SYST:ERR?`**：各 VI の最後に `SYST:ERR?` を発行し、`0,No Error.` 以外が返ったら
  TestError にする。※一般の SCPI 機器はエラーを**キュー**で保持するが、
  **RZ-X2 は「最後の1件のみ・読み出しでクリア」方式**（7.4.3d の SYSTem 階層参照）。
  そのため「まとめて後で読む」のではなく**設定のたびに毎回確認**すること。
- **`*OPC?`**：時間のかかる動作（出力 ON 直後の安定待ち等）の完了同期には
  `*OPC?`（動作完了で `1` が返る）を使う。TestStand 側の Wait と併用。

#### STEP 6：複数台への展開

STEP 3〜5 で作った VI は**リファレンス（VISA リソース）を入力で受け取る**ため、
台数分のリファレンス配列に対し For ループで回すだけで複数台対応になる（7.4 冒頭の方針どおり）。

### 7.4.3 RZ-X2 機器側の LAN 設定（マニュアル「LAN通信の設定」章・確認済み）

VI から接続する前に、**機器本体の前面パネルで**以下の LAN 設定を行っておく。

**設定画面への入り方**：HOME 画面 →「MENU」キー → Menu 画面 →「REMOTE」キー → Remote 画面 →「LAN」キー

**Lan 画面 1/2（ネットワーク基本設定）：**

| 設定項目 | 内容 | 本システムでの設定方針 |
|---------|------|----------------------|
| Internet Protocol Address | 機器の IP アドレス（数値部を押すとテンキー入力） | 固定 IP を割り当て（[01](./01_システム概要と構成.md) 1.5 のサブネット設計に従う。台数分で重複しないこと） |
| Subnet Mask | プレフィックス長で指定（例：`24` = 255.255.255.0） | PC と同一サブネット |
| Default Gateway | ゲートウェイアドレス | 閉じた試験 LAN ならハブ経由の任意値で可 |
| **Control Port** | SCPI コマンドを受け付ける TCP ポート | **既定値 `5025`**（SCPI raw socket の標準ポート。変更しないことを推奨） |

> 入力後、**テンキーの ENTER だけでは確定されない**。Lan 画面の「ENTER」キーを押して確定する
> （変更確定後、点滅が停止する）——設定したのに繋がらない場合はまずここを疑う。

これにより **VISA リソース名が確定**：

```
TCPIP0::<設定したIPアドレス>::5025::SOCKET
```

**Lan 画面 2/2（LAN 通信監視機能。7.4.1 の安全注意に対応する設定）：**

| 設定項目 | 内容 | 本システムでの設定方針 |
|---------|------|----------------------|
| **Remote Watchdog Time** | 通信途絶監視時間（秒）。**制御元のコマンド送信周期より長い時間**を設定する。`0.0s` で監視無効 | **必ず 0.0 以外を設定**。TestStand シーケンスの最長アイドル時間（コマンドを送らない最長区間）より長い値にする。短すぎると正常動作中に誤検出する |
| **Remote Watchdog Operation** | 通信途絶検出時の動作：`ALARM`＝アラーム発生状態にする ／ `STATUS OUTPUT`＝アラームにはしない | **`ALARM` を推奨**（アラーム状態で出力が停止するか、実機で要確認）。どちらの設定でも検出時にステータス出力 No.23 が 1 になる |
| **Link Down Monitoring** | リンクダウン（ケーブル抜け等の物理層断）の監視：`DISABLE` / `ALARM` / `STATUS OUTPUT` | **`ALARM` を推奨**（LAN ケーブル抜けを即検出できる） |

> **Watchdog Time 設計上の注意**：この機能は「一定時間コマンドが来ないと通信途絶とみなす」方式。
> つまり**試験中に長時間コマンドを送らない区間があると誤検出する**。対策として、
> TestStand の非同期ループまたは LabVIEW 側の監視ループで**定期的に `MEAS:VOLT?` 等を
> ポーリングして keep-alive を兼ねる**設計にする（モニタ VI `RZX_Read.vi` の定期実行で兼用可能）。

> **Link Down Monitoring の各設定値（マニュアル確認済み）**：
> - `DISABLE`：Link Down 検出時、ステータス出力の制御も行わない
> - `ALARM`：Link Down 検出時、アラーム発生状態にする
> - `STATUS OUTPUT`：Link Down 検出時、アラーム発生状態にはしない
> - `ALARM`／`STATUS OUTPUT` どちらの設定でも、検出時にはステータス出力 No.23 が 1 になる
>
> ※ Lan 2/2 画面も、変更後は「ENTER」キーで確定が必要（テンキーの ENTER だけでは未確定）。

### 7.4.3b RZ-X2 コマンドフォーマット規則（マニュアル「通信コマンド」章・確認済み）

VI でコマンド文字列を組み立てる際に守るべき構文規則。**`Format Into String` で
コマンドを生成する場合のフォーマット文字列設計の根拠になる。**

**基本規則：**

| 規則 | 内容 | VI 実装での注意 |
|------|------|----------------|
| 文字コード | 全コマンド・レスポンスとも **ASCII 文字列** | VISA Write/Read は標準設定でよい |
| パラメータ区切り | コマンドワードとパラメータの間に**半角スペース1文字** | 例：`OUTPut 1`（`OUTPut1` は不可）|
| クエリ | コマンドワード末尾に `?` を付ける | 例：`OUTPut?` |
| クエリ＋パラメータ | `?` とパラメータの間にも**半角スペース1文字**。使用可能パラメータは `DEFault`/`MAXimum`/`MINimum` | 例：`VOLTage? MAXimum`（最大設定可能値の問い合わせ）|
| 大文字小文字 | **区別なし**（`OUTPUT`/`output`/`OutP` すべて可）| どちらでもよいが、ドキュメント上は短縮形を大文字で統一する |

**ショートフォームとロングフォーム（重要）：**

- コマンド表では**大文字部分＝ショートフォーム、小文字含む全体＝ロングフォーム**
  （例：`OUTPut` → ショート `OUTP`、ロング `OUTPUT`）
- **どちらかの完全形でなければならない。中間の表記はエラー**：
  - `OUTPut` ✅（ロング） / `OUTP` ✅（ショート） / `OUTPu` ❌（中間形→実行されない）
- VI で文字列を組み立てる際は**ショートフォームで統一**することを推奨
  （タイプミスによる中間形エラーを防ぎやすく、送信バイト数も減る）

**オプションコマンド（省略可能な階層）：**

- コマンド表で `[ ]` に囲まれた部分は省略可能。**送信時はカッコ自体を付けない**
- 例：`[SOURce:]VOLTage[:LEVel][:IMMediate][:AMPLitude]` は `VOLT 10.0` と同じ意味
  （`SOURce:` や `:LEVel` 等をすべて省略した形）

**階層構造とパスポインタ（複数コマンド連結時の注意）：**

- SCPI コマンドは階層構造（ルートコマンド → `:` 区切りで下位コマンド）
- プログラムメッセージは省略可能なオプションコマンドを除き、**必ずルートコマンドから始める**
- 先頭にコロン `:` を置いてもよい（`SYSTem:VERSion?` ＝ `:SYSTem:VERSion?`）
- 複数コマンドを**セミコロン `;` で連結可能**：
  - `;` の直後に `:` が続く場合 → パスポインタがルートにリセットされ、ルートコマンドから記述
    例：`SYSTem:VERSion?;:SYSTem:KLOCk?` ✅
  - `;` の直後に `:` が無い場合 → 直前のパス位置からの相対記述と解釈される
    例：`SYSTem:VERSion?;KLOCk?` ✅（`SYSTem:` が引き継がれる）
  - 失敗例：`SYSTem:VERSion?;SYSTem:KLOCk?` ❌（パスポインタが `SYSTem` にある状態で
    さらに `SYSTem:` を書くと `SYSTem:SYSTem:KLOCk?` 相当になりエラー）

> **VI 実装方針**：セミコロン連結はパスポインタの誤りを生みやすいため、
> **本システムでは 1 コマンド = 1 回の VISA Write を基本とする**（1イベント1VI の方針とも整合）。
> 連結が必要な性能要件が出た場合のみ、上記規則に従い慎重に使う。

- 補足：**共通コマンド（`*IDN?` 等）はパスポインタの影響を受けない**（パスポインタにも影響しない）。
  例：`SYSTem:VERSion?;*IDN?;KLOCk?` のような連結でも `*IDN?` は問題なく、
  その後の `KLOCk?` には `SYSTem:` のパスが引き継がれる。

**デリミタ（終端文字。チェックリストの未確認項目→確定）：**

- プログラムメッセージの末尾には **CR（0x0D）／ LF（0x0A）／ CR+LF のいずれか**を付加する。
- VI 実装：`SCPI_Write.vi` で送信文字列の末尾に **LF を付加**する実装で統一する
  （3種のうちどれでも受け付けられるため、SCPI で最も一般的な LF を採用）。
- VISA の SOCKET 接続では受信側も **Termination Character = LF（0x0A）を有効化**する
  （7.4.2 STEP 2 の注意と同じ）。

**コマンドの実行順序と無効コマンドの扱い（マニュアル確認済み）：**

- コマンドはプログラムメッセージに現れる順に実行される。
- 無効なコマンドはエラーと判断され、実行されない。
- マルチコマンド（`;` 連結）に有効・無効が混在する場合、**無効コマンドの直前までは実行され、
  無効コマンド以降は有効なコマンドが含まれていても全て無視される**。
  → 連結メッセージは「途中まで実行される」中途半端な状態を生み得るため、
  　1 コマンド = 1 Write 方針の根拠がさらに強まる。

**アクノリッジメッセージ（VI 設計に影響する重要仕様）：**

- RZ-X2 には、正常なコマンド受信時に `"OK"`、異常時に `"ERROR"` を返す**アクノリッジ設定**がある。
- **デフォルトは「応答を返さない」設定**。
- VI 設計への影響：
  - **デフォルト（応答なし）のまま使う場合**：`SCPI_Write.vi` は Write のみでよい。
    エラー検出は Set→Verify パターン（7.4.2 STEP 4）と `SYST:ERR?` ポーリングで行う。
  - **アクノリッジを有効にする場合**：設定コマンドでも毎回応答が返るため、
    `SCPI_Write.vi` にも Read が必要になる（実質全コマンドがクエリ扱いになる）。
    エラーを即時検出できる利点があるが、VI の構造と通信量が変わる。
- **本システムの方針：デフォルト（応答なし）のまま使用し、Set→Verify + `SYST:ERR?` で
  エラー検出する**。アクノリッジ有効化は、通信品質に問題が出た場合の代替手段として保留。
  ※ どちらを採るにせよ、**機器側の設定と VI の実装が一致していないと Read タイムアウトや
  応答のズレ（1つ前のコマンドの応答を読む）が起きる**ため、Init 時に設定状態を確認する
  手順を含めることが望ましい。

### 7.4.3c RZ-X2 IEEE488.2 共通コマンド一覧（マニュアル「コマンドリスト」章・確認済み）

| コマンド | 処理概要 | 形態 | VI での用途 |
|---------|---------|------|-----------|
| `*CLS` | イベントレジスタのクリア（ステータスバイト・イベントステータス・エラー列を含む全イベントレジスタ）| 設定のみ | `RZX_Init.vi` の初期化に使用 |

| `*SRE <NR1>` | サービスリクエストイネーブルビット設定 | 両方 | （必要時のみ）|

| `*TST?` | 自己診断の実行。応答 `0`=異常なし／`1`=異常あり | クエリのみ | `RZX_Init.vi` で `0` を確認すると堅牢（任意）|

**`*IDN?` の応答形式（確認済み・接続確認の照合に使用）：**

```
TAKASAGO,RZ-X2-100K-H,FW_VER 01.00,01.00,01.00,01.00,01.00,1234567890AB
（メーカ名, 機種名, PWR-CONT/MST-CONT/LCD/PWR-CONT(FPGA)/MST-CONT(FPGA)の5バージョン, シリアル番号）
```

> `RZX_Init.vi` では応答の先頭が `TAKASAGO,RZ-X2-100K-H` で始まることを確認し、
> 不一致なら「接続先間違い」として TestError にする（IP 設定ミスで別の機器につながる事故の防止）。

> **制限事項（マニュアル記載）**：`*ESE`／`*PSC`／`*SRE` は、**直並列運転のブースター機として
> 動作中**の場合、正常な設定コマンドに対してアラームレスポンスが返る。
> 複数台構成（マスタ/ブースター）では**設定系コマンドはマスタ機にのみ発行**する設計とする
> （7.4 冒頭の「複数台対応」の For ループでは、マスタ/ブースターの区別を持たせること）。

> **`*RST` の重要な仕様**：通信設定（LAN設定）・外部コントロール設定は初期化**されない**。
> つまり `RZX_Init.vi` で `*RST` を発行しても LAN 接続は切れず、7.4.3 で設定した
> IP・ポート・Watchdog 設定も保持される（安心して Init に組み込める）。

### 7.4.3d RZ-X2 SCPI コマンド（マニュアル「SCPIコマンド」章・確認分）

#### CONTrol 階層（運転準備）— RZ-X2 特有の重要な状態遷移

RZ-X2 には一般的な電源の「OUTPUT ON/OFF」の**前段に「運転準備（入/切）」という状態**がある。
**運転準備が「入」でなければ出力を開始できない**ため、VI のシーケンス設計に直結する。

| コマンド | 機能 | 形態 |
|---------|------|------|
| `CONTrol:PERMission:CONDition <値>` | **運転準備指令**。`0`(STANdby/DEFault)=切 ／ `1`(STARtup)=入 | 両方 |
| `CONTrol:PERMission:MODE <値>` | 外部接点による運転準備制御。`0`(OFF/DEFault)=無効 ／ `1`(ON)=有効 | 両方 |

```
例: CONT:PERM:COND 1     ← 運転準備 入
    CONT:PERM:COND?      → 1
```

> **制限（アラームレスポンスが返る条件）**：
> - 直並列運転のブースター機として動作中（→設定系はマスタ機のみに発行。7.4.3c と同じ）
> - **運転準備 待機状態の時**（状態遷移中は受け付けない→リトライ／待機処理が必要）
> - 外部コントロール（運転準備）が有効な時（`CONT:PERM:MODE 1` の時はリモートから運転準備を操作できない）
>
> **VI 設計への反映**：`RZX_Init.vi` の後、出力前に `RZX_Ready.vi`（`CONT:PERM:COND 1` +
> クエリで確認）を挟むシーケンスとする。VI 一覧（7.4 冒頭）に **`RZX_Ready.vi` を追加**する。

#### OUTPut 階層（出力制御・保護・監視）

確認済みの主要コマンド：

| コマンド | 機能 | 形態 | VI 対応 |
|---------|------|------|--------|
| `OUTPut:MODE <値>` | **動作モード設定**：`0`(CV/DEFault)=定電圧 ／ `1`(CC)=定電流 ／ `2`(CP)=定電力 | 両方 | `RZX_Mode_Set.vi`（新規）|
| `OUTPut[:STATe][:IMMediate] <値>` | **OUTPUT ON/OFF 制御**：`0`(OFF)／`1`(ON)。クエリ応答は停止時`0`/出力時`1`。**制限：運転準備切状態・RUN中・汎用入力で出力制御中はアラーム** | 両方 | `RZX_Output_On/Off.vi`（ショート形は `OUTP 1`／`OUTP 0`）|
| `OUTPut:RUN <値>` | **RUN/STOP 制御**：`0`(STOP)=停止／`1`(RUN)=運転／`2`(RESTart)=再開（プログラム運転の再開データがある場合のみ。それ以外は RUN と同様）。予め設定している運転モードを開始/停止する | 両方 | `RZX_Run.vi`／`RZX_Stop.vi`（新規）|
| `OUTPut:PROTection:CLEar` | **アラームクリア**。⚠ **必ず原因を取り除いた後に実行**（マニュアル注意書き）| 設定のみ | `RZX_Alarm_Clear.vi`（異常系リカバリ用・新規）|
| `OUTPut:PROTection:BUZZer` | 鳴動中のブザー停止 | 設定のみ | （必要時）|
| `OUTPut:PROTection:BUZZer:MODE <値>` | アラーム時のブザー鳴動設定：`0`(OFF)=無効／`1`(ON/DEFault)=有効 | 両方 | （必要時）|
| `OUTPut:PROTection:WDOG[:DELay] <値>` | **通信途絶監視時間の設定**：`0.0`(MIN/DEFault)=監視しない〜`3600.0`(MAX) 秒 | 設定/クエリ | **`RZX_Init.vi` に組み込む**（下記）|
| `OUTPut:PROTection:WDOG:MODE <値>` | **通信途絶検出時動作**：`0`(DEFault)=異常としてアラーム状態とし、ステータス出力も行う／`1`=異常とはせず、ステータス出力のみ | 両方 | 同上 |
| `OUTPut:PON[:STATe]` | 装置起動時の動作設定 | 両方 | （必要時）|

```
例: OUTP:PROT:WDOG 10.0     ← 監視時間 10 秒
    OUTP:PROT:WDOG?         → 10.0
    OUTP:PROT:WDOG:MODE 0   ← 検出時はアラーム状態にする
```

> **重要な発見：Watchdog は SCPI からも設定可能**（正確なパスは **`OUTPut:PROTection:WDOG`**）。
> 7.4.3 では前面パネルでの設定手順を記載したが、SCPI により **`RZX_Init.vi` から
> プログラム的に設定できる**。
> → **本システムの方針**：`RZX_Init.vi` の初期化シーケンスに
> 　`OUTP:PROT:WDOG <監視時間>` + `OUTP:PROT:WDOG:MODE 0`（アラーム扱い）を組み込み、
> 　試験開始時に必ず有効化されることを保証する（前面パネル設定への依存・設定忘れを排除）。
> 　監視時間の値域は 0.0〜3600.0 秒（0.0=無効）で確定。

> **`OUTPut:RUN` の制限（重要・状態遷移の依存関係）**：以下の場合アラームレスポンスが返る。
> - 直並列運転のブースター機として動作中
> - **運転準備切状態**（→ 先に `CONT:PERM:COND 1` が必要）
> - **動作モードの不一致**（例：運転モード=IV 運転は定電圧制御固定のため、動作モードが CC だと RUN 不可）
> - 運転に使用するデータに不備がある場合（IV データと装置構成の不一致、必要データの不足等）

**RZ-X2 の状態遷移の全体像（OUTPUT/RUN の制限も反映・整理）：**

```
[電源投入]
   ↓ （OUTP:PON 0 なら何も起きない＝安全）
[運転準備 切]                    ※この状態では OUTP も OUTP:RUN もアラーム
   ↓ CONT:PERM:COND 1           ← RZX_Ready.vi
[運転準備 入]
   ↓ OUTP:MODE / OUTP:OPER:MODE / 各種データ設定（この段階で設定を確定させる）
   ↓ OUTP 1                     ← RZX_Output_On.vi（OUTPUT ON。RUN中は切替不可のためRUN前に行う）
[OUTPUT ON]
   ↓ OUTP:RUN 1                 ← RZX_Run.vi（設定済みの運転モードで運転開始）
[RUN（運転中）]                  ※この間 OUTP の切替・OUTP:MODE の変更はアラーム
   ↓ OUTP:RUN 0                 ← RZX_Stop.vi
[OUTPUT ON（停止）]
   ↓ OUTP 0                     ← RZX_Output_Off.vi
[運転準備 入]
   ↓ CONT:PERM:COND 0
[運転準備 切]
```

> **`OUTP[:STATe]` の制限（確認済み）**：運転準備切状態・**RUN 中**・汎用入力で出力制御中は
> アラームレスポンス。→ OUTPUT の切替は必ず RUN 停止後に行う（上図の順序を厳守）。
> 異常系の緊急停止シーケンス（[12](./12_異常系処理とシャットダウン設計.md)）でも
> `OUTP:RUN 0 → OUTP 0 → CONT:PERM:COND 0` の順で降ろすこと。

> **`OUTPut:MODE` の制限**：RUN 中または OUTPUT ON 中は設定変更でアラームレスポンス。
> **動作モードは必ず出力 OFF の状態で設定**するシーケンスにする（Setup 段階で確定させる）。

**運転モードの構造（確認済み・RZ-X2 の動作の骨格）：**

| コマンド | 機能 | 形態 |
|---------|------|------|
| `OUTPut:OPERation:MODE <値>` | **運転モードの設定**：`0`=PATTERN運転 ／ `1`=PROGRAM運転 ／ `2`=IV運転 ／ `3`=MPPT運転。前面パネルや専用アプリから設定された情報を元にどのモードで動くかを決定する | 両方 |

> RZ-X2 は「運転モード」を選んでから動作する構造。単純な定電圧/定電流出力を
> どのモードで実現するか（PROGRAM 運転の単行程か等）は、電圧設定コマンドの確認とあわせて要整理。
> 制限：RUN 中は変更不可（アラームレスポンス）。

**パターン運転（確認済み）— [08 負荷電流ランプ制御](./08_負荷電流VIと並列処理.md) に関係する重要機能：**

| コマンド | 機能 | 形態 |
|---------|------|------|
| `OUTPut:PATTern[:MODE] <値>` | パターン運転の動作モード：`0`(CV/DEFault)／`1`(CC)／`2`(CP)。**⚠ 設定時にパターン運転データが初期化される** | 両方 |
| `OUTPut:PATTern:REGister <行>,<制御値>,<時間>,<内容>` | パターン運転データ登録（1行ずつ）。行番号=1〜5、制御時間=0.001〜9999.999秒、制御内容：`0`=終了行／`1`=STEP／`2`=**SWEEP**／`3`=OUTPUT OFF。クエリは行番号必須（`OUTP:PATT:REG? 1`）| 両方 |
| `OUTPut:PATTern:LOOP <値>` | 繰り返し回数：`0`(DEFault)=無制限／`1`〜`65535` | 両方 |
| `OUTPut:PATTern:STOP <値>` | パターン終了時の出力状態：`0`=出力状態保持／`1`(DEFault)=STOP遷移時に出力停止 | 両方 |

> **設計上の重要な発見**：パターン運転の `SWEEP`（制御値まで制御時間をかけて掃引）を使えば、
> **負荷電流のランプ制御を機器側にオフロードできる**可能性がある。
> [08](./08_負荷電流VIと並列処理.md) では LabVIEW ループでのランプ制御を想定しているが、
> RZ-X2 のパターン運転（最大5行、SWEEP/STEP 組み合わせ）で実現できれば、
> LabVIEW 側のタイミング管理が不要になり精度も機器保証になる。
> **ランプ要件（変化幅・時間・中断可能性）とパターン運転の制約（5行まで・RUN中の変更不可）を
> 突き合わせて方式選定すること**。ランプ途中で割り込み変更が必要なら LabVIEW ループ方式が優位。

**起動時動作（確認済み）：**

| コマンド | 機能 | 形態 |
|---------|------|------|
| `OUTPut:PON[:STATe] <値>` | 装置起動時の動作：`0`(DEFault)=未使用／`1`=OUTPUT制御（起動・初期化完了後に運転準備入→OUTPUT ON）／`2`=RUN制御（起動時の設定で運転開始）。汎用入力による制御が設定されていた場合はそちらが優先 | 両方 |

> **本システムの方針**：`OUTP:PON 0`（未使用）とする。**電源投入だけで勝手に出力が出る設定
> （1/2）は自動試験システムでは危険**（TestStand シーケンスの管理外で高圧が出る）。
> `RZX_Init.vi` で `OUTP:PON?` を確認し、0 以外なら 0 に設定する処理を入れる。

#### SOURce 階層（出力設定）— `RZX_Voltage_Set.vi`／`RZX_Current_Limit_Set.vi` の実装コマンド確定

`[SOURce:]` はオプションコマンド（省略可）のため、**ショート形は `VOLT`／`CURR` から始められる**。

**電圧設定（VOLTage）：**

| コマンド | 機能 | 形態 |
|---------|------|------|
| `[SOURce:]VOLTage[:LEVel][:IMMediate][:AMPLitude] <値>` | **定電圧動作の制御値設定**（ショート形：`VOLT 100.0`）。MIN/DEFault=**0V**（電流と異なり負値なし）。範囲は直列台数×レンジで変化（H-TYPE 1直列: Lo 0〜78.750V／Hi 0〜787.50V、2直列: Lo 0〜157.50V／Hi 0〜1575.0V）。**外部アナログ制御が有効な場合この設定は使用されない** | 両方 |
| `[SOURce:]VOLTage:LIMit:HIGH <値>` ／ `:LOW <値>` | 電圧上限／下限の設定（定電圧動作**以外**の動作時に使用）。HIGH は下限以下・LOW は上限以上を設定するとアラーム | 両方 |
| `[SOURce:]VOLTage:PROTection[:LEVel] <値>` | 出力過電圧保護の設定 | 両方 |
| `[SOURce:]VOLTage:RANGe <値>` | 電圧レンジの設定 | 両方 |
| `[SOURce:]VOLTage:SLEW:RISing` ／ `:FALLing` | **CV スルーレート（上昇／下降）設定** | 両方 |
| `[SOURce:]VOLTage:EXTernal:SOURce <値>` ／ `:RANGe <値>` | 外部アナログ（電圧）制御：`0`(NONE/DEFault)=無効／`1`(VOLTage)=有効。レンジ `0`(LOW)=5V／`1`(HIGH)=10V。**RUN中・OUTPUT ON中変更不可** | 両方 |

**電流設定（CURRent）：**

| コマンド | 機能 | 形態 |
|---------|------|------|
| `[SOURce:]CURRent[:LEVel][:IMMediate][:AMPLitude] <値>` | **定電流動作の制御値設定**（ショート形：`CURR 30.000`）。MIN=最小値/DEFault=**0A**/MAX=最大値。**負値可**（回生・シンク方向）| 両方 |
| `[SOURce:]CURRent:LIMit:SINK <値>` | **シンク電流制限**（定電流動作**以外**の動作時に使用。負値。DEFault=MINimum と同値）| 両方 |

| コマンド | 機能 |

#### SYSTem 階層（装置設定）— 主要コマンド確定

**`SYSTem:ERRor[:NEXT]?` の詳細（確定）— ⚠ 標準 SCPI のエラーキューとは動作が異なる：**

- 応答形式：`エラーコード,エラーメッセージ`（例：`-901,Select IV-Table error.`／正常時：`0,No Error.`）
- **保持されるのは「最後に発生した」エラー 1 件のみ**（キューではない）。
- **問い合わせ後にクリアされる**。
- → 複数のエラーが連続発生した場合、**最後の 1 件しか取得できない**（先に起きたエラーは失われる）。
  一般的な SCPI 機器の「エラーキューを全件読み出す」実装は RZ-X2 には当てはまらない。

| エラーコード | メッセージ | 意味 |
|-------------|-----------|------|
| `0` | No Error. | 正常 |
| `-100` | Command error. | コマンドエラー（未定義コマンドなど）|
| `-101` | Invalid character. | 無効なキャラクタを受信した |
| `-102` | Syntax error. | 構文エラー |
| `-104` | Data type error. | データタイプエラー（数値のところを文字で受信した等）|
| `-108` | Parameter not allowed. | パラメータが多すぎる |
| `-109` | Missing parameter. | パラメータが少なすぎる |
| `-120` | Numeric data error. | 数値データエラー（**範囲オーバーなど**）|
| `-140` | Character data error. | 文字データエラー |
| `-150` | String data error. | 文字列データエラー |
| `-900` | Select Program error. | 選択したプログラムが実行不可 |
| `-901` | Select IV-Table error. | IV 模擬運転の実行不可 |
| `-902` | CheckSum error. | データ登録時のデータ破損 |
| `-904` | No permission Command. | 実行が許可されていないコマンド |
| `-905` | Receive time out. | 受信タイムアウト |
| `-906` | F/W initializing. | CPU F/W 初期化中 |

> **エラー処理の実装方針（RZ-X2 の仕様を踏まえた修正版）**：
> 1. 「最後の1件のみ・読むとクリア」のため、**エラー確認は各設定 VI の直後に毎回行う**
>    （まとめて後から読む方式では先行エラーが失われる）。
> 2. `SCPI_Write.vi` の直後に `SYST:ERR?` を発行し `0,No Error.` を確認する形を
>    共通下位 VI（`SCPI_Write_Check.vi` 等）としてパターン化すると量産しやすい。
> 3. `-120`（範囲オーバー）は試験条件の設定ミスで最も出やすい。Set→Verify（7.4.2 STEP 4）と
>    併用して二重に検出する。
> 4. `-906`（F/W 初期化中）は電源投入直後の接続で発生し得る。`RZX_Init.vi` は
>    リトライ（ウェイト付き）を実装しておく。

> **本システムで使わない階層**：`SYSTem:COMMunicate:CAN:*`（CAN 通信オプション。LAN 制御のため不要）、
> `:ADJust`（ユーザー調整）、`:TIMer`、`:OPTion`、`:SERial`、`:VERSion`、`:MM`。
> `SYSTem:LAN` の IP/ポート/ゲートウェイ/サブネットも **VI からは変更しない**
> （変更すると接続自体が切れるため、前面パネルで一度設定する運用。7.4.3 参照）。

  （マイコンが死んで高圧がかかっている状態だと制御不能になるため、12V は最後まで残す）

### 7.5.1 PPX36-3 の LAN 接続仕様（マニュアル 1-5 章・確認済み）

PPX36-3（TEXIO 製）のイーサネット接続は **Web サーバー（監視用）** と
**ソケットサーバー（リモート制御用）** の 2 つの用途がある。VI 制御に使うのはソケットサーバー。

| 項目 | 内容 |
|------|------|
| 接続方式 | ソケットサーバー。**ポート番号は `2268` に固定**（RZ-X2 の 5025 と異なる点に注意）|
| IP 設定 | DHCP／手動の両対応。**ソケットサーバー利用時は DHCP をオフにして手動 IP を設定**（マニュアル 1-5-3 の手順）。本システムの固定 IP 方針（[01](./01_システム概要と構成.md) 1.5）とも整合 |
| 設定パラメータ | MAC（表示）・ホスト名（表示）・DHCP On/Off・IP アドレス・サブネットマスク・ゲートウェイ IP・DNS・Web サーバー On/Off |
| 動作確認 | NI MAX（VISA）で確認（マニュアル 1-5-4 が NI MAX の使用を公式に案内）|
| リモート接続確立 | 前面画面にリモートコントロールアイコンが表示される |
| 注意 | ネットワークに接続するには電源を入れ直すか、Web ブラウザの更新が必要な場合がある（設定変更後は再起動を推奨）|

これにより **VISA リソース名が確定**：

```
TCPIP0::<設定したIPアドレス>::2268::SOCKET
```

> Web サーバー機能（ブラウザで `http://<IP>` にアクセス）では System Information・
> Network Configuration・Measurement 等が確認できる。**トラブルシュート時の状態確認手段**
> として有用（VI からは使わない）。Web 画面の System Information に
> 「VISA TCPIP Connect String」が表示されるため、リソース名の確認にも使える。

### 7.5.2 PPX36-3 コマンド構文（マニュアル第2章・確認済み）

| 項目 | 内容 | RZ-X2 との差分 |
|------|------|---------------|
| 準拠規格 | IEEE488.2 準拠、**SCPI 1999 準拠** | 同等 |
| 階層構造 | コロン `:` 区切りのツリー（例：`MEASure:SCALar:CURRent:DC?`）| 同じ |
| 標準形／省略形 | 大文字部分＝省略形。**不完全なコマンドは認識されない**。大文字小文字の区別なし | 同じルール |
| 角括弧 `[ ]` | 省略可能（`DISPlay:MENU[:NAME]?` = `DISPlay:MENU?`）| 同じ |
| 複合コマンド | セミコロン `;`（同一ノード）／セミコロン+コロン `;:`（異なるノード）| 同じ（1コマンド1Write方針も同様に適用）|
| **複数パラメータ** | カンマ区切り。**カンマの前後にスペースを入れないこと**（例：`APPLY 1.5,5.2`）| RZ-X2 では複数パラメータのコマンド未使用だったため新規の注意点 |
| パラメータ形式 | `<Boolean>`(0,1)／`<NR1>`(整数)／`<NR2>`(10進数)／`<NR3>`(浮動小数点 4.5e-1等)／`<NRf>`(NR1〜3のいずれか)／`<block data>` | 同等 |
| **メッセージターミネータ** | **LF（改行コード）** | RZ-X2（CR/LF/CR+LF いずれか可）より限定的。**LF 統一方針（7.4.3b）がそのまま適用可** |

### 7.5.4 PPX36-3 コマンド詳細（確認分）

#### Abort／Apply コマンド（確定）

| コマンド | 機能 | 形態 |
|---------|------|------|
| `:ABORt` | トリガー動作をキャンセル | Set のみ |
| `:APPLy {<NRf>(V)\|MIN\|MAX[,<NRf>(A)\|MIN\|MAX]}` | **電圧と電流を同時に設定**。第1パラメータ=電圧、第2パラメータ=電流（省略可）。`:APPLy?` で現在値を問い合わせ | Set/Query |

```
例: APPL 12.0,3.0     ← 12V・3A を一括設定
    APPL MIN, MIN     ← 電圧と電流を最小設定に

```

> `PPX_Voltage_Set.vi` の実装は **`APPLy` で電圧・電流を一括設定する方式**と、
> `VOLT`/`CURR` を個別に設定する方式（1イベント1VI に忠実）の 2 案がある。
> DUT電源としては「電圧・電流制限をセットで管理」する方が事故が少ないため、
> **`PPX_Apply.vi`（電圧+電流制限の一括設定 VI）を基本とし、個別 VI は補助**とする設計を推奨。

#### SOURce 階層：電流系（確定）

| コマンド | 機能 | パラメータ | 形態 |
|---------|------|-----------|------|
| `[:SOURce]:CURRent[:LEVel][:IMMediate][:AMPLitude] <NR2>` | **電流設定値[A]**。外部アナログコントロール中はその設定値を応答 | 定格電流出力レベルの **0〜105%**／MIN／MAX | Set/Query |
| `[:SOURce]:CURRent[:LEVel]:TRIGgered <NR2>` | ソフトウェアトリガ発生時の電流設定値 | 定格の 0〜105% | Set/Query |
| `[:SOURce]:CURRent:LIMit:AUTO <bool>` | 電流設定の上限を有効にするか | `0`(OFF)=無効／`1`(ON)=有効 | Set/Query |
| `[:SOURce]:CURRent:PROTection:DELay <NR2>` | **OCP 検出の遅延時間**。初期値 0.05 | 0.05〜2.5 秒 | Set/Query |
| `[:SOURce]:CURRent:PROTection[:LEVel] <NR2>` | **OCP（過電流保護）レベル** | 5%〜110%[A]（最小=Iレート×0.05、最大=Iレート×1.1）| Set/Query |
| `[:SOURce]:CURRent:PROTection:TRIPped?` | **OCP が発生したかの問い合わせ** | 応答 `<bool>` | Query のみ |

> **実装メモ**：
> - `PPX_Current_Limit_Set.vi`：`CURR <値>` で設定 → `CURR?` で Verify。
> - OCP は「設定電流の 105% で頭打ち」とは別の**保護トリップ機構**。
>   `CURR:PROT:LEV` を試験条件に応じ設定し、`PPX_Read.vi`（または異常系）で
>   `CURR:PROT:TRIP?` を確認 → トリップ時は `OUTP:PROT:CLE`（7.5.3）でクリアする流れ。
> - `SOUR:MODE?` は「実際に CV/CC どちらで動作しているか」の確認に使える
>   （DUT の起動電流で CC に張り付いていないか等のチェックに有用）。
>   応答は**文字列** `CC`／`CV`／`OFF`（数値ではない点に注意）。

| コマンド | 機能 | パラメータ | 形態 |
|---------|------|-----------|------|

| `[:SOURce]:VOLTage:PROTection:TRIPped?` | **OVP が発生したかの問い合わせ** | 応答 `0`=未発生／`1`=発生 | Query のみ |
| `[:SOURce]:VOLTage:SLEWrate:RISing <NR2>` | 電圧立ち上がりスルーレート。**CV スルーレート優先（CVLS）モードでのみ有効** | 0.0001V/ms〜モデル依存最大（0.1/0.2/0.36/1 V/ms）| Set/Query |
| `[:SOURce]:VOLTage:SLEWrate:FALLing <NR2>` | 電圧立ち下がりスルーレート（CVLS モードのみ）| 同上 | Set/Query |
| `[:SOURce]:VOLTage:SENSe <値>` | **リモートセンシング設定**：`0`(INTernal)=2線式／`1`(EXTernal)=4線式 | － | Set/Query |

> **実装メモ（電圧系）**：
> - `PPX_Voltage_Set.vi`：`VOLT <値>` → `VOLT?` Verify（または `APPLy` 一括設定）。
> - **OVP/UVL の設定順序に注意**：`VOLT:LIM:AUTO 1`（制限有効）の状態では OVP/UVL が
>   自動調整される。試験条件として OVP を明示設定する場合は、電圧設定 → OVP 設定の順で行い、
>   `VOLT:PROT:TRIP?` を異常系チェックに組み込む（OCP と同様のトリップ確認フロー）。
> - **リモートセンシング（`VOLT:SENS`）**：DUT までの配線電圧降下を補正する場合は
>   4線式（`EXT`）＋センス線接続が必要。**機器側の設定と実配線が一致していないと
>   電圧が正しく出ない**ため、`PPX_Init.vi` で試験系の配線方式に合わせて明示設定する。
> - スルーレート設定は CVLS モード時のみ有効。低圧 DUT 電源の立ち上げ速度を
>   制御したい場合に利用（既定モードのままなら未使用でよい）。

| `:OUTPut[:STATe][:IMMediate] <bool>` | **出力の ON/OFF 切替**。RZ-X2 のような「運転準備」の前段はない（シンプル）| `0`(OFF)／`1`(ON) | Set/Query |
| `:OUTPut[:STATe]:TRIGgered <bool>` | ソフトウェアトリガ（`*TRG`）発生時に出力を切替 | `0`=OFF に切替／`1`=ON に切替 | Set/Query |
| `:OUTPut:PROTection:CLEar` | **保護回路のクリア**：OVP・OCP・OTP＋温度短絡・検知保護＋**他のアラーム（WDOG・CAP・TEMP モニター）もクリア** | なし | Set のみ |
| `:OUTPut:PROTection:TRIPped?` | **保護回路が作動したかの確認** | 応答 `0`=保護エラーなし／`1`=発生 | Query のみ |
| `:OUTPut:PROTection:WDOG[:STATe] <bool>` | **通信監視（ウォッチドッグ）の有効/無効** | `0`(OFF)／`1`(ON) | Set/Query |
| `:OUTPut:PROTection:WDOG:DELay <NR1>` | **通信監視タイマー（秒単位）** | **1〜3600 秒** | Set/Query |

> **実装メモ**：
> - `PPX_Output_On/Off.vi`：`OUTP 1`／`OUTP 0` → `OUTP?` Verify。RZ-X2 と違い状態遷移の
>   前提条件が少なくシンプル。
> - **Watchdog は `PPX_Init.vi` に組み込む**（RZ-X2 と同方針）：
>   `OUTP:PROT:WDOG:DEL <秒>` → `OUTP:PROT:WDOG 1` の順で設定。
>   タイマーは TestStand シーケンスの最長アイドル時間より長く（keep-alive ポーリング設計も
>   RZ-X2 と同様に適用）。
> - **異常系リカバリ**：`OUTP:PROT:TRIP?` で保護作動を確認 → 原因除去後
>   `OUTP:PROT:CLE` で一括クリア（WDOG アラームもこれでクリアされる）。

#### MEASure 階層：測定（確定）— `PPX_Read.vi` の実装コマンド

| コマンド | 機能 | 応答 | 形態 |
|---------|------|------|------|
| `:MEASure[:SCALar]:ALL[:DC]?` | **平均出力電圧・電流・電力を一括取得** | `"+0.0000,+0.00000,+0.00000"` ＝ 電圧(V)，電流(A)，電力(W) のカンマ区切り | Query のみ |
| `:MEASure[:SCALar]:VOLTage[:DC]?` | 平均出力電圧 | ボルト単位 | Query のみ |
| `:MEASure[:SCALar]:CURRent[:DC]?` | 平均出力電流 | アンペア単位 | Query のみ |
| `:MEASure[:SCALar]:POWer[:DC]?` | 平均出力電力 | **ワット単位（RZ-X2 は kW だった。単位が異なる点に注意）** | Query のみ |

> `PPX_Read.vi` は **`MEAS:ALL?` の 1 クエリで V/A/W を一括取得**する実装が効率的
> （通信回数 1/3。Watchdog の keep-alive も兼ねる）。応答文字列をカンマで分割し
> 3 つの DBL に変換する。

**測定の平滑化設定：**

| コマンド | 機能 | パラメータ |
|---------|------|-----------|
| `:SENSe:AVERage:COUNt <値>` | 平均設定の平滑化レベル | `OFF`=デフォルト／`LOW`(0)=低／`MIDDle`(1)=中／`HIGH`(2)=高 |

#### SYSTem 階層（確定）

| コマンド | 機能 | パラメータ | 形態 |
|---------|------|-----------|------|
| `:SYSTem:ERRor?` | **エラークエリ**。最後のエラーメッセージが戻る。**最大 32 のエラーがエラーキューに保存される**（応答例：`-100,"Command error"`）| － | Query のみ |
| `:SYSTem:ERRor:ENABle` | **エラーキューをクリア** | なし | Set のみ |
| `:SYSTem:KLOCk <bool>` | フロントパネルのキーロック | `0`=無効／`1`=有効 | Set/Query |
| `:SYSTem:KEYLock:MODE <bool>` | キーロック・リモート時の Output キー動作：`0`(OFF)=**キーロック時、アウトプットのオフのみ有効**／`1`(ON)=オン/オフのみ有効 | － | Set/Query |
| `:SYSTem:CONFigure:VOLTage:CONTrol <値>` | CV コントロールモード：`0`(NONE)=ローカル（パネル）／`1`(VOLTage)=外部電圧コントロール／`2`(RRISing)=外部抵抗（10kΩ:最大電圧設定）。**出力オン中は設定不可** | － | Set/Query |
| `:SYSTem:CONFigure:OUTPut:PON[:STATe] <値>` | **電源投入時の出力状態**（PWR On Config。**電源再投入後に有効**）：`SAFE`/`OFF`/`0`=前回状態で起動するが**出力はオフ（初期設定）**／`FORCe`/`ON`/`1`=前回状態で起動し**出力オン**／`AUTO`/`2`=前回のオン/オフ設定を引き継ぐ | － | Set/Query |

> **⚠ RZ-X2 との重要な違い：PPX の `SYST:ERR?` は最大32件の本物のエラーキュー**。
> - RZ-X2（最後の1件のみ・読出しでクリア）とはエラー処理の実装が異なる。
> - PPX では「`SYST:ERR?` を `0,"No error"` が返るまで繰り返し読んで全件回収」する
>   標準 SCPI 方式が使える。キューを一括破棄したい場合は `SYST:ERR:ENAB`。
> - 共通下位 VI（`SCPI_Query.vi` 等）は共用できるが、**エラー確認 VI は機器別**
>   （`RZX_Error_Check.vi`＝毎回1件確認／`PPX_Error_Check.vi`＝キュー全件回収）にする。

> **安全設定（`PPX_Init.vi` に組み込み）**：
> - `SYST:CONF:OUTP:PON?` を確認し、**`0`（SAFE）以外なら `SAFE` に設定**
>   （`FORCe`/`AUTO` だと電源投入だけで出力が出る可能性があり、RZ-X2 の `OUTP:PON 0` 方針と同じ理由で危険）。
>   ※設定は電源再投入後に有効になる点に注意。
> - `SYST:CONF:VOLT:CONT?` が `0`（ローカル）であることを確認（外部コントロール有効だと
>   `VOLT` 設定が効かない。RZ-X2 の `VOLT:EXT:SOUR` と同じ注意）。
> - キーロック（`SYST:KLOC 1`）を有効にする場合、`SYST:KEYL:MODE 0` にしておくと
>   **キーロック中でも前面パネルから出力オフだけは可能**＝非常停止手段を残せる。
