# 07. 機器別 VI 構築手順

> **本章の役割**：オシロ、ロガー、電源、CANなど、機器別VIを作る際の実装ルートと単体試験条件を定義する。
>
> 新規VIの詳細手順は[00A](./00A_LabVIEW実装資料の記述ルール.md)の「目的 → 入出力 → 配置関数 → 配線順 → 単体テスト」に従う。RAMScopeの詳細は重複記載せず、[10](./10_RAMScope実装方針.md)を唯一の正本とする。

---

## 7.1 共通方針

### 7.1.1 なぜ機器ごとに公開APIを分けるのか

メーカーごとに通信方式、エラー仕様、単位、設定確認方法が異なる。一方、TestStandから見た操作は「接続」「設定」「開始」「読出し」「停止」「終了」にそろえられる。そこで、機器固有処理をLabVIEW公開APIへ閉じ込め、TestStandへは共通したイベント粒度を見せる。

### 7.1.2 1イベント1VI

- 1つの機器操作を1つの公開API VIへ分離する。
- 試験条件はTestStandから入力する。
- 待ち、繰り返し、並列処理はTestStandへ置く。
- 公開APIへ`error in / error out`、`Status.ctl`、`TestError.ctl`を持たせる。
- 下位DLLラッパや純粋変換VIはStatus/TestErrorを生成しない。

### 7.1.3 各VIの詳細手順に必ず含めるもの

```text
0. VIが必要な理由と処理概要
1. 入出力の全端子
2. 配置する関数・メーカー提供VI・SubVI
3. 接続元と接続先を明記した配線順
4. 正常・異常・既存エラーの単体テスト
```

メーカー提供VIを使用する場合も、「ドライバVIを配置する」だけで終わらせず、どの入力端子へ何を接続し、どの出力を後段へ渡すかを記載する。

### 7.1.4 VISA / SCPI機器の共通下位VI

```text
SCPI_Write.vi
  in : VISAリファレンス、コマンド、error in
  out: VISAリファレンス、error out

SCPI_Query.vi
  in : VISAリファレンス、コマンド、最大読取長、タイムアウト、error in
  out: VISAリファレンス、応答文字列、error out
```

上位VIは「コマンド生成 → Write / Query → Verify → 機器固有エラー確認」に集中する。

### 7.1.5 Set → Verify

設定コマンドを送信できたことだけで正常と判定しない。読み返し可能な機器では次を実施する。

```text
設定値
  → 文字列にフォーマット（Format Into String）
  → SCPI_Write.vi
  → SCPI_Query.vi（設定値?）
  → 応答を期待型へ変換
  → 設定値と読出値を比較
```

詳細手順では、フォーマット文字列、単位、許容差、Queryコマンド、比較結果のエラーコードまで記載する。

## 7.2 オシロスコープ DLM5058

### 0. 目的と方式

DUTの電圧・電流波形を試験条件どおり取得し、正常時と異常時の解析ファイルを保存する。

**接続**：Ethernet / VISA TCPIP / LXI

### 1. 作成する公開API

| VI | 入力の例 | 出力の例 | 役割 |
|---|---|---|---|
| `DLM5058_Init.vi` | VISA Resource、Timeout、error in | VISA Ref、機種情報、Status、error out | VISA Open、機種確認、基本設定 |
| `DLM5058_Config.vi` | VISA Ref、時間軸、各CH条件、トリガ | VISA Ref、設定確認結果 | 測定条件設定とVerify |
| `DLM5058_Acquire_Start.vi` | VISA Ref、error in | VISA Ref、Status、error out | 取り込み開始 |
| `DLM5058_Acquire_Stop.vi` | VISA Ref、error in | VISA Ref、Status、error out | 取り込み停止 |
| `DLM5058_Save_Waveform.vi` | VISA Ref、保存先、対象CH | 保存ファイルパス、Status、error out | 波形取得・保存 |
| `DLM5058_Close.vi` | VISA Ref、error in | error out | VISA Close |

### 2. 実装順

1. NI MAXでVISAリソースを確認する。
2. メーカー計装ドライバの`VI Tree.vi`またはサンプルで、Open、Config、Start、Stop、Read、Closeの呼出順を確認する。
3. メーカー提供VIを1イベント単位で薄くラップする。
4. 不足機能だけをVISA / SCPIで補完する。
5. 設定VIでは設定値を読み返してVerifyする。
6. 保存ファイル名へ試験ID、条件、日時を含める。
7. Cleanupでは前段エラーがあっても停止とCloseを試みる。

### 3. 単体テスト

- `*IDN?`またはドライバの機種取得でDLM5058を確認する。
- 設定した時間軸、レンジ、トリガを読み返す。
- Start後に取り込み状態、Stop後に停止状態を確認する。
- 既知波形を保存し、ファイルを再読込できることを確認する。
- 通信切断時にTimeoutまたは通信エラーを返す。
- 既存error inでは通常処理をスキップする。

## 7.3 温度ロガー MX100

### 0. 目的と方式

複数チャンネルの温度を一定周期で取得し、試験条件と関連付けて保存する。

**接続**：Ethernet

### 1. 作成する公開API

| VI | 役割 |
|---|---|
| `MX100_Init.vi` | 接続、機種確認、チャンネル設定 |
| `MX100_Log_Start.vi` | ロギング開始 |
| `MX100_Read.vi` | 現在値、単位、状態取得 |
| `MX100_Log_Stop.vi` | ロギング停止 |
| `MX100_Save.vi` | データ保存 |
| `MX100_Close.vi` | 接続終了 |

### 2. 実装順

1. 横河の専用APIまたは利用可能な計装ドライバを確認する。
2. チャンネル番号、測定種別、レンジ、単位を入力クラスタまたは配列へまとめる。
3. Initで全設定を適用し、可能な項目は読み返す。
4. Readはチャンネル順が設定配列と一致するようにする。
5. Timestampと欠測状態を取得値と一緒に返す。
6. 異常時も保存可能なデータを退避する。

### 3. 単体テスト

- 代表2チャンネルへ異なる入力を与え、チャンネル順と単位を確認する。
- 未接続チャンネル、断線、範囲外の状態を確認する。
- Start → Read → Stop → Save → Closeを単体VIで完走する。
- 保存件数とRead回数を比較する。

## 7.4 RAMScope GT170

### 0. 目的と方式

DUTマイコンのRAM値をGT170で取得し、設定チャンネル名、Flag、Timestampへ解析する。

**接続**：USB3.0  
**方式**：RAMScopeVP API 64bit版をLabVIEW 64bitのCLFNから直接呼び出す。

環境準備、DLL疎通、共通エラー変換、DLLラッパ、typedef、数値変換、Builder、Parser、公開API、ダミーデータ生成、PoCのすべては[10](./10_RAMScope実装方針.md)を参照する。

### 公開API

```text
RAMScope_Connect.vi
RAMScope_Init.vi
RAMScope_Set_Cond.vi
RAMScope_Log_Start.vi
RAMScope_Read.vi
RAMScope_Release.vi
RAMScope_Log_Stop.vi
RAMScope_Close.vi
```

### 下位VI

```text
00_Common
  RAMScope_Code_To_Error.vi
  typedef 7個
  数値⇔U8変換VI 5個

10_DLL_Wrapper
  RS_DLL_* 12個

20_Data_Conversion
  Builder 3個
  Parser 2個
```

次は作成しない。

- `RAMScope_Config.vi`：PGT設定は`RAMScope_Init.vi`へ統合する。
- 公開用`RAMScope_Parse_Buffer.vi`：Parserは`RAMScope_Read.vi`内から呼ぶ。
- `RAMScope_Context.ctl`：PoC後に必要性を判断する。
- `RAMScope_Reset.vi`：Stop、Release候補、Closeへ置き換える。

## 7.5 高圧模擬電源・高圧負荷 RZ-X2-100K-H

### 0. 目的と方式

高圧模擬電源と高圧負荷を、TestStandの安全シーケンスから設定・監視・停止できるようにする。

**接続**：Ethernet / SCPI raw socket  
**Control Port**：`5025`

```text
TCPIP0::<IPアドレス>::5025::SOCKET
```

SOCKET接続ではTermination Characterを有効化し、通常はLF（`0x0A`）を使用する。

### 1. 作成する公開API

| VI | 役割 |
|---|---|
| `RZX_Init.vi` | 接続、機種確認、初期化、安全設定 |
| `RZX_Ready.vi` | 運転準備と状態確認 |
| `RZX_Mode_Set.vi` | CV / CC / CPモード設定とVerify |
| `RZX_Voltage_Set.vi` | 電圧設定とVerify |
| `RZX_Current_Limit_Set.vi` | 電流または制限値設定とVerify |
| `RZX_Output_On.vi` | 出力ONと状態確認 |
| `RZX_Output_Off.vi` | 出力OFFと状態確認 |
| `RZX_Run.vi` | 運転開始 |
| `RZX_Stop.vi` | 運転停止 |
| `RZX_Read.vi` | 電圧、電流、電力取得 |
| `RZX_Error_Check.vi` | 機器エラー取得 |
| `RZX_Alarm_Clear.vi` | 原因除去後のアラームクリア |
| `RZX_Close.vi` | ローカル復帰、VISA Close |

### 2. LAN・安全設定

前面パネルで固定IP、サブネット、Control Port、Remote Watchdog、Link Down監視を設定する。

```text
OUTP:PROT:WDOG <秒>
OUTP:PROT:WDOG:MODE 0
SYST:COMM:LAN:LDOWN 1
```

詳細手順では、設定場所、設定値、Queryによる確認結果、異常時の安全状態を記載する。

### 3. Init推奨フロー

```text
VISA Open
  → *IDN?
  → 機種確認
  → *CLS
  → *RST
  → ACKモード設定
  → Watchdog設定
  → Link Down監視
  → RZX_Error_Check.vi
```

### 4. 運転準備・出力

```text
CONT:PERM:COND 1
CONT:PERM:COND?

OUTP:MODE <0/1/2>
OUTP 1 / OUTP 0
OUTP:RUN 1 / OUTP:RUN 0
OUTP:PROT:CLE
```

- ブースター機へ設定系コマンドを直接送らない。
- 運転準備切状態で出力・RUNを行わない。
- モードと運転データの整合を確認する。

### 5. 測定とエラー

```text
MEAS:VOLT?
MEAS:CURR?
MEAS:POW?
SYST:ERR?
```

RZ-X2の電力単位はkW。各設定VI直後に機器エラーを確認し、TestErrorへ記録する。

### 6. 単体テスト

- 設定値と読出値が許容差内で一致する。
- Ready前のOutput Onがエラーになることを確認する。
- Watchdogと通信断で安全状態へ移行する。
- 複数台構成ではマスタとブースターの役割を確認する。
- Cleanupで使用台数分のOutput Offを最初に実行する。

## 7.6 低圧・IGS電源 PPX36-3

### 0. 目的と方式

DUT低圧電源とIGS電源を安全に設定・監視し、異常時に確実にOFFする。

**接続**：Ethernet / VISA  
**実装**：TEXIO公式LabVIEWドライバを主に使用し、不足する安全機能をSCPIで補完する。

### 1. ドライバ利用方針

- `Public`配下をラップする。
- `Private`を直接呼ばない。
- `VI Tree.vi`で公開VIを確認する。
- サンプルで呼び出し順と端子を確認する。
- LabVIEW 64bitで依存関係と実機動作を確認する。

### 2. 作成する公開API

| VI | 主な実装 |
|---|---|
| `PPX_Init.vi` | Initialize + Reset + 安全設定SCPI |
| `PPX_Apply.vi` | VI Level設定 |
| `PPX_Voltage_Set.vi` | 電圧設定とVerify |
| `PPX_Current_Set.vi` | 電流設定とVerify |
| `PPX_Set_Protection.vi` | OVP + OCP設定とVerify |
| `PPX_Output_On.vi` | 出力ONと状態確認 |
| `PPX_Output_Off.vi` | 出力OFFと状態確認 |
| `PPX_Read.vi` | 電圧・電流・電力取得 |
| `PPX_Error_Check.vi` | エラーキュー全件回収 |
| `PPX_Reset_Protection.vi` | 保護回路クリア |
| `PPX_Close.vi` | Close |

### 3. SCPIで補完する安全機能

```text
OUTP:PROT:WDOG:DEL <1～3600秒>
OUTP:PROT:WDOG 1
SYST:CONF:OUTP:PON SAFE
SYST:CONF:VOLT:CONT?
```

### 4. 出力制御・測定・エラー

```text
OUTP 1
OUTP 0
OUTP?
OUTP:PROT:TRIP?
OUTP:PROT:CLE
MEAS:ALL?
SYST:ERR?
```

PPXの電力単位はW。RZ-X2のkWと混同しない。エラーキューは`No error`相当まで繰り返し読み、RZ-X2の「最後の1件」と処理を共通化しない。

### 5. 単体テスト

- 電圧・電流設定を読み返す。
- Output On/Off後に`OUTP?`で状態を確認する。
- OVP/OCPを意図的に発生させ、Trip、Clear、エラーキューを確認する。
- Cleanupで前段エラーがあってもOutput OffとCloseを試みる。

## 7.7 CANインタフェース

CAN方式は[09](./09_CAN通信の実装.md)を正とする。

候補：

- CANalyzer COM / ActiveX
- NI-XNET
- メーカーUSB-CAN
- RAMScope GT170 CAN

共通公開API名：

```text
CAN_Open.vi
CAN_Send.vi
CAN_Read.vi
CAN_Close.vi
```

物理IFやAPIが変わっても、TestStandから見える入出力を可能な範囲で統一する。方式決定後、採用方式の各VIを00Aの標準書式で記載する。

## 7.8 機器別単体試験の完了条件

- [ ] 接続・機種確認ができる
- [ ] 設定値をVerifyできる
- [ ] 計測値の単位とスケールが正しい
- [ ] 機器固有エラーをTestErrorへ変換できる
- [ ] error inありで通常処理をスキップする
- [ ] Cleanup用停止・Close VIが前段エラーでも動く
- [ ] 通信切断時に安全状態へ移行する
- [ ] TestStandを使わないFlow Testで一連の操作が通る
- [ ] 単体テスト手順に入力方法、期待値、保存結果、確認画面が記載されている
