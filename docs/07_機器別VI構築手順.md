# 07. 機器別 VI 構築手順

> **本章の役割**：オシロ、ロガー、電源、CANなどの機器別VIを作る際の要点をまとめる。
>
> RAMScopeの詳細は重複記載せず、[10](./10_RAMScope実装方針.md)を唯一の正本とする。
> 共通入出力・エラー処理は[05](./05_VI設計方針と共通仕様.md)と[06](./06_VIの作り方_手順.md)に従う。

## 7.1 共通方針

### 1イベント1VI

- 1つの機器操作を1つの公開API VIへ分離する。
- 試験条件はTestStandから入力する。
- 待ち、繰り返し、並列処理はTestStandへ置く。
- 公開APIへ`error in / error out`、`Status.ctl`、`TestError.ctl`を持たせる。
- 下位DLLラッパや純粋変換VIはStatus/TestErrorを生成しない。

### VISA / SCPI機器の共通下位VI

```text
SCPI_Write.vi
  in : VISAリファレンス、コマンド、error in
  out: VISAリファレンス、error out

SCPI_Query.vi
  in : VISAリファレンス、コマンド、最大読取長、タイムアウト、error in
  out: VISAリファレンス、応答文字列、error out
```

上位VIは「コマンド生成 → Write / Query → Verify → 機器固有エラー確認」に集中する。

### Set → Verify

```text
設定値
  → Format Into String
  → SCPI_Write
  → SCPI_Query（設定値?）
  → 応答を数値化
  → 許容差内か判定
```

高圧・低圧電源では、送信成功だけで正常判定しない。

## 7.2 オシロスコープ DLM5058

**接続**：Ethernet / VISA TCPIP / LXI

### 作成するVI

| VI | 役割 |
|---|---|
| `DLM5058_Init.vi` | VISA Open、機種確認、基本設定 |
| `DLM5058_Config.vi` | 時間軸、レンジ、カップリング、トリガ設定 |
| `DLM5058_Acquire_Start.vi` | 取り込み開始 |
| `DLM5058_Acquire_Stop.vi` | 取り込み停止 |
| `DLM5058_Save_Waveform.vi` | 波形取得・保存 |
| `DLM5058_Close.vi` | VISA Close |

### 手順

1. NI MAXでVISAリソースを確認する。
2. メーカー計装ドライバが利用できる場合は薄くラップする。
3. 不足機能はVISA / SCPIで補完する。
4. 設定値をVerifyする。
5. 保存ファイル名へ試験ID、条件、日時を含める。
6. 異常時はCleanupで停止し、`ERROR`名で可能な範囲の波形を保存する。

## 7.3 温度ロガー MX100

**接続**：Ethernet

| VI | 役割 |
|---|---|
| `MX100_Init.vi` | 接続、チャンネル設定 |
| `MX100_Log_Start.vi` | ロギング開始 |
| `MX100_Read.vi` | 現在値取得 |
| `MX100_Log_Stop.vi` | ロギング停止 |
| `MX100_Save.vi` | データ保存 |
| `MX100_Close.vi` | 接続終了 |

- 横河の専用APIまたは利用可能な計装ドライバを優先する。
- チャンネル構成、測定レンジ、単位をTestStand条件として管理する。
- 異常時も保存可能なデータを退避する。

## 7.4 RAMScope GT170

**接続**：USB3.0  
**方式**：RAMScopeVP API 64bit版をLabVIEW 64bitのCLFNから直接呼び出す。

環境準備、DLL疎通、共通エラー変換、DLLラッパ、typedef、数値変換、Builder、Parser、公開API、PoCのすべては[10](./10_RAMScope実装方針.md)を参照する。

### 公開API

```text
RAMScope_Connect.vi
RAMScope_Init.vi
RAMScope_Set_Cond.vi
RAMScope_Log_Start.vi
RAMScope_Read.vi
RAMScope_Release.vi
RAMScope_Log_Stop.vi
RAMScope_Close.vi
```

### 下位VI

```text
00_Common
  RAMScope_Code_To_Error.vi
  typedef 7個
  数値⇔U8変換VI 5個

10_DLL_Wrapper
  RS_DLL_* 12個

20_Data_Conversion
  Builder 3個
  Parser 2個
```

次は作成しない。

- `RAMScope_Config.vi`：PGT設定は`RAMScope_Init.vi`へ統合する。
- 公開用`RAMScope_Parse_Buffer.vi`：Parserは`RAMScope_Read.vi`内から呼ぶ。
- `RAMScope_Context.ctl`：PoC後に必要性を判断する。
- `RAMScope_Reset.vi`：Stop、Release候補、Closeへ置き換える。

## 7.5 高圧模擬電源・高圧負荷 RZ-X2-100K-H

**接続**：Ethernet / SCPI raw socket  
**Control Port**：`5025`

```text
TCPIP0::<IPアドレス>::5025::SOCKET
```

SOCKET接続ではTermination Characterを有効化し、通常はLF（`0x0A`）を使用する。

### 作成するVI

| VI | 役割 |
|---|---|
| `RZX_Init.vi` | 接続、機種確認、初期化、安全設定 |
| `RZX_Ready.vi` | 運転準備 |
| `RZX_Mode_Set.vi` | CV / CC / CPモード設定 |
| `RZX_Voltage_Set.vi` | 電圧設定とVerify |
| `RZX_Current_Limit_Set.vi` | 電流または制限値設定とVerify |
| `RZX_Output_On.vi` | 出力ON |
| `RZX_Output_Off.vi` | 出力OFF |
| `RZX_Run.vi` | 運転開始 |
| `RZX_Stop.vi` | 運転停止 |
| `RZX_Read.vi` | 電圧、電流、電力取得 |
| `RZX_Error_Check.vi` | 最後の機器エラー取得 |
| `RZX_Alarm_Clear.vi` | 原因除去後のアラームクリア |
| `RZX_Close.vi` | ローカル復帰、VISA Close |

### LAN・安全設定

前面パネルで固定IP、サブネット、Control Port、Remote Watchdog、Link Down監視を設定する。

```text
OUTP:PROT:WDOG <秒>
OUTP:PROT:WDOG:MODE 0
SYST:COMM:LAN:LDOWN 1
```

- Watchdog時間はTestStandの最長アイドル時間より長くする。
- `RZX_Read.vi`の定期ポーリングをkeep-aliveとして利用できる。
- Watchdogを短くしすぎない。

### Init推奨フロー

```text
VISA Open
  → *IDN?
  → 機種確認
  → *CLS
  → *RST
  → ACKモード設定
  → Watchdog設定
  → Link Down監視
  → RZX_Error_Check.vi
```

### 運転準備・出力

```text
CONT:PERM:COND 1
CONT:PERM:COND?

OUTP:MODE <0/1/2>
OUTP 1 / OUTP 0
OUTP:RUN 1 / OUTP:RUN 0
OUTP:PROT:CLE
```

- ブースター機へ設定系コマンドを直接送らない。
- 運転準備切状態で出力・RUNを行わない。
- モードと運転データの整合を確認する。

### 測定

```text
MEAS:VOLT?
MEAS:CURR?
MEAS:POW?
```

RZ-X2の電力単位はkW。

### エラー処理

```text
SYST:ERR?
```

- 最後に発生した1件を保持し、読み出し後にクリアする。
- 各設定VI直後に確認する。
- 範囲外入力や初期化中エラーをTestErrorへ記録する。

### 複数台

- 使用台数、マスタ、ブースター情報をTestStand条件で持つ。
- VISAリファレンス配列を使用する。
- Cleanupでは全対象機のOutput Offを最優先する。

## 7.6 低圧・IGS電源 PPX36-3

**接続**：Ethernet / VISA  
**実装**：TEXIO公式LabVIEWドライバを主に使用し、不足する安全機能をSCPIで補完する。

### ドライバ利用方針

- `Public`配下をラップする。
- `Private`を直接呼ばない。
- `VI Tree.vi`で公開VIを確認する。
- サンプルで呼び出し順を確認する。
- LabVIEW 64bitで依存関係と実機動作を確認する。

### 作成するVI

| VI | 主な実装 |
|---|---|
| `PPX_Init.vi` | Initialize + Reset + 安全設定SCPI |
| `PPX_Apply.vi` | VI Level設定 |
| `PPX_Voltage_Set.vi` | 電圧設定 |
| `PPX_Current_Set.vi` | 電流設定 |
| `PPX_Set_Protection.vi` | OVP + OCP |
| `PPX_Output_On.vi` | 出力ON |
| `PPX_Output_Off.vi` | 出力OFF |
| `PPX_Read.vi` | 電圧・電流・電力取得 |
| `PPX_Error_Check.vi` | エラーキュー全件回収 |
| `PPX_Reset_Protection.vi` | 保護回路クリア |
| `PPX_Close.vi` | Close |

### SCPI補完する安全機能

```text
OUTP:PROT:WDOG:DEL <1～3600秒>
OUTP:PROT:WDOG 1
SYST:CONF:OUTP:PON SAFE
SYST:CONF:VOLT:CONT?
```

### 出力制御・保護

```text
OUTP 1
OUTP 0
OUTP?
OUTP:PROT:TRIP?
OUTP:PROT:CLE
```

- ON/OFF後に`OUTP?`でVerifyする。
- 保護クリアは原因除去後に行う。
- OVP/OCP設定後に読み返す。

### 測定

```text
MEAS:ALL?
```

PPXの電力単位はW。RZ-X2のkWと混同しない。

### エラーキュー

```text
SYST:ERR?
```

- 最大32件のエラーキューを持つ。
- `No error`相当まで繰り返し読む。
- RZ-X2の「最後の1件」と処理を共通化しない。

## 7.7 CANインタフェース

CAN方式は[09](./09_CAN通信の実装.md)を正とする。

候補：

- CANalyzer COM / ActiveX
- NI-XNET
- メーカーUSB-CAN
- RAMScope GT170 CAN

共通公開API名：

```text
CAN_Open.vi
CAN_Send.vi
CAN_Read.vi
CAN_Close.vi
```

物理IFやAPIが変わっても、TestStandから見える入出力を可能な範囲で統一する。

## 7.8 機器別単体試験の完了条件

- [ ] 接続・機種確認ができる
- [ ] 設定値をVerifyできる
- [ ] 計測値の単位とスケールが正しい
- [ ] 機器固有エラーをTestErrorへ変換できる
- [ ] error inありで通常処理をスキップする
- [ ] Cleanup用停止・Close VIが前段エラーでも動く
- [ ] 通信切断時に安全状態へ移行する
- [ ] TestStandを使わないFlow Testで一連の操作が通る
