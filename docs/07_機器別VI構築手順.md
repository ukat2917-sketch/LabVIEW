# 07. 機器別 VI 構築手順

> **本章の役割**：オシロ、ロガー、電源、CANなどの機器別VIを作る際の要点をまとめる。
>
> RAMScopeは本章へ詳細を重複させず、[10A](./10A_RAMScope実装手順_DLL準備とCLFN疎通確認.md) → [10B](./10B_RAMScope_VI作成手順_STEP3_STEP4詳細.md) を正本とする。
> 共通入出力・エラー処理は [05](./05_VI設計方針と共通仕様.md) / [06](./06_VIの作り方_手順.md) に従う。

## 7.1 共通方針

### 1イベント1VI

- 1つの機器操作を1つのVIへ分離する。
- 試験条件はTestStandから入力する。
- 待ち、繰り返し、並列処理はTestStandへ置く。
- 全VIへ`error in / error out`、`Status.ctl`、`TestError.ctl`を持たせる。

### VISA / SCPI機器の共通下位VI

```text
SCPI_Write.vi
  in : VISAリファレンス、コマンド、error in
  out: VISAリファレンス、error out

SCPI_Query.vi
  in : VISAリファレンス、コマンド、最大読取長、タイムアウト、error in
  out: VISAリファレンス、応答文字列、error out
```

上位VIは「コマンド生成 → Write / Query → Verify → 機器固有エラー確認」に集中する。

### Set → Verify

設定コマンド送信後に対応するクエリで読み返し、設定値と照合する。

```text
設定値
  → Format Into String
  → SCPI_Write
  → SCPI_Query（設定値?）
  → 応答を数値化
  → 許容差内か判定
```

高圧・低圧電源では、送信成功だけで正常判定しない。

## 7.2 オシロスコープ DLM5058

**接続**：Ethernet / VISA TCPIP / LXI

### 作成するVI

| VI | 役割 |
|----|------|
| `DLM5058_Init.vi` | VISA Open、機種確認、基本設定 |
| `DLM5058_Config.vi` | 時間軸、レンジ、カップリング、トリガ設定 |
| `DLM5058_Acquire_Start.vi` | 取り込み開始 |
| `DLM5058_Acquire_Stop.vi` | 取り込み停止 |
| `DLM5058_Save_Waveform.vi` | 波形取得・保存 |
| `DLM5058_Close.vi` | VISA Close |

### 手順

1. NI MAXでVISAリソースを確認する。
2. メーカー計装ドライバが利用できる場合は薄くラップする。
3. 不足機能はVISA / SCPIで補完する。
4. 設定値をVerifyする。
5. 保存ファイル名へ試験ID、条件、日時を含める。
6. 異常時はCleanupで停止し、`ERROR`名で可能な範囲の波形を保存する。

# 7.5 高圧模擬電源・高圧負荷 RZ-X2-100K-H

**接続**：Ethernet / SCPI raw socket  
**Control Port**：`5025`  
**VISAリソース例**：

```text
TCPIP0::<IPアドレス>::5025::SOCKET
```

SOCKET接続ではTermination Characterを有効化し、通常はLF（`0x0A`）を使用する。終端設定を誤るとVISA Readがタイムアウトしやすい。

## 7.5.1 作成するVI

| VI | 役割 |
|----|------|
| `RZX_Init.vi` | 接続、機種確認、初期化、安全設定 |
| `RZX_Ready.vi` | 運転準備を入れる |
| `RZX_Mode_Set.vi` | CV / CC / CPモード設定 |
| `RZX_Voltage_Set.vi` | 電圧設定とVerify |
| `RZX_Current_Limit_Set.vi` | 電流または制限値設定とVerify |
| `RZX_Output_On.vi` | 出力ON |
| `RZX_Output_Off.vi` | 出力OFF |
| `RZX_Run.vi` | 運転開始 |
| `RZX_Stop.vi` | 運転停止 |
| `RZX_Read.vi` | 電圧、電流、電力取得 |
| `RZX_Error_Check.vi` | 最後の機器エラーを取得 |
| `RZX_Alarm_Clear.vi` | 原因除去後のアラームクリア |
| `RZX_Close.vi` | ローカル復帰、VISA Close |

電圧・電流設定コマンドの正確な階層と値域は、使用するRZ-X2のプログラミングマニュアルで最終確認する。確認前に推定コマンドを本番VIへ固定しない。

## 7.5.2 機器LAN設定

前面パネルで次を設定する。

- 固定IP
- サブネット
- Control Port = 5025
- Remote Watchdog Time
- Remote Watchdog Operation
- Link Down Monitoring

設定画面で値を入力した後、画面側のENTERで確定する。テンキー側のENTERだけでは反映されない場合がある。

## 7.5.3 安全設定

通信途絶時に出力が残らないよう、初期化時にWatchdogとLink Down検出を有効化する。

確認済みSCPI：

```text
OUTP:PROT:WDOG <秒>
OUTP:PROT:WDOG:MODE 0
SYST:COMM:LAN:LDOWN 1
```

- Watchdog時間はTestStandの最長アイドル時間より長くする。
- `RZX_Read.vi`の定期ポーリングをkeep-aliveとして利用できる。
- Watchdogを短くしすぎると正常試験中に誤停止する。

## 7.5.4 `RZX_Init.vi`推奨フロー

```text
VISA Open
  → *IDN?
  → 機種名がTAKASAGO,RZ-X2-100K-Hで始まることを確認
  → *CLS
  → *RST
  → ACKモードを無効または設計値へ固定
  → Watchdog設定
  → Link Down監視設定
  → 必要なら* TST?相当の自己診断
  → RZX_Error_Check.vi
```

`*RST`は通信設定を初期化しないことを確認済み。ただし`SYSTem:RESet`はユーザー調整まで初期化するため通常使用しない。

## 7.5.5 運転準備

RZ-X2は出力ONの前に運転準備が必要。

```text
CONT:PERM:COND 1
CONT:PERM:COND?
```

`RZX_Ready.vi`で設定と読み返しを行う。外部接点制御が有効な場合や状態遷移中は受け付けない可能性がある。

## 7.5.6 出力・運転

| コマンド | 役割 |
|----------|------|
| `OUTP:MODE <0/1/2>` | CV / CC / CP |
| `OUTP 1` / `OUTP 0` | 出力ON / OFF |
| `OUTP:RUN 1` / `OUTP:RUN 0` | RUN / STOP |
| `OUTP:PROT:CLE` | 原因除去後のアラームクリア |

制限条件：

- ブースター機へ設定系コマンドを直接送らない。
- 運転準備切状態では出力・RUNを行わない。
- モードと運転データの整合を確認する。

## 7.5.7 測定

```text
MEAS:VOLT?
MEAS:CURR?
MEAS:POW?
```

- 電圧：V
- 電流：A
- 電力：RZ-X2はkW表記である点に注意する。

`RZX_Read.vi`は3クエリを実行し、Watchdogのkeep-aliveを兼ねる。

## 7.5.8 エラー処理

```text
SYST:ERR?
```

RZ-X2は標準的な複数件エラーキューではなく、最後に発生した1件を保持し、読み出し後にクリアする。

- 各設定VIの直後に毎回確認する。
- 後でまとめて読まない。
- 範囲外入力の`-120`等をTestErrorへ記録する。
- F/W初期化中の`-906`はInit時にリトライ候補とする。

## 7.5.9 複数台

- 使用台数、マスタ、ブースターの情報をTestStand条件で持つ。
- リファレンス配列を使用する。
- 設定系コマンドはマスタ機だけに送る必要があるかを機器構成ごとに確認する。
- Cleanupでは全対象機のOutput Offを最優先する。

# 7.6 低圧・IGS電源 PPX36-3

**接続**：Ethernet / VISA  
**実装**：TEXIO公式LabVIEWドライバを主に使用し、不足する安全機能をSCPIで補完する。

## 7.6.1 ドライバ利用方針

```text
PPX.lvproj
PPX.lvlib
Public/
Examples/
Private/
```

- `Public`配下をラップする。
- `Private`を直接呼ばない。
- `VI Tree.vi`で公開VIを確認する。
- サンプル`PPX Output DC Voltage and Current.vi`で呼び出し順を確認する。
- LabVIEW 64bitで開き、依存関係と実機動作を確認する。

## 7.6.2 作成するVI

| VI | 主な実装 |
|----|----------|
| `PPX_Init.vi` | Initialize + Reset + 安全設定SCPI |
| `PPX_Apply.vi` | `Configure VI Level.vi`をラップ |
| `PPX_Voltage_Set.vi` | `Configure Voltage Level.vi` |
| `PPX_Current_Set.vi` | `Configure Current Level.vi` |
| `PPX_Set_Protection.vi` | OVP + OCP設定 |
| `PPX_Output_On.vi` | `Configure Output.vi` |
| `PPX_Output_Off.vi` | `Configure Output.vi` |
| `PPX_Read.vi` | 電圧・電流・電力取得 |
| `PPX_Error_Check.vi` | エラーキューを全件回収 |
| `PPX_Reset_Protection.vi` | 保護回路クリア |
| `PPX_Close.vi` | Close |

## 7.6.3 公式ドライバで使用する主なVI

- `Initialize.vi`
- `Close.vi`
- `Configure VI Level.vi`
- `Configure VI Limit.vi`
- `Configure Voltage Level.vi`
- `Configure Current Level.vi`
- `Configure OVP.vi`
- `Configure OCP.vi`
- `Configure Output.vi`
- `Read Voltage and Current.vi`
- `Read Output Status.vi`
- `Output Protection Tripped.vi`
- `Reset Output Protection.vi`
- `Error Query.vi`
- `Reset.vi`
- `Revision Query.vi`

## 7.6.4 SCPI補完する安全機能

公式ドライバに対応VIが見当たらない場合、Initialize後のVISAリファレンスを使ってSCPIを送る。

### Watchdog

```text
OUTP:PROT:WDOG:DEL <1～3600秒>
OUTP:PROT:WDOG 1
```

### 電源投入時の安全状態

```text
SYST:CONF:OUTP:PON SAFE
```

設定は電源再投入後に有効になる可能性があるため、設定値を読み返して運用手順へ反映する。

### 外部電圧制御

```text
SYST:CONF:VOLT:CONT?
```

通常のリモート電圧設定を使用する場合はローカル設定相当であることを確認する。

### キーロック

キーロック中も前面パネルから出力OFFできる設定を優先し、非常停止手段を残す。

## 7.6.5 出力制御・保護

```text
OUTP 1
OUTP 0
OUTP?
OUTP:PROT:TRIP?
OUTP:PROT:CLE
```

- ON/OFF後に`OUTP?`でVerifyする。
- 保護クリアは原因除去後に行う。
- OVP/OCP設定後に読み返す。
- 電圧制限の自動調整機能がある場合は、電圧設定と保護設定の順序を確認する。

## 7.6.6 測定

効率を優先する場合：

```text
MEAS:ALL?
```

応答例：

```text
電圧,電流,電力
```

PPXの電力単位はW。RZ-X2のkWと混同しない。

公式ドライバの`Read Voltage and Current.vi`で電力が取得できない場合は、SCPIの`MEAS:POW?`または`MEAS:ALL?`で補完する。

## 7.6.7 エラーキュー

```text
SYST:ERR?
```

PPXは最大32件のエラーキューを持つ。

- `0,"No error"`相当が返るまで繰り返し読む。
- RZ-X2の「最後の1件だけ」と処理を共通化しない。
- `PPX_Error_Check.vi`を機器専用で作る。

## 7.6.8 リモートセンシングとスルーレート

- 4線式リモートセンシングを使用する場合、機器設定と実配線を一致させる。
- CVLS等のスルーレートモードを使用する場合、立ち上げ時間と試験タイミングの関係を実機確認する。

## 7.7 CANインタフェース

CAN方式は [09](./09_CAN通信の実装.md) を正とする。

候補：

- CANalyzer COM / ActiveX
- NI-XNET
- Contec等のUSB-CAN
- RAMScope GT170 CAN機能

共通VI名：

```text
CAN_Open.vi
CAN_Send_Mode.vi
CAN_Read.vi
CAN_Close.vi
```

物理IFやAPIが変わっても、TestStandから見える入出力を可能な範囲で統一する。

## 7.8 機器別単体試験の完了条件

- [ ] 接続・機種確認ができる
- [ ] 設定値をVerifyできる
- [ ] 計測値の単位とスケールが正しい
- [ ] 機器固有エラーをTestErrorへ変換できる
- [ ] error inありで通常処理をスキップする
- [ ] Cleanup用停止・Close VIが前段エラーでも動く
- [ ] 通信切断時に安全状態へ移行する
- [ ] TestStandを使わないFlow Testで一連の操作が通る
