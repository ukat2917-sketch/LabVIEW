# 03. LabVIEW 環境構築

VI を作り始める前に、開発 PC に必要なソフト・ドライバを準備し、各機器との通信を確認する。

## 3.1 必要なソフトウェア

| ソフト | 用途 | 備考 |
|--------|------|------|
| **LabVIEW**（推奨：最新の対応バージョン） | VI 開発・機器制御 | TestStand と互換のバージョンを選ぶ |
| **TestStand** | 試験フロー管理 | LabVIEW Adapter を有効化 |
| **NI-VISA** | Ethernet/USB/GPIB 機器との汎用通信 | SCPI 機器（オシロ・電源）制御の基盤 |
| **NI-XNET** | CAN 通信（NI ハードウェア使用時） | dbc 対応。[09](./09_CAN通信の実装.md) 参照 |
| **NI-DAQmx** | （必要時）DAQ デバイス | 本構成では必須でない |
| 各機器の **計装ドライバ（Instrument Driver）** | 機器固有の制御 VI | NI Instrument Driver Network 等から入手 |
| RAMScope 用 **API / マックシステムズ製ドライバ** | RAM 計測・CAN | [10](./10_RAMScope実装方針.md) 参照 |

> **バージョン整合性に注意**：LabVIEW・TestStand・各ドライバはビット数（32/64bit）と
> バージョンの互換性がある。TestStand から呼ぶ VI のビット数と LabVIEW Runtime を一致させること。

## 3.2 ドライバの探し方・入手方針

機器制御 VI は、可能な限り次の優先順位で用意する。

1. **NI 認定の Plug and Play 計装ドライバ**（機器メーカー提供の LabVIEW VI 群）
   - 横河 DLM5058、AMETEK PPX シリーズ等は計装ドライバが提供されている場合がある。
2. **IVI ドライバ**（クラス互換が必要な場合）
3. **SCPI コマンドを VISA で直接送信**（ドライバが無い／不足する場合）
   - Ethernet（TCPIP/LXI）機器は `VISA Write` / `VISA Read` で SCPI コマンドを送受信できる。
4. メーカー専用 API / DLL（RAMScope など）

## 3.3 ドライバのバージョン互換性（重要）

メーカーが公開する計装ドライバは「対応 LabVIEW バージョン」や「必要 NI-VISA バージョン」が
古い表記のまま更新されていないことが多い（例：横河の計測器ドライバが
**「LabVIEW 2021 Upgrade / NI-VISA 5.4」** で止まっている等）。
**この表記が古くても、新しい LabVIEW（例：LabVIEW 2026）で動作するのが基本** である。
理由と注意点を以下にまとめる。

### 3.3.1 なぜ古い表記でも新しい LabVIEW で動くのか

1. **LabVIEW ドライバはソースVI（G言語）で前方互換がある**
   - Plug and Play / Project-Style ドライバはコンパイル済みバイナリではなく、
     **ソースVI（.vi / .lvlib）** で配布される。
   - LabVIEW は後方互換性が強く、**古いバージョンで保存されたVIを新しい LabVIEW で開くと
     自動で再コンパイル（マスコンパイル）される**。
   - → 「LabVIEW 2021 で保存」されたドライバも、**LabVIEW 2026 で開けば 2026 用に再コンパイルされて動く**。
     表記の「2021」は確認済みの基準バージョンであって上限ではない。

2. **「NI-VISA 5.4」は最低要件であり固定指定ではない**
   - ドライバが使う VISA 関数（`VISA Open / Write / Read / Close` など）は API が安定しており、
     **NI-VISA は後方互換**。新しい NI-VISA でも旧バージョン時代の API はそのまま動く。
   - → **古い 5.4 を入れる必要はなく、LabVIEW 2026 に対応した現行の NI-VISA を入れればよい**
     （5.4 自体は古すぎて 2026 環境にはインストールできない）。

### 3.3.2 推奨セットアップ手順

1. **LabVIEW 2026** をインストール。
2. **現行の NI-VISA**（2026 対応の最新版。NI Package Manager から導入）をインストール
   — ※ 5.4 ではなく最新を入れる。
3. メーカー計装ドライバ（DLM5058 / MX100 用）を `instr.lib` に配置、
   または VI Package Manager / NI 提供インストーラで導入。
4. ドライバを開く → LabVIEW がマスコンパイル → **LabVIEW 2026 形式で保存**。
5. `*IDN?` 等で通信確認（[3.4](#34-機器接続の事前確認手順)）。

### 3.3.3 注意点（まれに起きること）

- 開いた際に **「非推奨（deprecated）関数」の警告** が出ることがあるが、通常は動作に支障なし。
- **32bit / 64bit** を LabVIEW・NI-VISA・ドライバ・他DLL系で揃える。
- ごくまれに、新しい LabVIEW で削除された旧VIを使うドライバは要修正（Plug and Play 系では稀）。
- 非常に古い形式のパスワードロック付きライブラリは変換でつまずく場合があるが、
  公開計装ドライバでは通常問題にならない。

### 3.3.4 保険：ドライバが不調でも SCPI 直叩きで代替可能

- DLM5058・MX100 等は Ethernet（TCPIP/LXI）接続のため、万一ドライバが動作しなくても
  **VISA で SCPI コマンドを直接送受信**すれば計測・制御できる（ドライバ非依存）。
- つまりドライバの有無・バージョンは**性能要件ではなく実装の手間の問題**に留まる。
  （[07_機器別VI構築手順.md](./07_機器別VI構築手順.md) の方針どおり）

## 3.4 機器接続の事前確認手順

VI を作る前に、まず **手動で通信が通ること** を確認する。

### (1) ネットワーク疎通確認
1. 各機器に固定 IP を設定（[01](./01_システム概要と構成.md) の IP 表）。
2. PC のコマンドプロンプトで `ping <機器IP>` が通ることを確認。

### (2) NI-MAX での確認（VISA 機器）
1. **NI MAX（Measurement & Automation Explorer）** を起動。
2. `Devices and Interfaces` → `Network Devices` で対象機器を追加。
3. VISA リソース名（例：`TCPIP0::192.168.0.11::inst0::INSTR`）を確認。
4. `Open VISA Test Panel` から `*IDN?` を送信し、機器の識別文字列が返ることを確認。
   - 返答があれば SCPI 通信は OK。
5. VISA リソース名を [01](./01_システム概要と構成.md) の表に記録する。

### (3) CAN インタフェースの確認
- NI-XNET 使用時：NI MAX に XNET インタフェースが見えること、dbc を登録できることを確認。
- USB-CAN（Contec 等）使用時：付属ドライバのテストツールで送受信できることを確認。
- 詳細は [09_CAN通信の実装.md](./09_CAN通信の実装.md)。

### (4) RAMScope の確認
- API / ドライバの動作確認は [10_RAMScope実装方針.md](./10_RAMScope実装方針.md) を参照。

## 3.5 プロジェクト構成（推奨フォルダ構成）

LabVIEW プロジェクト（`.lvproj`）を作成し、以下のように整理する。

```
TestSystem.lvproj
├─ 00_Common/          … 共通サブVI（エラー処理、ログ書込、型定義）
│    ├─ Status.ctl     … 実行結果ステータス（型定義 Enum）
│    ├─ TestError.ctl  … エラー情報クラスタ（型定義）
│    └─ Log_Append.vi  … 共通ログ追記VI
├─ 10_Oscilloscope/    … DLM5058 関連VI
├─ 20_Logger/          … MX100 関連VI
├─ 30_RAMScope/        … GT170 関連VI
├─ 40_HV_Power/        … 高圧模擬/負荷 RZ-X 関連VI
├─ 50_LV_Power/        … 低圧/IGS PPX36-3 関連VI
├─ 60_CAN/             … CAN 送受信VI
└─ 90_TypeDefs/        … 共有型定義
```

> **型定義（.ctl）を必ず使う**：ステータスやエラー情報のクラスタは「型定義」にしておくと、
> 後から項目を追加しても全 VI に変更が伝播し、保守が容易になる。
> 型定義の**具体的な作り方**は [06_VIの作り方_手順.md](./06_VIの作り方_手順.md) の 6.1 を参照。

### 3.5.1 初期セットアップ手順（プロジェクトの実フォルダを先に作る）

上記の構成図は「プロジェクトの実フォルダ（`.lvproj` を置く場所）の中身」を表す。
**プロジェクトを保存する前は実フォルダが存在しない**ため、最初に次の順で土台を作る。

> ⚠️ **最初のハマりどころ**：LabVIEW の**プロジェクトツリー上のフォルダ**と
> **ディスク上の実フォルダ**は別物。ツリーで整理しただけでは実ファイルは移動しない
> （詳細は 3.5.2）。そのため **ディスク側のフォルダを先に作ってから** VI/型定義を
> そこへ保存していくのが確実。

1. **プロジェクトルート（親フォルダ）を作る**
   作業用ドライブ（例：`C:\LabVIEW work\`）に、プロジェクト専用フォルダを 1 つ作成する。
   例：`C:\LabVIEW work\AutoTestSystem\`
   → **プロジェクトに関するファイルはすべてこの 1 フォルダに収める**
   （フォルダごと zip・バックアップ・別 PC への移動・バージョン管理が容易になる）。
   `.lvproj` を作業ドライブ直下に直接置かない（他の資材と混ざるため）。

2. **サブフォルダを先にエクスプローラーで作る**
   ルートフォルダの中に、上記構成図のサブフォルダを実フォルダとして作成する：
   `00_Common` / `10_Oscilloscope` / `20_Logger` / `30_RAMScope` /
   `40_HV_Power` / `50_LV_Power` / `60_CAN` / `90_TypeDefs`

3. **プロジェクトを保存**
   LabVIEW で `ファイル → プロジェクトを保存` → 手順 1 のルートフォルダの中に
   `<プロジェクト名>.lvproj` として保存する。→ ここが「プロジェクトの実フォルダ」になる。

4. **VI・型定義を対応するサブフォルダへ保存**
   以降、作成する VI・`.ctl` は「名前を付けて保存」で対応するサブフォルダ（実フォルダ）へ保存する。
   例：`Status.ctl` → `00_Common\`、`RZX_Voltage_Set.vi` → `40_HV_Power\`。

> **サードパーティ製ドライバの扱い**：CAN ドライバ（Vector XL / Hooovahh 版など、[09](./09_CAN通信の実装.md)）や
> 計装ドライバ（PPX 公式ドライバ、[07](./07_機器別VI構築手順.md) 7.5.5）は、
> プロジェクトルートの**外**（インストール先／ドライバ配布フォルダ）に置いたままでよい。
> プロジェクトからは「依存関係（依存項目）」として参照される。
> ※ フォルダ名のスペース（`LabVIEW work` 等）は通常問題ないが、一部ツールで不都合が出る場合は
> 　アンダースコア（`LabVIEW_work`）が無難。

### 3.5.2 プロジェクトツリーのフォルダ 2 種類（重要）

プロジェクトツリーでフォルダを作るとき、2 種類あり挙動が全く異なる。混同するとツリーは
整理されて見えるのに実ファイルはバラバラ、という状態になる。

| 種類 | 作り方 | ディスク（実ファイル）との関係 |
|------|--------|------------------------------|
| **仮想フォルダ** | ツリーで右クリック → 新規 → 仮想フォルダ | ⚠️ **ツリー上の見た目だけ**。実ファイルは移動・作成されない |
| **自動更新フォルダ** | ツリーで右クリック → 新規 → 自動更新フォルダ（ディスクのフォルダを指定）| ディスクのフォルダと同期（中身が自動でツリーに反映）|

> **推奨**：本システム規模では **「自動更新フォルダ」**方式が、ツリーとディスクが常に一致して
> 混乱が少ない。3.5.1 の手順 2 で作った実フォルダ（`00_Common` 等）を、それぞれ
> **自動更新フォルダとしてプロジェクトに追加**すれば、この構成図とディスクが完全に一致する。
> 仮想フォルダを使う場合は、ドラッグしただけでは実ファイルが移動しない点に注意し、
> 実ファイルの保存先を別途「名前を付けて保存」で揃えること。

### 3.5.3 プロジェクトツリーへのフォルダ追加手順（自動更新フォルダ）

3.5.1 でディスクに作った実フォルダ（`00_Common` 等）を、プロジェクトエクスプローラの
ツリーに反映させる具体手順。**ディスクにフォルダを作っただけではツリーに現れない**ため、
この操作で追加する。

1. プロジェクトエクスプローラで **「マイ コンピュータ」を右クリック**。
2. **`追加(D)` → `フォルダ（自動更新）…`** を選択。
   （`フォルダ（スナップショット）` は追加時点の中身を 1 回だけ取り込む方式で以後同期しないため、
   　通常は使わない。必ず **自動更新** を選ぶ）
3. ディスク上の対象フォルダ（例：`00_Common`）を選んで OK。
   → ツリーに `00_Common` が現れ、以後その中に保存したファイルは**自動でツリーに反映**される。
4. 残りのフォルダ（`10_Oscilloscope`〜`90_TypeDefs`）も 1〜3 を繰り返して追加。

**完成イメージ（プロジェクトツリー）：**

```
プロジェクト: SVS_AutoSystem.lvproj
└─ マイ コンピュータ
   ├─ 00_Common/       （+ Status.ctl / TestError.ctl などを内包）
   ├─ 10_Oscilloscope/
   ├─ 20_Logger/
   ├─ 30_RAMScope/
   ├─ 40_HV_Power/
   ├─ 50_LV_Power/
   ├─ 60_CAN/
   ├─ 90_TypeDefs/
   ├─ 依存項目
   └─ ビルド仕様
```

> **既に作成済みのファイルをフォルダに入れるには**：
> 例えば `Status.ctl` を先にプロジェクトルート直下へ保存してしまった場合、
> `00_Common` を自動更新フォルダとして追加しても、**実ファイルが `00_Common` の中に
> 無ければツリーの位置は変わらない**。LabVIEW で対象を開き
> `ファイル → 名前を付けて保存` で `00_Common\` の中へ保存し直す（実ファイルを移動）と、
> 自動更新フォルダの下に現れる。

> **フォルダ名は空のうちに確定する**：VI や `.ctl` がフォルダを参照し始めた後にフォルダ名を
> 変えるとリンク切れの修正が必要になる。綴り（`Oscilloscope` 等）・大文字小文字は
> **中身が空の初期段階で揃えておく**こと。
