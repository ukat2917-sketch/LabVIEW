# 12. 異常系処理とシャットダウン設計

> **本章の役割**：正常終了・異常終了のどちらでも、事故防止、データ保全、機器状態の解放を行うCleanup順序を定義する。

## 12.1 基本方針

1. 人身・設備リスクの高いエネルギー源を最初に停止する。
2. 異常解析に必要な計測データを可能な範囲で保存する。
3. DUT低圧電源を停止する。
4. RAMScopeの計測を停止し、API接続を終了する。
5. 各通信セッションを解放する。
6. Cleanup中にエラーが発生しても、後続の安全停止を可能な限り継続する。

## 12.2 装置別の処理

| 装置 | 異常時の処理 | 理由 |
|------|--------------|------|
| 高圧電源・高圧負荷 | **最初に出力OFF** | 人身・機材事故を防ぐ |
| オシロ・ロガー | 計測停止、異常データ保存 | 異常時の信号を解析用に残す |
| DUT低圧電源 | 高圧停止とデータ退避の後にOFF | 高圧が残る状態で制御を失わない |
| RAMScope | 計測中ならStop、必要ならRelease、最後にDeviceExit | 計測状態とAPI内部状態を解放する |
| IGS・通信セッション | 試験仕様に従いOFF / Close | 後始末と次試験への影響防止 |

過去資料の`RAMScope_Reset.vi`は現在のVI構成では使用しない。次のVIへ置き換える。

```text
RAMScope_Log_Stop.vi
RAMScope_Release.vi（要否は実機検証中）
RAMScope_Close.vi
```

## 12.3 推奨Cleanup順序

```text
① 高圧模擬電源・高圧負荷をOFF
        ↓
② オシロ・ロガー・RAMScopeの必要データを退避
        ↓
③ DUT低圧電源をOFF
        ↓
④ RAMScopeが計測中ならRAMScope_Log_Stop.vi
        ↓
⑤ RAMScope_Release.vi（採用する場合）
        ↓
⑥ RAMScope_Close.vi（DeviceExit）
        ↓
⑦ IGS電源OFF、VISA/XNET/CAN等のセッションClose
```

### RAMScopeをDUT停止後に終了する理由

RAMScope終了処理はDUT低圧停止後に行うという安全要件を維持する。ただし、異常データの退避が必要な場合は、DUT停止前に最後の`RAMScope_Read.vi`またはログ取得を試みる。

実機の電気的条件やプローブ仕様により安全手順が異なる場合は、設備責任者とベンダー仕様を優先する。

## 12.4 TestStand Cleanup例

```text
Cleanup
  1. RZX_Output_Off.vi（高圧模擬・負荷、使用台数分）
  2. If DLM measuring:
       DLM5058_Acquire_Stop.vi
       DLM5058_Save_Waveform.vi（ERROR名）
  3. If MX100 logging:
       MX100_Log_Stop.vi
       MX100_Save.vi（ERROR名）
  4. If RAMScope data remains:
       RAMScope_Read.vi / 保存処理（可能な場合）
  5. PPX_Output_Off.vi（DUT低圧）
  6. If RAMScope.IsMeasuring:
       RAMScope_Log_Stop.vi
  7. RAMScope_Release.vi（有効化している場合）
  8. RAMScope_Close.vi
  9. PPX_Output_Off.vi（IGS）
 10. VISA / XNET / CAN / その他セッションClose
```

## 12.5 Cleanup VIのエラー処理

### 通常VI

前段の`error in.status=True`なら、実処理をスキップして元エラーを伝播する。

### Cleanup VI

前段エラーがあっても終了処理を試みる。

```text
元のerror in ─────────────────────────────┐
                                          ▼
エラーなしクラスタ → Close処理 → Close error
                                          │
元のerror in ───────────────→ Merge Errors┘
```

- 元エラーを優先して保持する。
- 元エラーがなくCloseだけ失敗した場合はCloseエラーを返す。
- Cleanupエラーをログへ別途記録する。
- 1つのCleanupステップの失敗で残りを打ち切らない。

## 12.6 計測状態フラグ

TestStandのFileGlobals等へ状態を保持する。

| フラグ | Trueにするタイミング | Falseにするタイミング |
|--------|----------------------|-----------------------|
| `DLM.IsMeasuring` | Acquire Start成功後 | Stop成功後 |
| `MX100.IsLogging` | Log Start成功後 | Stop成功後 |
| `RAMScope.IsMeasuring` | `RAMScope_Log_Start.vi`成功後 | `RAMScope_Log_Stop.vi`成功後 |
| `RAMScope.IsConnected` | `RAMScope_Connect.vi`成功後 | `RAMScope_Close.vi`成功後 |

Cleanupではフラグを使って必要な停止処理を判断する。ただしフラグが壊れている可能性もあるため、DeviceExit等の冪等性（複数回実行しても安全か）は実機で確認する。

## 12.7 異常データの命名

```text
<試験ID>_<条件>_<日時>_ERROR_<機器>.<拡張子>
```

例：

```text
T2026-0001_HV400V_20260714_141530_ERROR_DLM5058.csv
T2026-0001_HV400V_20260714_141530_ERROR_RAMScope.bin
```

保存時に次も記録する。

- 試験条件
- 異常発生時刻
- 発生ステップ
- `TestError.ctl`
- RAMScope API ReturnCode
- LostDataNum
- 取得データが途中であること

## 12.8 TestErrorとレポート

- 各VIは標準error cluster、`Status.ctl`、`TestError.ctl`を出力する。
- RAMScope API ReturnCodeは`RAMScope_Code_To_Error.vi`で標準error clusterへ変換する。
- TestStandは元エラー、Cleanup結果、保存ファイルのパスをレポートへ残す。
- Cleanupで別のエラーが出ても、最初に試験を中断させた原因を失わない。

## 12.9 異常系テスト

最低限、次を意図的に発生させて確認する。

1. Ethernet通信切断
2. USB切断
3. RAMScope未接続でDeviceInit
4. RAMScope計測中の後段エラー
5. 設定範囲外入力
6. タイムアウト
7. バッファ取りこぼし
8. Cleanup中のClose失敗

### 合格条件

- [ ] 高圧が最初にOFFになる
- [ ] 異常データがERROR名で保存される
- [ ] DUT低圧停止後にRAMScope終了処理が行われる
- [ ] `RAMScope_Close.vi`が前段エラーに関係なく実行される
- [ ] Cleanupの途中エラーでも後続停止が続行される
- [ ] 元エラーとCleanupエラーの両方を追跡できる
- [ ] 次回試験開始時に機器状態が残らない
