# 12. 異常系処理とシャットダウン設計

> **本章の役割**：正常終了・異常終了のどちらでも、事故防止、データ保全、機器状態の解放を行うCleanup順序を定義する。
>
> Cleanup VIやTestStandステップの詳細手順は[00A](./00A_LabVIEW実装資料の記述ルール.md)に従い、入力、配置処理、接続順、異常テストを記載する。

---

## 12.1 なぜCleanupをMainと分離するのか

Mainの途中でエラーが発生すると、通常の後続ステップは実行されない可能性がある。高圧出力、計測中状態、通信セッションをMainの正常順序だけに依存させると、危険な状態が残る。

そのため、停止・保存・CloseをCleanupへ分離し、Mainの成功・失敗に関係なく実行する。

---

## 12.2 基本方針

1. 人身・設備リスクの高いエネルギー源を最初に停止する。
2. 異常解析に必要な計測データを可能な範囲で保存する。
3. DUT低圧電源を停止する。
4. RAMScopeの計測を停止し、API接続を終了する。
5. 各通信セッションを解放する。
6. Cleanup中にエラーが発生しても、後続の安全停止を可能な限り継続する。
7. 最初に試験を中断させた元エラーをCleanupエラーで上書きしない。

---

## 12.3 装置別のCleanup責務

| 装置 | 異常時の処理 | 理由 | 状態判定に使う値 |
|---|---|---|---|
| 高圧電源・高圧負荷 | 最初に出力OFF | 人身・機材事故を防ぐ | 使用台数、Output状態 |
| オシロ | 計測停止、異常波形保存 | 異常発生前後の信号を残す | `DLM.IsMeasuring` |
| 温度ロガー | ロギング停止、異常ログ保存 | 異常時の温度履歴を残す | `MX100.IsLogging` |
| DUT低圧電源 | 高圧停止とデータ退避後にOFF | 高圧が残る状態で制御を失わない | Output状態 |
| RAMScope | 必要データ読出し、Stop、Release候補、DeviceExit | 計測状態とAPI内部状態を解放 | `IsMeasuring`、`IsConnected` |
| IGS・通信セッション | 試験仕様に従いOFF / Close | 次試験への影響を防ぐ | 接続・出力状態 |

過去資料の`RAMScope_Reset.vi`は使用しない。

```text
RAMScope_Log_Stop.vi
RAMScope_Release.vi（要否は実機検証中）
RAMScope_Close.vi
```

---

## 12.4 推奨Cleanup順序

```text
① 高圧模擬電源・高圧負荷をOFF
        ↓
② オシロ・ロガー・RAMScopeの必要データを退避
        ↓
③ DUT低圧電源をOFF
        ↓
④ RAMScopeが計測中ならRAMScope_Log_Stop.vi
        ↓
⑤ RAMScope_Release.vi（採用する場合）
        ↓
⑥ RAMScope_Close.vi（DeviceExit）
        ↓
⑦ IGS電源OFF、VISA/XNET/CAN等のセッションClose
```

RAMScope終了処理はDUT低圧停止後に行う。ただし、異常データを残す必要がある場合は、DUT停止前に最後の`RAMScope_Read.vi`または保存処理を試みる。

実機の電気的条件やプローブ仕様により安全手順が異なる場合は、設備責任者とベンダー仕様を優先する。

## 12.5 TestStand Cleanupの作成手順

### 0. 目的

Mainの中断位置に関係なく、安全順序で停止・保存・Closeを実行する。

### 1. 必要な状態変数

| 変数 | 型 | Trueの意味 |
|---|---|---|
| `FileGlobals.DLM.IsMeasuring` | Boolean | オシロ計測中 |
| `FileGlobals.MX100.IsLogging` | Boolean | 温度ロギング中 |
| `FileGlobals.RAMScope.IsMeasuring` | Boolean | RAMScope計測中 |
| `FileGlobals.RAMScope.IsConnected` | Boolean | DeviceInit後、DeviceExit前 |
| `FileGlobals.HV.OutputOn[]` | Boolean配列 | 各高圧機の出力ON |
| `FileGlobals.LV.OutputOn` | Boolean | DUT低圧出力ON |

### 2. 配置するステップ

```text
Cleanup
  1. RZX_Output_Off.vi（高圧模擬・負荷、使用台数分）
  2. If DLM.IsMeasuring:
       DLM5058_Acquire_Stop.vi
       DLM5058_Save_Waveform.vi（ERROR名）
  3. If MX100.IsLogging:
       MX100_Log_Stop.vi
       MX100_Save.vi（ERROR名）
  4. If RAMScope data remains:
       RAMScope_Read.vi / 保存処理（可能な場合）
  5. PPX_Output_Off.vi（DUT低圧）
  6. If RAMScope.IsMeasuring:
       RAMScope_Log_Stop.vi
  7. RAMScope_Release.vi（採用している場合）
  8. If RAMScope.IsConnected:
       RAMScope_Close.vi
  9. PPX_Output_Off.vi（IGS）
 10. VISA / XNET / CAN / その他セッションClose
```

### 3. 接続・設定順

1. Cleanupの先頭に使用台数分の高圧Output Offステップを配置する。
2. 1台のOutput Offが失敗しても、残り台数のOutput Offを続行するエラー動作へ設定する。
3. DLM計測中判定のIf条件へ`FileGlobals.DLM.IsMeasuring`を設定する。
4. Stop後に異常波形保存を配置し、保存先へ異常用ファイル名を入力する。
5. MX100も同様にStopとSaveを配置する。
6. RAMScopeに未読データがある場合だけ、最後のReadを試みる。Read失敗でCleanupを中断しない。
7. DUT低圧Output Offを配置する。
8. RAMScope.IsMeasuring=Trueの場合だけLog Stopを呼ぶ。
9. Release採用時だけReleaseを配置する。
10. RAMScope.IsConnected=Trueの場合にCloseを呼ぶ。
11. Close成功後にIsConnected=Falseへ変更する。
12. IGSと通信セッションのCloseを最後に配置する。
13. 各Cleanupステップの結果を個別のCleanup Resultへ保存する。
14. Cleanup全体終了後、元エラーとCleanup Resultをレポートへ保存する。

## 12.6 Cleanup VIのエラー処理

### 12.6.1 通常VIとの違い

通常VI：

```text
error in.status=True
  → 実処理をスキップ
  → 元エラーをerror outへ返す
```

Cleanup VI：

```text
元のerror in ─────────────────────────────┐
                                           ├→ エラーをマージ（Merge Errors）
正常error cluster → Close処理 → Close error┘
```

### 12.6.2 `RAMScope_Close.vi`の配線ルール

1. 元の`error in`を分岐して保持する。
2. DeviceExitラッパへ正常なerror clusterを接続する。
3. 元の`error in`をDeviceExitの実行ガードには使用しない。
4. DeviceExit errorと元エラーをエラーをマージ（Merge Errors）へ接続する。
5. 元エラーを優先する入力順とする。
6. 元エラーが正常でDeviceExitだけ失敗した場合はDeviceExitエラーを返す。
7. 統合結果を`Error_To_TestStatus.vi`へ接続する。

### 12.6.3 共通ルール

- 元エラーを優先して保持する。
- Cleanupエラーを別の結果へ記録する。
- 1つのCleanupステップの失敗で残りを打ち切らない。
- 同じCloseを複数回実行して安全か、各機器で確認する。

## 12.7 状態フラグの更新

| フラグ | Trueにするタイミング | Falseにするタイミング |
|---|---|---|
| `DLM.IsMeasuring` | Acquire Start成功後 | Stop成功後 |
| `MX100.IsLogging` | Log Start成功後 | Stop成功後 |
| `RAMScope.IsMeasuring` | `RAMScope_Log_Start.vi`成功後 | `RAMScope_Log_Stop.vi`成功後 |
| `RAMScope.IsConnected` | `RAMScope_Connect.vi`成功後 | `RAMScope_Close.vi`成功後 |
| `HV.OutputOn[n]` | 各Output On成功後 | 各Output Off成功後 |
| `LV.OutputOn` | DUT低圧Output On成功後 | Output Off成功後 |

フラグはAPI成功後だけ変更する。API呼び出し前に先行して変更しない。

フラグが誤っている場合にも備え、CloseやOutput Offを再実行した際の機器動作を実機で確認する。

---

## 12.8 異常データの命名

```text
<試験ID>_<条件>_<日時>_ERROR_<機器>.<拡張子>
```

例：

```text
T2026-0001_HV400V_20260714_141530_ERROR_DLM5058.csv
T2026-0001_HV400V_20260714_141530_ERROR_RAMScope.bin
```

保存時に次を記録する。

- 試験条件
- 異常発生時刻
- 発生SequenceとStep名
- 元の`TestError.ctl`
- 標準error cluster
- RAMScope API ReturnCode
- LostDataNum
- 取得データが途中であること
- Cleanup各ステップの結果

## 12.9 異常系テスト

### 12.9.1 テスト記録形式

| 項目 | 記録内容 |
|---|---|
| 故障注入 | 何を、いつ、どう切断・異常化したか |
| 事前状態 | 各Output、計測、接続フラグ |
| 期待順序 | どのCleanupが何番目に動くか |
| 実測順序 | Step Result、Timestamp |
| 最終状態 | 電源OFF、計測停止、接続解放 |
| エラー | 元エラー、Cleanupエラー |

### 12.9.2 最低限の故障注入

1. Ethernet通信切断
2. USB切断
3. RAMScope未接続でDeviceInit
4. RAMScope計測中のReadエラー
5. 設定範囲外入力
6. 通信Timeout
7. バッファ取りこぼし
8. Cleanup中のStop失敗
9. Cleanup中のClose失敗
10. 高圧機1台のOutput Off失敗

### 12.9.3 期待結果

| 故障 | 期待結果 |
|---|---|
| Main途中エラー | Main後続を中断しCleanup開始 |
| 高圧1台OFF失敗 | 他の高圧機OFFを続行 |
| RAMScope Read失敗 | DUT低圧停止後にStop/Closeを試行 |
| Stop失敗 | Release候補とCloseを続行 |
| Close失敗 | IGS、VISA、CAN Closeを続行 |
| Cleanup別エラー | 元エラーを保持し、別結果へ記録 |

### 12.9.4 合格条件

- [ ] 高圧が最初にOFFになる
- [ ] 異常データがERROR名で保存される
- [ ] DUT低圧停止後にRAMScope終了処理が行われる
- [ ] `RAMScope_Close.vi`が前段エラーに関係なく実行される
- [ ] Cleanupの途中エラーでも後続停止が続行される
- [ ] 元エラーとCleanupエラーの両方を追跡できる
- [ ] 次回試験開始時に機器状態が残らない
- [ ] 各テストの入力方法、期待順序、最終状態が資料から再現できる
