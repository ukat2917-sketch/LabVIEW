# 11. 異常系処理とシャットダウン設計

異常（エラー）発生時は、**安全を最優先**にした順序で機器を停止し、
解析に必要なデータを退避する。順序を誤ると事故・解析不能につながるため、特に重要。

## 11.1 各装置の異常系処理（要件）

| 装置 | 異常時の処理 | 理由 |
|------|--------------|------|
| **高圧電源・模擬負荷装置** | **一番はじめに落とす** | 大きな事故につながる可能性があるため |
| **オシロ・ロガー** | 計測中なら **計測停止 → データ保存（エラーと分かる名前を付ける）** | 異常動作時の信号を解析用に残したい |
| **低圧電源（12V系）** | **高圧停止後に停止** | マイコンが死んで高圧がかかった状態だと制御不能になるため、最後まで残す |
| **RAMScope** | **一番最後にリセット**。DUT の電源を落としてから RAMScope を落とす | （要件どおり） |

## 11.2 シャットダウン順序（統合）

要件を統合した安全シャットダウン順序は以下のとおり。**この順序を Cleanup に実装する。**

```
① 高圧電源・高圧負荷を OFF          ← 最優先（事故防止）
        ↓
② オシロ・ロガーが計測中なら停止し、
   データを「エラーと分かる名前」で保存   ← 解析用データ退避
        ↓
③ 低圧電源（12V＝DUT電源）を OFF      ← 高圧停止後に停止
        ↓
④ RAMScope をリセット（落とす）        ← 一番最後（DUT電源OFF後）
        ↓
⑤ IGS 電源 OFF / 各種クローズ          ← セッション解放・後始末
```

> ポイント
> - ①高圧を最初に切る（人身・機材事故の回避）。
> - ②③の間にデータ退避を挟む（低圧＝DUT を切る前後で、異常時信号を確実に保存）。
> - ④RAMScope は **DUT 電源 OFF の後**にリセット（要件：DUT 電源を落としてから RAMScope を落とす）。

## 11.3 TestStand での実装（Cleanup ステップグループ）

Cleanup は **正常終了でも異常終了でも必ず実行される** ため、ここに上記順序を配置する。

```
Cleanup（必ず実行）
 ① RZX_Output_Off.vi   （高圧模擬・高圧負荷：使用台数分）
 ② If 計測中:
       DLM5058_Acquire_Stop.vi
       DLM5058_Save_Waveform.vi  （ファイル名に "ERROR" と試験ID・日時）
       MX100_Log_Stop.vi / MX100_Save.vi （同上）
 ③ PPX_Output_Off.vi   （低圧 12V = DUT電源）
 ④ RAMScope_Reset.vi   （最後にリセット）
 ⑤ PPX_Output_Off.vi(IGS) / VISA・XNET・各セッション Close
```

### 実装の要点
- 各 Cleanup ステップは **前段がエラーでも実行を止めない** ように設定する
  （ステップの `Ignore run-time errors` / Cleanup は既定で継続実行）。
- 「計測中かどうか」は FileGlobals 等の **計測状態フラグ** で判定する
  （計測開始 VI でフラグを立て、停止 VI で倒す）。
- 異常で中断した場合、Main から Cleanup へジャンプさせる（[10](./10_TestStandシーケンス構築手順.md) 10.9）。

## 11.4 エラーと分かるデータ保存（命名規則）

異常時に保存するオシロ波形・ロガーデータは、**正常データと区別できる名前**にする。

```
<試験ID>_<試験条件>_<日時>_ERROR_<機器>.<拡張子>
例) T2026-0001_HV400V_20260629_141530_ERROR_DLM5058.csv
```

- `ERROR` を含めることで、後から「異常時に取得したデータ」を一目で識別できる。
- 保存先フォルダも `／異常データ` 等に分けるとさらに分かりやすい。

## 11.5 エラー情報のトレース

- 各 VI は `TestError.ctl`（機器名・コード・メッセージ・時刻・致命度）を出力する（[04](./04_VI設計方針と共通仕様.md)）。
- TestStand は受け取ったエラー情報を **レポート／ログに記録**し、
  「どの機器で何が起きたか」をトレースできるようにする。
- 致命度（Fatal/Recoverable）に応じて、即中断するか・記録のみで継続するかを TestStand で分岐する。

## 11.6 異常系のテスト（検証）

シャットダウン順序は実際に検証する。
1. 各機器で意図的にエラーを発生させる（通信切断・範囲外設定・タイムアウト）。
2. Cleanup が **①→⑤の順** で実行されることを確認。
3. オシロ／ロガーのデータが `ERROR` 名で保存されることを確認。
4. RAMScope が **DUT 電源 OFF 後** にリセットされることを確認。
5. 高圧が最初に確実に OFF になることを確認（安全上、最重要）。
