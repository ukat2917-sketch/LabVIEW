# 05. VI 設計方針と共通仕様

> VI、コネクタペイン、typedef、error clusterが不明な場合は、先に[04](./04_VIの仕組み_LabVIEW基礎.md)を読む。
> RAMScope固有の詳細手順は[10](./10_RAMScope実装方針.md)だけを参照する。

## 5.1 1イベント1VI

試験フロー上の1つの操作を1つの公開API VIへ分離する。

| イベント | VI名例 |
|---|---|
| RAMScope接続 | `RAMScope_Connect.vi` |
| RAMScope初期化 | `RAMScope_Init.vi` |
| RAMScope測定条件設定 | `RAMScope_Set_Cond.vi` |
| RAMScope計測開始 | `RAMScope_Log_Start.vi` |
| RAMScopeデータ取得・解析 | `RAMScope_Read.vi` |
| RAMScope計測停止 | `RAMScope_Log_Stop.vi` |
| RAMScopeバッファ解放候補 | `RAMScope_Release.vi` |
| RAMScope終了 | `RAMScope_Close.vi` |
| オシロ計測開始 | `DLM5058_Acquire_Start.vi` |
| オシロ波形保存 | `DLM5058_Save_Waveform.vi` |
| 温度ロガー計測開始 | `MX100_Log_Start.vi` |
| 高圧電源設定 | `RZX_Voltage_Set.vi` |
| CANモード送信 | `CAN_Send_Mode.vi` |

命名規則：

```text
<機器または対象>_<動作>.vi
```

RAMScopeでは次を公開APIにしない。

- `RAMScope_Config.vi`：PGT設定は`RAMScope_Init.vi`へ統合する。
- 公開用`RAMScope_Parse_Buffer.vi`：Parserは内部データ変換VIとし、`RAMScope_Read.vi`から呼ぶ。

## 5.2 VIへ持たせる共通端子

### 公開API入力

| 端子 | 型 | 用途 |
|---|---|---|
| `error in` | 標準error cluster | 前段エラーの受け取り |
| 試験条件 | 数値、Enum、配列、Cluster | TestStandから渡す条件 |
| 機器リファレンスin | VISA / Session | リファレンス型APIの機器だけ |

### 公開API出力

| 端子 | 型 | 用途 |
|---|---|---|
| `error out` | 標準error cluster | 後段とTestStandへの伝播 |
| `実行結果ステータス` | `Status.ctl` | OK / Warning / Error / Timeout |
| `エラー情報` | `TestError.ctl` | 機器名、コード、メッセージ、時刻、致命度 |
| 計測値 | 数値、配列、Cluster | ログ・判定用 |
| 機器リファレンスout | VISA / Session | リファレンス型APIの機器だけ |

### RAMScope DLLラッパ

`RS_DLL_*`は下位VIなので`Status.ctl`と`TestError.ctl`を持たせない。

```text
入力 : API引数、error in
出力 : API固有値、API ReturnCode、error out
```

### RAMScopeの例外

RAMScopeVP APIはセッションハンドルを返さないため、VISAリファレンスin/outを持たせない。

必要に応じて個別に渡す値：

- `UnitNo`
- `MdlNo_RAM`
- `MdlNo_CAN`
- `Endian_RAM`
- `RAMScope_Channel.ctl`配列
- 標準error cluster

`RAMScope_Context.ctl`はPoC完了まで作成しない。

## 5.3 待ち時間とフロー制御

- VI内部へ試験都合の`Wait(ms)`を入れない。
- 待ち、繰り返し、条件分岐、リトライはTestStandで管理する。
- `RAMScope_Read.vi`のポーリング周期はTestStand側で管理する。
- 負荷ランプのように機能自体が時間変化を持つ場合だけVI内部に時間制御を持たせる。

## 5.4 `Status.ctl`

| 値 | 意味 | TestStandの扱い |
|---|---|---|
| `OK` | 正常完了 | 次ステップへ進む |
| `Warning` | 継続可能な注意 | 記録して継続 |
| `Error` | 異常 | Mainを中断しCleanupへ |
| `Timeout` | 応答タイムアウト | 原則Error扱い |

## 5.5 `TestError.ctl`

| 項目 | 推奨型 | 説明 |
|---|---|---|
| `機器名` | String | `RAMScope`、`DLM5058`等 |
| `エラーコード` | U32 | RAMScopeの32bitコードをビット列どおり保持 |
| `エラーメッセージ` | String | 人が読める説明 |
| `発生時刻` | Timestamp | エラー発生時刻 |
| `致命度` | EnumまたはBoolean | Cleanup、中断、継続の判断 |

## 5.6 標準error clusterの伝播

通常VI：

```text
error in
  → Case Structure
      True : 実処理をスキップし元エラーを出力
      False: 機器操作を実行
  → error out
```

- 前段エラーを消さない。
- 機器固有エラーを標準error clusterへ変換する。
- 公開API末尾で`Error_To_TestStatus.vi`を呼ぶ。
- Cleanup VIは前段エラーがあっても終了処理を試み、元エラーとCleanupエラーを統合する。

## 5.7 RAMScopeの2系統エラー

| 経路 | 内容 |
|---|---|
| CLFN `error out` | DLL未検出、関数未検出、呼び出し設定等 |
| API ReturnCode | デバイス未接続、状態不正、引数不正等 |

```text
DLLラッパ内
  CLFN error out + API ReturnCode
    → RAMScope_Code_To_Error.vi
    → error out

公開API末尾
  error out
    → Error_To_TestStatus.vi
    → Status / TestError / error out
```

## 5.8 接続と終了

### VISA機器

```text
Setup  : Openしてリファレンスを保持
Main   : 各VIへリファレンスを渡す
Cleanup: Close
```

### RAMScope

```text
Setup  : Connect → Init → Set_Cond
Main   : Log_Start → Read → Log_Stop → Release候補
Cleanup: Close
```

`RAMScope_Close.vi`は前段エラーがあってもDeviceExitを試みる。
