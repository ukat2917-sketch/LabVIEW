# 02. 役割分担とアーキテクチャ

> **本章の役割**：LabVIEWとTestStandの責務境界を定義する。
> 各VIの具体的な作成方法は [05](./05_VI設計方針と共通仕様.md) / [06](./06_VIの作り方_手順.md)、RAMScopeは [10A](./10A_RAMScope実装手順_DLL準備とCLFN疎通確認.md) / [10B](./10B_RAMScope_VI作成手順_STEP3_STEP4詳細.md) を参照する。

## 2.1 LabVIEWとTestStandの役割

| 項目 | LabVIEW | TestStand |
|------|---------|-----------|
| 担当 | 1つの機器に対する最小操作 | 試験全体の順序・条件・時間・結果管理 |
| 粒度 | 1イベント1VI | VI呼び出しを組み合わせたシーケンス |
| 条件 | 入力として受け取る | FileGlobals / Parameters / Property Loaderで管理 |
| 待ち | 原則入れない | Waitステップで管理 |
| 分岐・繰り返し | 機器処理に必要な最小範囲 | 試験条件に応じて管理 |
| エラー | 標準error clusterと機器固有コードを出力 | 中断、継続、Cleanup、レポートを判断 |
| Cleanup | 個別の停止・終了VIを提供 | 安全順序で必ず実行 |

### 基本原則

- **何をするか**はLabVIEW VIへ実装する。
- **いつ、どの順番で、何回、どの条件で行うか**はTestStandへ実装する。
- VIは呼ばれたら処理を完了して返す。試験都合の待ち時間やシナリオ分岐を内部へ埋め込まない。
- 例外は、負荷電流ランプのように処理自体が時間変化を持つ機能とする。

## 2.2 1イベント1VI

```text
RAMScope_Connect.vi       : DeviceInit
RAMScope_Init.vi          : AllInit + GetSysInfo
RAMScope_Config.vi        : PGT_SetMdlConfig
RAMScope_Set_Cond.vi      : 測定条件、チャンネル、ログ条件
RAMScope_Log_Start.vi     : 計測開始
RAMScope_Read.vi          : 生データ取得
RAMScope_Parse_Buffer.vi  : 生データ解析
RAMScope_Log_Stop.vi      : 計測停止
RAMScope_Release.vi       : バッファ解放候補
RAMScope_Close.vi         : DeviceExit
```

この粒度にすることで、TestStand側で順番変更、リトライ、条件分岐、別試験への流用ができる。

## 2.3 同期・非同期

自動試験には、順序を守る操作と同時実行したい操作が混在する。

| 種類 | 例 | 実装 |
|------|----|------|
| 同期 | 電源ON → DUT起動 → RAMScope設定 → 計測開始 | TestStandで直列実行 |
| 非同期 | 負荷電流ランプ中にCANモードを送信 | 別ThreadのSequence Call |
| ポーリング | RAMScopeの表示用バッファ読み出し | TestStandループから`RAMScope_Read.vi`を反復呼び出し |

RAMScopeVP APIがスレッドセーフであることは未確認のため、同一デバイスへのDLL呼び出しを複数スレッドから同時実行しない。

## 2.4 接続状態の持ち方

### VISA機器

VISA機器はSetupでセッションをOpenし、リファレンスをFileGlobals等へ保持する。

```text
Setup  : VISA Open
Main   : リファレンスを各操作VIへ渡す
Cleanup: VISA Close
```

### RAMScope

RAMScopeVP APIは`DeviceInit`でLabVIEWへセッションハンドルを返さず、DLL内部のグローバル状態で接続を管理する。

```text
Setup
  RAMScope_Connect.vi
  RAMScope_Init.vi
  RAMScope_Config.vi
  RAMScope_Set_Cond.vi

Main
  RAMScope_Log_Start.vi
  RAMScope_Read.vi / RAMScope_Parse_Buffer.vi
  RAMScope_Log_Stop.vi
  RAMScope_Release.vi（要否検証中）

Cleanup
  RAMScope_Close.vi
```

したがってRAMScope VIには、VISAリファレンスのin/out端子を追加しない。VI間で引き回すのは、`MdlNo_RAM`、`MdlNo_CAN`、`Endian`、チャンネル数などの取得済み情報と標準error clusterである。

## 2.5 エラー経路

RAMScopeでは、次の2種類を分けて扱う。

```text
CLFN error out
  └─ DLL未検出、関数未検出、引数設定などLabVIEW呼び出し層のエラー

API ReturnCode
  └─ デバイス未接続、状態不正、パラメータ不正などRAMScope APIの結果
```

API ReturnCodeは`RAMScope_Code_To_Error.vi`で標準error clusterへ変換し、さらに`Error_To_TestStatus.vi`で`Status.ctl`と`TestError.ctl`へ変換する。

## 2.6 全体アーキテクチャ

```text
┌──────────────────────── TestStand ────────────────────────┐
│ Setup   : 接続・初期化・設定                              │
│ Main    : 試験イベント、待ち、分岐、ループ、並列処理       │
│ Cleanup : 高圧停止、データ退避、DUT停止、機器終了          │
│ Variables: 条件、機器状態、取得値、ファイルパス、結果      │
└────────────────────────────┬───────────────────────────────┘
                             │ LabVIEW Adapter
┌────────────────────────────▼───────────────────────────────┐
│ LabVIEW VI群                                                │
│ 1イベント1VI / 共通error in-out / Status / TestError       │
│ VISA機器はリファレンスを受け渡し                            │
│ RAMScopeはDLL内部状態を利用し、モジュール番号等だけを受け渡す │
└─────────────────────────────────────────────────────────────┘
```

## 2.7 再利用性のルール

- 試験条件はTestStand変数として管理し、VIへハードコードしない。
- 機器固有の変換やCLFN設定はLabVIEW VIへ閉じ込める。
- 同じ機器VIを複数プロジェクトで利用する場合は、コピーを増やさず実体を1か所に置いて参照する。
- 未確認事項は「確定」と書かず、PoC結果またはベンダー一次資料で更新する。
