# 12. 構築ロードマップ（推奨の進め方）

いきなり全体を作らず、**段階的に**構築・検証することで手戻りを減らす。

## 12.1 フェーズ分割

### フェーズ0：方式決定（実装前に確定すべき項目）
- [ ] **CAN 方式**：NI-XNET / Contec USB-CAN のどちらか（[08](./08_CAN通信の実装.md)）。
- [ ] **RAMScope 方式**：API(DLL) 直叩き / マックシステムズ製ドライバ（[09](./09_RAMScope実装方針.md)）。
      - マックシステムズ製の費用・CAN 操作対応可否の確認。
      - API(DLL) の関数仕様入手可否・PoC。
- [ ] LabVIEW / TestStand / 各ドライバの **バージョン・ビット数** 確定。

### フェーズ1：環境構築・通信確認
- [ ] LabVIEW / TestStand / NI-VISA / NI-XNET インストール。
- [ ] 全機器に固定 IP 設定、`ping` 疎通。
- [ ] NI MAX で各機器の `*IDN?` 応答確認（[03](./03_LabVIEW環境構築.md)）。
- [ ] CAN・RAMScope の最小通信 PoC。

### フェーズ2：共通基盤の作成
- [ ] 型定義 `Status.ctl` / `TestError.ctl` 作成（[04](./04_VI設計方針と共通仕様.md)）。
- [ ] VI テンプレート（ひな形）作成（[05](./05_VIの作り方_手順.md)）。
- [ ] 共通ログ／ファイル保存 VI 作成。
- [ ] プロジェクト構成（フォルダ／ライブラリ）整備。

### フェーズ3：機器ごとの VI 作成・単体検証
機器単位で「1イベント1VI」を作り、単体で動作確認（[06](./06_機器別VI構築手順.md)）。
- [ ] 低圧 PPX36-3（Init/電圧設定/出力ON/OFF/モニタ）
- [ ] 高圧 RZ-X（複数台対応・電圧/電流制限/出力/モニタ）
- [ ] 負荷 RZ-X（電流設定／ランプ：割り込み可能設計、[07](./07_負荷電流VIと並列処理.md)）
- [ ] オシロ DLM5058（設定/開始/停止/保存）
- [ ] ロガー MX100（開始/停止/保存）
- [ ] CAN（Open/モード送信/受信/Close、[08](./08_CAN通信の実装.md)）
- [ ] RAMScope（Init/開始/読出/停止/リセット、[09](./09_RAMScope実装方針.md)）

### フェーズ4：TestStand シーケンス構築
- [ ] LabVIEW Adapter 設定。
- [ ] 試験条件の変数化（FileGlobals / Property Loader、[10](./10_TestStandシーケンス構築手順.md)）。
- [ ] イベント単位のサブシーケンス作成。
- [ ] MainSequence で `Sequence Call` により手順を構成。
- [ ] 同期／非同期・待ち・条件分岐の設定。
- [ ] **Cleanup に安全シャットダウンを実装**（[11](./11_異常系処理とシャットダウン設計.md)）。

### フェーズ5：結合試験・異常系検証
- [ ] 1 試験条件で End-to-End 実行。
- [ ] 非同期（負荷ランプ中の割り込み）動作確認。
- [ ] 異常系：シャットダウン順序・ERROR 名データ保存・トレース確認。
- [ ] レポート出力確認。

### フェーズ6：再利用性の確認・横展開
- [ ] 試験条件（電圧/電流/モード/Ramp/台数）を変えて再実行 → シーケンス改変なしで通るか。
- [ ] サブシーケンスの並び替えで別シナリオを構成できるか。
- [ ] 別試験への流用テスト。

## 12.2 マイルストーン例

| マイルストーン | 完了条件 |
|----------------|----------|
| M1 通信確立 | 全機器が NI MAX / PoC で応答 |
| M2 単体VI完成 | 各機器 VI が単体で動作 |
| M3 シーケンス試作 | 1条件で自動試験が通る |
| M4 異常系対応 | 安全シャットダウン・データ退避が機能 |
| M5 再利用性確認 | 条件変更・並び替えで複数試験を実行 |
