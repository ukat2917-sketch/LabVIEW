# 06. VI の作り方（共通手順）

> **本章の役割**：機器を問わず使用する型定義、共通エラー変換、VI雛形の作り方を説明する。
> RAMScope固有のCLFNと構造体は [10B](./10B_RAMScope_VI作成手順_STEP3_STEP4詳細.md) を参照する。

## 6.1 最初に作る共通部品

プロジェクトの`00_Common`へ次を作成する。

```text
00_Common\
├─ Status.ctl
├─ TestError.ctl
└─ Error_To_TestStatus.vi
```

RAMScope用として`30_RAMScope`へ次を追加する。

```text
30_RAMScope\
└─ RAMScope_Code_To_Error.vi
```

## 6.2 `Status.ctl`

### 作成手順

1. `ファイル → 新規 → 他のファイル → タイプ定義`を選ぶ。
2. Enumを配置する。
3. 項目を次の順で登録する。

```text
OK
Warning
Error
Timeout
```

4. `Status.ctl`として`00_Common`へ保存する。

## 6.3 `TestError.ctl`

Cluster型のタイプ定義として作成する。

| 要素 | 型 | 備考 |
|------|----|------|
| `機器名` | String | `RAMScope`、`DLM5058`等 |
| `コード` | **U32** | RAMScopeの16進コードを保持できる |
| `メッセージ` | String | 人が読める説明 |
| `時刻` | Timestamp | エラー発生時刻 |
| `致命的` | BooleanまたはEnum | Cleanup・中断判定に使用 |

### 注意

- Cluster枠の内側へ全要素を配置する。
- `TestError.ctl`として`00_Common`へ保存する。
- 標準error clusterの`code`はI32である。`TestError.ctl`のU32へ渡すときは、必要に応じて`Type Cast`でビット列を保持する。

## 6.4 `Error_To_TestStatus.vi`

標準error clusterから、本システム共通の`Status.ctl`と`TestError.ctl`を生成する。

### 入出力

| 端子 | 方向 | 型 |
|------|------|----|
| `error in` | 入力 | 標準error cluster |
| `機器名` | 入力 | String |
| `実行結果ステータス` | 出力 | `Status.ctl` |
| `エラー情報` | 出力 | `TestError.ctl` |
| `error out` | 出力 | 標準error cluster |

### 内部処理

1. `Unbundle By Name`で`status`、`code`、`source`を取り出す。
2. `status`でCase Structureを分岐する。
3. `False`ケース：
   - Status = `OK`
   - コード = `0`
   - メッセージ = 空文字
   - 致命的 = `False`
4. `True`ケース：
   - Status = `Error`
   - コード = error clusterのcodeをU32へType Cast
   - メッセージ = source
   - 致命的 = `True`
5. 両ケースで機器名と現在時刻をBundleする。
6. `error in`を変更せず`error out`へ渡す。

### 役割

```text
標準error cluster
  → Error_To_TestStatus.vi
      ├─ Status.ctl
      ├─ TestError.ctl
      └─ error out
```

## 6.5 `RAMScope_Code_To_Error.vi`

RAMScope APIは標準error clusterではなく、関数戻り値として結果コードを返す。そのため、直接`Error_To_TestStatus.vi`へ渡さず、先に標準error clusterへ変換する。

```text
CLFN ReturnCode
  → RAMScope_Code_To_Error.vi
  → Error_To_TestStatus.vi
```

具体的な作成手順は [10B 10B.3](./10B_RAMScope_VI作成手順_STEP3_STEP4詳細.md) を正とする。

## 6.6 一般的な操作VIの雛形

### 共通端子

| 方向 | 端子 |
|------|------|
| 入力 | 試験条件、`error in`、必要な場合のみ機器リファレンスin |
| 出力 | 計測値、`実行結果ステータス`、`エラー情報`、`error out`、必要な場合のみリファレンスout |

### ブロックダイアグラム

```text
error in
  → Case Structure
      ├─ Errorケース
      │    └─ 実処理を行わず元エラーを伝播
      └─ No Errorケース
           └─ 機器操作
                → Error_To_TestStatus.vi
```

### SCPI / 計装ドライバVI

1. `error in`でCase Structureをガードする。
2. VISA Write / Readまたはメーカー提供VIを配置する。
3. 設定値はフロントパネル入力から受け取る。
4. 固定値はブロックダイアグラムの定数にする。
5. ドライバのerror outを`Error_To_TestStatus.vi`へ接続する。
6. VISAリファレンスin/outを直列で渡す。

### RAMScope VI

1. CLFNの`error in / error out`を配線する。
2. CLFNのAPI ReturnCodeを`RAMScope_Code_To_Error.vi`へ接続する。
3. 変換後のerror clusterを`Error_To_TestStatus.vi`へ接続する。
4. RAMScopeにはVISAリファレンス端子を追加しない。
5. 複数CLFNを持つVIでは、APIごとに`RAMScope_Code_To_Error.vi`を挟み、最後に`Error_To_TestStatus.vi`を1回だけ呼ぶ。

## 6.7 フロントパネルとコネクタペイン

### 公開する端子

- TestStandから変更する試験条件
- 後段VIへ渡す値
- `error in / error out`
- `実行結果ステータス`
- `エラー情報`
- 必要な機器リファレンス

### 公開しないもの

- 常に固定する単位、モード、UnitNo等
- 内部デバッグだけに使用する値
- 使用しないドライバVI出力

### 推奨配置

```text
左上 : 機器リファレンスまたは主要入力
左下 : error in
右上 : 機器リファレンスまたは主要出力
右下 : error out
```

RAMScopeはリファレンスがないため、左上・右上には`MdlNo_RAM`、取得値、Status等を配置する。

## 6.8 Cleanup VIの例外

通常VIは前段エラーがあれば実処理をスキップする。Cleanup VIは逆に、前段エラーがあっても終了処理を試みる。

```text
元の error in ─────────────────────────────┐
                                           ▼
エラーなしクラスタ → Close処理 → Close error
                                           │
元の error in ──────────────→ Merge Errors ┘
```

- 元エラーを失わない。
- Closeで新たに発生したエラーも記録する。
- RAMScopeでは`RAMScope_Close.vi`が該当する。

## 6.9 単体テスト

### 正常系

- 実機が期待どおり動作する。
- Statusが`OK`になる。
- error outが正常である。
- 設定値、取得値、戻り値が仕様どおりである。

### 異常系

- error inへ意図的にエラーを入れ、通常VIが実処理をスキップする。
- 機器を切断し、ErrorとTestErrorが出力される。
- RAMScopeでは実機未接続状態のDeviceInitをエラー注入として利用できる。
- Cleanup VIが前段エラーに関係なく終了処理を試みる。

## 6.10 テンプレート化

次の2種類を分けて作る。

```text
_Template_VISA_Operation.vi
  └─ リファレンスin/outあり

_Template_RAMScope_CLFN.vi
  └─ CLFN + ReturnCode変換 + 共通出力
```

テンプレートから新しいVIを作る場合は、必ず「別名で保存」してから関数・試験条件・機器名を変更する。

## 6.11 作成する主なVI

| 機器 | VI |
|------|----|
| DLM5058 | Init / Config / Acquire_Start / Acquire_Stop / Save_Waveform |
| MX100 | Init / Log_Start / Log_Stop / Save |
| RAMScope | Connect / Init / Config / Set_Cond / Log_Start / Read / Parse_Buffer / Log_Stop / Release / Close |
| RZ-X | Init / Voltage_Set / Current_Limit_Set / Output_On / Output_Off / Read |
| PPX | Init / Voltage_Set / Output_On / Output_Off / Read / Close |
| CAN | Open / Send / Read / Close（採用方式に応じる） |

RAMScopeの各VIは [10B](./10B_RAMScope_VI作成手順_STEP3_STEP4詳細.md) に従って作成する。
