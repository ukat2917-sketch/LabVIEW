# 06. VI の作り方（共通手順）

> **本章の役割**：機器を問わず使用する型定義、共通エラー変換、VI雛形の作り方を説明する。
> RAMScope固有のCLFN、typedef、数値変換、Builder、Parserは[10](./10_RAMScope実装方針.md)を参照する。
>
> LabVIEW関数は**日本語名（英語名）**の順で記載する。版によってパレット階層が異なる場合は、`Ctrl + Space`のQuick Dropへ英語名を入力する。

## 6.1 最初に作る共通部品

```text
00_Common\
├─ Status.ctl
├─ TestError.ctl
└─ Error_To_TestStatus.vi
```

RAMScope固有の共通部品は`30_RAMScope\00_Common`へ作成する。

```text
30_RAMScope\00_Common\
├─ RAMScope_Code_To_Error.vi
├─ RAMScope_Channel.ctl
├─ RAMScope_Meas_Config.ctl
├─ RAMScope_Module_Log_Config.ctl
├─ RAMScope_Module_Info.ctl
├─ RAMScope_Channel_Value.ctl
├─ RAMScope_Packet.ctl
├─ RAMScope_Byte_Order.ctl
└─ 数値⇔U8変換VI
```

## 6.2 `Status.ctl`

本資料では、プロジェクトエクスプローラから直接タイプ定義を作成する。

1. プロジェクトエクスプローラの`00_Common`を右クリックする。
2. `新規 → タイプ定義`を選ぶ。
3. 制御器エディタが開く。初期配置された不要な制御器がある場合は削除する。
4. 制御器パレットから列挙体（Enum）を配置する。
5. 次を登録する。

```text
OK
Warning
Error
Timeout
```

6. `Status.ctl`として`00_Common`へ保存する。
7. 制御器エディタ上部の種類が`タイプ定義（Type Def.）`であることを確認する。

> `新規 → タイプ定義`から作成した場合、後からカスタム制御器を`Type Def.`へ変更する操作は不要である。

## 6.3 `TestError.ctl`

1. `00_Common`を右クリックし、`新規 → タイプ定義`を選ぶ。
2. クラスタ（Cluster）を配置する。
3. 次の制御器をクラスタ内へ入れる。

| 要素 | 型 | 備考 |
|---|---|---|
| `機器名` | String | `RAMScope`、`DLM5058`等 |
| `コード` | U32 | RAMScopeの32bitコードを保持 |
| `メッセージ` | String | 人が読める説明 |
| `時刻` | Timestamp | エラー発生時刻 |
| `致命的` | BooleanまたはEnum | Cleanup・中断判定 |

4. 各要素のラベルと表現形式を確認する。
5. `TestError.ctl`として保存する。

標準error clusterの`code`はI32。U32へ渡す場合は型変換（Type Cast）でビット列を保持する。

## 6.4 `Error_To_TestStatus.vi`

### 入出力

| 端子 | 方向 | 型 |
|---|---|---|
| `error in` | 入力 | error cluster |
| `機器名` | 入力 | String |
| `実行結果ステータス` | 出力 | `Status.ctl` |
| `エラー情報` | 出力 | `TestError.ctl` |
| `error out` | 出力 | error cluster |

### 内部処理

1. 名前でバンドル解除（Unbundle By Name）で`status`、`code`、`source`を取り出す。
2. `status`をケースストラクチャ（Case Structure）へ接続する。
3. Falseケース：Status=`OK`、コード=0、メッセージ空、致命的=False。
4. Trueケース：Status=`Error`、コードをU32へ型変換（Type Cast）、メッセージ=`source`、致命的=True。
5. 両ケースで機器名と現在時刻を名前でバンドル（Bundle By Name）へ接続する。
6. `error in`を変更せず`error out`へ渡す。

## 6.5 `RAMScope_Code_To_Error.vi`

```text
CLFN error out + API ReturnCode
  → RAMScope_Code_To_Error.vi
  → 標準error cluster
```

作成手順は[10](./10_RAMScope実装方針.md)の`10.6`を正とする。

## 6.6 一般的な公開API VIの雛形

### 共通端子

| 方向 | 端子 |
|---|---|
| 入力 | 試験条件、`error in`、必要な場合だけ機器リファレンスin |
| 出力 | 計測値、Status、TestError、`error out`、必要な場合だけリファレンスout |

### ブロックダイアグラム

```text
error in
  → ケースストラクチャ（Case Structure）
      True : 実処理を行わず元エラーを伝播
      False: 機器操作
  → Error_To_TestStatus.vi
```

### SCPI / 計装ドライバVI

1. `error in`でケースストラクチャ（Case Structure）をガードする。
2. VISA Write / VISA Readまたはメーカー提供VIを配置する。
3. 設定値は入力端子から受け取る。
4. 固定値だけを定数にする。
5. ドライバerror outを`Error_To_TestStatus.vi`へ接続する。
6. VISAリファレンスin/outを直列で渡す。

### RAMScope公開API

1. 公開APIから`RS_DLL_*`ラッパまたはData Conversion VIを呼ぶ。
2. DLLラッパ内でReturnCodeは`RAMScope_Code_To_Error.vi`へ接続済みとする。
3. 公開API内のerror clusterを直列にする。
4. 公開API末尾で`Error_To_TestStatus.vi`を1回呼ぶ。
5. RAMScopeにはVISAリファレンス端子を追加しない。

### RAMScope DLLラッパ

1. 1個のCLFNだけを配置する。
2. CLFN ReturnCodeとCLFN error outを`RAMScope_Code_To_Error.vi`へ接続する。
3. `Status.ctl`と`TestError.ctl`を生成しない。
4. Builder、Parser、複数関数の順序制御を入れない。

## 6.7 フロントパネルとコネクタペイン

### 公開する端子

- TestStandから変更する条件
- 後段へ渡す値
- `error in / error out`
- Status
- TestError
- 必要な機器リファレンス

### 公開しないもの

- 固定する単位、モード、内部用定数
- デバッグ専用値
- 使用しないドライバ出力

### 推奨配置

```text
左上 : 主要入力
左下 : error in
右上 : 主要出力
右下 : error out
```

## 6.8 Cleanup VIの例外

通常VIは前段エラーで実処理をスキップする。Cleanup VIは前段エラーがあっても終了処理を試みる。

```text
元のerror in ─────────────────────────────┐
                                           ├→ エラーをマージ（Merge Errors）
エラーなしクラスタ → Close処理 → Close error ┘
```

RAMScopeでは`RAMScope_Close.vi`が該当する。

## 6.9 単体テスト

### 正常系

- 実機が期待どおり動作する。
- Statusが`OK`。
- error outが正常。
- 設定値、取得値、戻り値が仕様どおり。

### 異常系

- error inへ意図的にエラーを入れ、通常VIが処理をスキップする。
- 機器切断でErrorとTestErrorを出力する。
- RAMScope未接続時のDeviceInit結果を記録する。
- Cleanup VIが前段エラーに関係なく終了処理を試みる。

## 6.10 テンプレート化

```text
_Template_VISA_Operation.vi
  └─ VISAリファレンスin/outあり

_Template_RAMScope_DLL_Wrapper.vi
  └─ 1 CLFN + ReturnCode変換

_Template_RAMScope_Public.vi
  └─ 下位VI + Error_To_TestStatus
```

テンプレートは別名保存してから編集する。

## 6.11 作成する主な公開API
