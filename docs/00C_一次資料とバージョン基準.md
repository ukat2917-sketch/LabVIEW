# 00C. 一次資料とバージョン基準

**最終整理日：2026-07-26**

本章は、VI作成手順へ記載する仕様の出典、採用バージョンおよび確認方法を統一する。VI構成の正本ではない。既に決定したVI名、レイヤおよび呼出順は各実装章、RAMScopeは[10](./10_RAMScope実装方針.md)を正とする。

---

## 1. 情報源の優先順位

仕様が競合する場合は、次の順で採用する。

1. 対象PCへ実際に導入したドライバのヘルプ、VIのコネクタペイン、DLL同梱ヘッダ、COM Type Library。
2. 対象バージョンのメーカー公式マニュアル、API仕様書、Readme。
3. NI公式製品マニュアルおよび互換性表。
4. メーカー公式サンプル。
5. 本リポジトリの既決設計。
6. 実機PoCの観測結果。

検索結果の要約、第三者サイト、生成AIの回答だけで端子名、データ型、引数順、制限値または戻り値の意味を確定しない。

## 2. 2026-07-26時点の採用基準

| 項目 | 採用基準 | 実装時の確認 |
|---|---|---|
| LabVIEW | 2026 Q1 64bit | `Help → About LabVIEW`でEdition、Version、bit数を記録 |
| TestStand | 2026 Q1 64bit | Version SelectorとSequence EditorのAboutで確認 |
| LabVIEW Adapter | LabVIEW 2026 Q1 64bitと一致 | `Configure → Adapters → LabVIEW`で実行方式も記録 |
| Run-Time Engine | ビルドに使用したLabVIEWと互換のある同系統 | NI Package Managerと試験PCのインストール一覧で確認 |
| NI-VISA | LabVIEW 2026 Q1と対象OSをサポートする版 | NI Package Manager、NI MAX、NI公式互換性表で確認 |
| 外部DLL | 呼出しプロセスと同じbit数 | DLL、LabVIEW、TestStand、PowerShellを個別に確認 |
| RAMScopeVP API | 64bit版 | 同梱`RAMScopeVP.h`、API仕様書、実DLLのExportを照合 |
| CANalyzer | 64bit版。製品Versionは実機確認待ち | 対象PCのAboutと登録済みType Libraryを記録 |

LabVIEWまたはTestStandを将来更新する場合は、先にNIのUpgrade and Compatibility Issuesを確認し、開発PCだけを先行更新しない。

## 4. ベンダー資料

| 対象 | 正本 | リポジトリ内の確認先 |
|---|---|---|
| RAMScope GT170 | RAMScopeVP API Specification、インストールDLL同梱ヘッダ、ベンダーサンプル | `reference/RAMScopeVP.h`、`reference/GTHard.h`、`reference/samp_simple.cpp` |

Web上のマニュアルとインストール済みドライバでVI名や端子が異なる場合は、対象PCの実物を優先し、差異を章末の「実機確認記録」へ残す。

## 5. VI情報を記載するときの必須証跡

各VIまたはWrapperの説明には、[00A](./00A_LabVIEW実装資料の記述ルール.md)と[00B](./00B_LabVIEW学習型VI設計ルール.md)に加え、次を記録する。

| 項目 | 記載内容 |
|---|---|
| Source | NI公式Help名、ベンダーマニュアル番号、ヘッダ名、Type Library名のいずれか |
| Version | LabVIEW、TestStand、ドライバ、機器FirmwareまたはDLL版 |
| Symbol | VI名、関数名、Property名、Method名またはSCPIコマンド |
| Signature | 端子方向、型、配列次元、ポインタ渡し、引数順 |
| Verified by | Help表示、Ctrl+H、ヘッダ照合、実機PoCのいずれか |
| State | `公式仕様`、`ベンダー仕様`、`既決設計`、`実機確認済み`、`実機確認待ち` |

確認できていない端子やメンバを補完して書かない。実装を止めないための仮値は、仮値であること、確認方法および確定後の修正箇所を同じ節へ記載する。

## 6. VI構成を維持する更新ルール

最新情報への更新は、既決VI構成を変更する理由にならない。次の変更は、別途設計変更として承認されるまで禁止する。

- 既決VIの統合、分割、改名または削除。
- 公開APIから薄いWrapperを直接呼ぶレイヤ飛越し。
- TestStandからDLL Wrapperを直接呼ぶ構成。
- 第10章で固定したctl 11個、Common／Builder／Parser 11個、Wrapper 18個、公開API 11個、TDMS VI 4個、PoC 2個の変更。
- ベンダー提供VIまたはDLL同梱ファイルの改変。

## 7. 更新時チェックリスト

- [ ] 対象製品とVersionを記録した。
- [ ] NIまたはメーカーの一次資料を確認した。
- [ ] VI／関数の実シグネチャを確認した。
- [ ] 推測と確認済み仕様を分離した。
- [ ] 既決VI名、レイヤ、呼出順を変更していない。
- [ ] 正常、境界、異常、既存エラー入力の試験を定義した。
- [ ] 実機が必要な項目を`実機確認待ち`として残した。
