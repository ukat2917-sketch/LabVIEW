# 01. システム概要と構成

## 1.1 目的

NI社製の LabVIEW（+ TestStand）を利用した自動テストシステムを構築する。

## 1.2 背景（現状の課題）

- 現在の試験環境では、複数の操作者が「模擬電源」「供試体マイコンの CAN 操作」「測定機器の操作」を
  分担して手動で実施している。
- 各機器の操作タイミングがシビアな試験条件では、入力タイミングを人手で調整し、
  トライアンドエラーで試験している。
- 試験条件ごとに異なる測定機器の **設定変更忘れ**、**測定開始忘れ** が発生し、
  データ再取得による工数増加が課題となっている。

## 1.3 導入によるメリット

| ソフト | 効果 |
|--------|------|
| LabVIEW | 各機器を単一アプリ上で制御。手動の測定開始・設定ミスを防止。ms オーダーの制御・計測。 |
| TestStand | 試験条件ごとに異なる手順・条件・タイミングをシーケンスとして定義・管理。フローの可視化、条件／結果管理。 |
| 組み合わせ | 人に頼っていた操作を再現性の高い試験へ。試験品質の向上と工数削減。 |

## 1.4 計測・制御対象機器一覧

| 区分 | 役割 | 型式 | 接続 | 備考 |
|------|------|------|------|------|
| 測定 | 電圧・電流計測（オシロスコープ） | **DLM5058**（横河） | Ethernet | 波形取得 |
| 測定 | 温度ロガー | **MX100**（横河） | Ethernet | 多チャンネル温度 |

| 電源 | 高圧模擬電源 | **RZ-X2-100K-H × 3台** | Ethernet | 出力により接続台数変更 |
| 電源 | 高圧負荷電源 | **RZ-X2-100K-H × 3台** | Ethernet | 出力により接続台数変更 |

> **「使用台数」を試験条件（変数）として持つ** 設計にしておく（後述）。

## 1.5 ネットワーク構成

- 上記機器を **Ethernet（LAN）** で PC と接続し、PC 上の LabVIEW / TestStand から制御する。
- 各機器に固定 IP を割り当て、PC と同一サブネットに配置する。
- CAN インタフェースは Ethernet ではなく USB / PCIe など専用ハードウェアで接続する。
- **RAMScope GT170 は例外**：電源通信モジュール `GT170U01` の Ethernet ポートは
  XCP on Ethernet 専用であり、RAMScopeVP API（本システムで使用する制御方式）は
  **USB3.0 接続でのみ利用可能**。そのため RAMScope のみ PC（LabVIEW 稼働機）へ
  USB3.0 直結とし、他機器のような LAN 経由の統一構成からは除外する。

## 1.6 自動化の対象

LabVIEW + TestStand を用いて以下を「設定した時系列どおりに実行・計測」する。

- 電源制御（高圧／低圧／IGS）
- CAN 信号制御（マイコンの動作モード送信など）
- 負荷制御（負荷電流のランプ変化）
- ログ取得（オシロ波形・温度・RAM 値・CAN ログ）

加えて、**試験条件を変更しても再利用できる自動試験シーケンス**を構築する。
