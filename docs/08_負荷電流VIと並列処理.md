# 08. 負荷電流 VI と並列処理（割り込み可能設計）

> **本章の役割**：負荷電流を指定時間で変化させながら、CAN送信や計測処理を並行実行する構成を定義する。
>
> VIの詳細手順は[00A](./00A_LabVIEW実装資料の記述ルール.md)の標準書式に従う。

---

## 8.1 なぜ並列処理が必要か

負荷電流ランプは数秒間継続する。一方、試験ではランプ途中の指定時刻にCANモード遷移、RAMScope読出し、オシロ確認を行う必要がある。

負荷ランプVIの内部へCANや計測処理を埋め込むと、試験ごとにVIを作り直すことになる。そこで、負荷ランプVIは「開始電流から目標電流まで変化させる処理」だけを担当し、並列実行と割り込みタイミングはTestStandで管理する。

---

## 8.2 `Load_Current_Ramp.vi`

### 0. 目的と処理概要

開始電流から目標電流までを、指定したRamp時間と制御周期で線形変化させる。各ステップで負荷電源の電流設定VIを呼び、最後に目標値へ確実に設定する。

### 1. 入出力

| 端子名 | 方向 | 型 | 用途 |
|---|---|---|---|
| `Start Current [A]` | 入力 | DBL | ランプ開始値 |
| `Target Current [A]` | 入力 | DBL | 最終目標値 |
| `Ramp Time [s]` | 入力 | DBL | 開始から目標までの時間 |
| `Control Period [ms]` | 入力 | U32またはI32 | 設定更新周期 |
| `VISA Ref in` | 入力 | VISA Refnum | 負荷電源接続 |
| `error in` | 入力 | error cluster | 前段エラー |
| `Current Output [A]` | 出力 | DBL | 最後に設定した電流値 |
| `VISA Ref out` | 出力 | VISA Refnum | 後段へ渡す接続 |
| `Status` | 出力 | `Status.ctl` | 実行結果 |
| `TestError` | 出力 | `TestError.ctl` | 詳細エラー |
| `error out` | 出力 | error cluster | 処理結果 |

### 2. 配置する関数およびSubVI等

| 数 | 日本語名 | 英語名 | 配置場所・追加方法 |
|---:|---|---|---|
| 1 | 名前でバンドル解除 | Unbundle By Name | プログラミング → クラスタ、クラス、バリアント |
| 2以上 | ケースストラクチャ | Case Structure | プログラミング → ストラクチャ |
| 1 | Forループ | For Loop | プログラミング → ストラクチャ |
| 1 | シフトレジスタ | Shift Register | Forループ枠を右クリック → シフトレジスタを追加 |
| 複数 | 加算、減算、乗算、除算 | Add, Subtract, Multiply, Divide | プログラミング → 数値 |
| 1 | 商と余り | Quotient & Remainder | プログラミング → 数値 |
| 1 | 待機（ミリ秒） | Wait (ms) | プログラミング → タイミング |
| 1 | `RZX_Current_Limit_Set.vi`または対象負荷設定VI | SubVI | 対象機器フォルダ |
| 1 | `Error_To_TestStatus.vi` | SubVI | `00_Common` |

### 3. 配線順

#### A. 外側エラーガード

1. `error in`を名前でバンドル解除（Unbundle By Name）へ接続する。
2. `status`を外側ケースストラクチャ（Case Structure）へ接続する。
3. Trueケースでは、負荷設定処理を実行せず、`Start Current [A]`を`Current Output [A]`へ接続する。
4. Trueケースで`VISA Ref in`を`VISA Ref out`へ、`error in`を後段の`Error_To_TestStatus.vi`へ接続する。
5. Falseケースへ入力値検証を作る。

#### B. 入力値検証

1. `Ramp Time [s] >= 0`を比較する。
2. `Control Period [ms] > 0`を比較する。
3. 2条件を複合演算（Compound Arithmetic）のANDへ接続する。
4. 判定Falseケースでは機器を操作せず、入力不正エラーを作る。
5. 判定TrueケースへRamp時間判定を作る。

#### C. Ramp時間が0の場合

1. `Ramp Time [s] == 0`を判定する。
2. Trueケースでは`Target Current [A]`を負荷設定VIの電流入力へ接続する。
3. 設定成功後、`Target Current [A]`を`Current Output [A]`へ接続する。
4. 負荷設定VIのVISA Refとerror clusterを出力へ渡す。

#### D. Ramp時間が0より大きい場合

1. `Ramp Time [s] × 1000`でRamp時間をミリ秒へ変換する。
2. Ramp時間msを`Control Period [ms]`で除算し、端数を切り上げて`Step Count`を作る。
3. `Step Count`が1未満にならないようにする。
4. Forループの`N`端子へ`Step Count`を接続する。
5. VISA Ref用シフトレジスタを追加し、左外側へ`VISA Ref in`を接続する。
6. Forループ反復端子`i`へI32定数`1`を加え、`Step Number`を作る。
7. `Step Number / Step Count`をDBLで計算し、`Progress`を作る。
8. `Target Current - Start Current`を計算し、`Progress`を乗算する。
9. 乗算結果へ`Start Current`を加え、今回の`Command Current`を作る。
10. `Command Current`を負荷設定VIの設定値入力へ接続する。
11. VISA Refシフトレジスタ左内側を負荷設定VIのVISA Ref入力へ接続する。
12. 前反復のerror clusterを負荷設定VIの`error in`へ接続する。error用シフトレジスタを使用する場合は、左外側へ外側Falseケースの正常error clusterを接続する。
13. 負荷設定VIのVISA Ref出力をVISA Refシフトレジスタ右内側へ接続する。
14. 負荷設定VIのerror outをerror用シフトレジスタ右内側へ接続する。
15. `Control Period [ms]`を待機（ミリ秒）（Wait (ms)）へ接続する。
16. `Command Current`をForループ右枠へ接続する。最終値だけを取得する場合は自動指標付けを無効にするか、Current用シフトレジスタを使用する。
17. Forループ終了後、VISA Ref右外側を`VISA Ref out`へ接続する。
18. 最後のCommand Currentを`Current Output [A]`へ接続する。
19. 最後のerror clusterを`Error_To_TestStatus.vi`へ接続する。
20. `Error_To_TestStatus.vi`のStatus、TestError、error outを本VIの各出力へ接続する。

### 4. 単体テスト

#### 計算だけを確認するテスト

負荷設定VIをダミーVIへ置き換え、受け取った電流値を配列へ記録する。

```text
Start Current     = 0 A
Target Current    = 100 A
Ramp Time         = 5 s
Control Period    = 1000 ms
```

期待値：

```text
Step Count = 5
設定値     = 20, 40, 60, 80, 100 A
最終出力   = 100 A
```

#### 境界・異常テスト

| 条件 | 期待結果 |
|---|---|
| Ramp Time=0 | 1回だけTarget Currentを設定 |
| Control Period=0 | 入力不正エラー、機器操作なし |
| Ramp Time<0 | 入力不正エラー、機器操作なし |
| 既存error in | 機器操作なし、元エラー保持 |
| 途中の設定VIでエラー | 後続反復で元エラーを保持し、最終Status=Error |

## 8.3 並列処理の実現方法

### 方式A：TestStandで非同期実行（推奨）

`Load_Current_Ramp.vi`自体は開始から完了まで同期実行する。TestStand側で別スレッドとして起動する。

```text
Main Thread
  ├─ Sequence Call: Load_Current_Ramp.viをNew Threadで起動
  ├─ Wait 1 s
  ├─ CAN_Send_Mode.vi
  ├─ RAMScope_Read.vi
  └─ Wait for Threadでランプ完了待ち
```

詳細手順では、Sequence Callの実行方法、Thread参照の保存先、完了待ち、Timeout、Cleanup時の停止方法を記載する。

### 方式B：LabVIEW内の常駐並列ループ

次の要件がある場合だけ検討する。

- ms精度で滑らかな更新が必要
- ランプ中の現在値を別VIから取得する必要がある
- 外部からランプを中断する必要がある

候補VI：

```text
Load_Ramp_Start.vi
Load_Ramp_GetCurrent.vi
Load_Ramp_Stop.vi
```

キュー、Notifier、FGV等の参照生成・破棄、常駐ループの生存管理を追加で設計する必要があるため、初期実装では方式Aを採用する。

## 8.4 並列実行の単体・結合テスト

```text
t0      : 0 A → 100 A、5秒ランプを別Threadで開始
t0+1 s  : CANモード送信
t0+3 s  : RAMScope_Read.viまたはオシロ確認
t0+5 s  : ランプThread完了待ち
t0+5 s～: 次の試験イベント
```

確認項目：

- [ ] CAN送信がランプ完了を待たずに実行される
- [ ] ランプ設定値が指定周期で更新される
- [ ] 合流後の最終電流が目標値と一致する
- [ ] Ramp側エラーをMain Threadで検出できる
- [ ] Main側エラーでもCleanupで負荷出力をOFFできる
- [ ] 同一VISAセッションを複数Threadから同時操作していない
