> **本章の役割**：LabVIEWを初めて触る人が、05章以降の「コネクタペイン」「型定義」「配列」「Case Structure」「シフトレジスタ」「エラー伝搬」を理解できるようにする。
>
> 実際のVI作成手順は[00A](./00A_LabVIEW実装資料の記述ルール.md)と[06](./06_VIの作り方_手順.md)に従う。

## 4.1 VIとは何か

**VI（Virtual Instrument）**は、LabVIEWにおける1つのプログラムまたは関数である。拡張子は`.vi`。

- C言語やPythonの関数に相当する。
- 他のVIから部品として呼ばれるVIを**サブVI（SubVI）**と呼ぶ。
- 本資料の「1イベント1VI」は、1つの機器操作を1つの再利用可能なVIへ分けるという意味である。

### VIを構成する3つの画面・要素

| 部分 | 英語名 | 役割 |
|---|---|---|
| フロントパネル | Front Panel | 入力用制御器と出力用表示器を配置する |
| ブロックダイアグラム | Block Diagram | 関数、SubVI、ストラクチャをワイヤで接続する |
| アイコン／コネクタペイン | Icon / Connector Pane | 他VIやTestStandから呼ぶ際の端子を定義する |

LabVIEWは上から下へ実行するのではなく、必要な入力データがそろったノードから実行する。

---

## 4.2 制御器と表示器

| 日本語名 | 英語名 | 方向 | 例 |
|---|---|---|---|
| 制御器 | Control | VIへの入力 | 電圧条件、チャンネル配列、error in |
| 表示器 | Indicator | VIからの出力 | 測定値、Raw配列、error out |

ブロックダイアグラムでは、制御器端子を左側、表示器端子を右側へ置くとデータフローを追いやすい。

### 制御器と表示器の変更

配置済み端子を右クリックし、`制御器に変更`または`表示器に変更`を使用する。資料では「入力」「出力」とだけ書かず、フロントパネルへ置く種類も明記する。

---

## 4.3 コネクタペインとアイコン

VIをSubVIまたはTestStandから呼ぶには、フロントパネルの制御器・表示器をコネクタペインへ割り当てる。

```text
フロントパネルの制御器  → コネクタペイン入力端子
フロントパネルの表示器  → コネクタペイン出力端子
```

### 割り当て手順

1. フロントパネル右上のVIアイコンを右クリックする。
2. `コネクタを表示`を選ぶ。
3. 使用する端子パターンを選ぶ。
4. コネクタペインの端子をクリックする。
5. 割り当てる制御器または表示器をクリックする。
6. すべての公開端子を割り当てる。
7. Context HelpでSubVI端子名が表示されることを確認する。

推奨配置：

```text
左上 : 主要入力
左下 : error in
右上 : 主要出力
右下 : error out
```

---

## 4.4 リファレンス（Reference / Refnum）

リファレンスは、開いている機器接続やセッションを指す識別子である。

```text
Setup でOpen
  → リファレンスを各操作VIへ直列に渡す
  → CleanupでClose
```

VISA機器ではVISAリファレンスを使用する。RAMScopeVP APIはセッションハンドルを返さないため、RAMScope VIへVISAリファレンスを追加しない。

---

## 4.5 データ型

| 型 | 色の目安 | 用途 |
|---|---|---|
| U8 / I32 / U32 / U64 | 青 | バイト、整数、APIコード、アドレス |
| DBL | オレンジ | 電圧、電流、Scale、Offset |
| Boolean | 緑 | ON/OFF、判定結果 |
| String | ピンク | 名前、メッセージ、SCPIコマンド |
| Enum | 青 | 限定された選択肢 |
| Array | 要素型に依存 | 波形、Rawバイト列、チャンネル一覧 |
| Cluster | 茶色・ピンク等 | 複数フィールドを1本のワイヤへまとめる |
| error cluster | 黄黒 | status、code、source |

数値制御器や定数は、右クリックして`表現形式`をI32、U32、U64、DBL等へ合わせる。値が同じでも型が違うと、強制変換ドットや配線エラーが発生する。

---

## 4.6 クラスタと型定義

### クラスタ（Cluster）

関連する複数の値を1本のワイヤへまとめたデータ型である。C言語の`struct`に近い。

例：

```text
RAMScope_Channel.ctl
  Name
  Enable
  Core
  Address
  Size
  Sign
  Speed
  Scale
  Offset
  Unit
```

### 型定義（Type Definition / `.ctl`）

複数のVIで同じクラスタやEnumを使用するため、定義を`.ctl`ファイルとして一元管理する。

本資料での新規作成経路：

```text
プロジェクトエクスプローラ
  → 保存先フォルダを右クリック
  → 新規
  → タイプ定義
```

詳細は[06](./06_VIの作り方_手順.md)と[00A](./00A_LabVIEW実装資料の記述ルール.md)を参照する。

## 4.7 配列

配列は、同じ型の値を複数保持する。

### 単一要素と配列の違い

```text
RAMScope_Channel.ctl       = 1チャンネル分のクラスタ
Channel List              = 上記クラスタの一次元配列
SYSINFO Raw               = U8の一次元配列
```

配列サイズ（Array Size）は配列へだけ接続できる。単一クラスタを接続すると破線になる。

### 配列の作成

1. フロントパネルへ空の配列枠を配置する。
2. 配列枠の内側へ数値制御器またはtypedefを配置する。
3. 配列全体のラベルを設定する。
4. 実要素を追加する場合は、配列内要素を右クリックし、`データ操作 → 要素を挿入`を使用する。

表示セル数と実際の配列要素数は別である。配列サイズ（Array Size）で実要素数を確認する。

## 4.8 error clusterとエラー伝搬

標準error clusterは次の3要素を持つ。

| 要素 | 型 | 意味 |
|---|---|---|
| `status` | Boolean | Trueならエラーあり |
| `code` | I32 | エラーコード |
| `source` | String | 発生場所や説明 |

error clusterをSubVI間で直列接続すると、処理順と最初のエラーを保持できる。

```text
VI-A error out
  → VI-B error in
  → VI-C error in
```

通常VIでは`error in.status=True`の場合に実処理をスキップする。Cleanup VIでは前段エラーがあっても停止・Close処理を試みる。

---

## 4.9 Case Structure

ケースストラクチャ（Case Structure）は、Boolean、Enum、数値、文字列等の条件で処理を切り替える。

通常VIの基本：

```text
error in.status
  → Case Structure
      True  : 安全な初期出力、元エラーを保持
      False : 実処理
```

各ケースの出力トンネルをすべて配線する。`Use default if unwired`へ依存しない。

---

## 4.10 Forループと自動指標付け

Forループ（For Loop）は、指定回数または配列要素数だけ処理を繰り返す。

### 自動指標付けを有効にする場合

配列をForループ枠へ接続し、入力トンネルの`指標付けを有効`にすると、ループ内へ1要素ずつ渡される。

```text
ループ外 : Channel List配列
ループ内 : RAMScope_Channel.ctl単体
```

### 自動指標付けを無効にする場合

配列全体から部分配列（Array Subset）で任意位置を切り出す場合は、入力トンネルを右クリックして`指標付けを無効`にする。

```text
ループ外 : SYSINFO Raw U8[960]
ループ内 : SYSINFO Raw U8[960]全体
```

## 4.11 シフトレジスタ

シフトレジスタ（Shift Register）は、前回反復の値を次の反復へ渡す。

追加方法：

```text
Forループ枠を右クリック
  → シフトレジスタを追加
```

| 端子 | 意味 |
|---|---|
| 左外側 | ループ開始前の初期値 |
| 左内側 | 前回反復までの値 |
| 右内側 | 今回反復後の値 |
| 右外側 | ループ終了後の最終値 |

初期値`-1`を左外側へ接続した場合でも、判定Falseケースでは左内側の現在値を右内側へ渡す。毎回`-1`へ戻さない。

---

## 4.12 データフロー

LabVIEWは、入力データがすべてそろったノードから実行する。

- 上から下への配置順では実行順を決められない。
- 実行順を保証する場合はデータワイヤ、特にerror clusterを直列接続する。
- ワイヤで依存していない処理は並列実行される可能性がある。

## 4.13 用語早見表

| 本資料の表現 | LabVIEW用語 | 意味 |
|---|---|---|
| 入力 | Control | VIへ渡す値 |
| 出力 | Indicator | VIが返す値 |
| 端子割り当て | Connector Pane | SubVIの引数と戻り値 |
| 配列要素数 | Array Size | 実際に保持する要素数 |
| 条件分岐 | Case Structure | 条件で処理を切り替える |
| 反復 | For Loop | 複数要素・複数パケットを処理する |
| 前回値の保持 | Shift Register | 反復間で値を引き継ぐ |
| エラーの受け渡し | error in / error out | 最初の失敗を下流へ伝える |
