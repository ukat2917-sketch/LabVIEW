# LabVIEW + TestStand 自動テストシステム構築資料

NI社製 LabVIEW（+ TestStand）を利用した自動テストシステムの構築手順をまとめた資料です。
VI（バーチャルインスツルメント）の作り方、TestStand シーケンスの設定手順を中心に記載しています。

---

## 1. この資料の目的

複数の操作者が手動で実施している以下の操作を、LabVIEW + TestStand で自動化し、
**再現性の高い試験** と **工数削減・試験品質向上** を実現するための構築手順を示す。

- 模擬電源（高圧／低圧）の制御
- 供試体マイコンの CAN 操作
- 測定機器（オシロ／ロガー／RAMScope）の操作・ログ取得
- 上記をシビアなタイミング条件どおりに時系列実行

```
                  ┌─────────────────────────────────────────────┐
                  │                  PC (Windows)               │
                  │  ┌───────────────┐     ┌─────────────────┐  │
                  │  │   TestStand   │────▶│     LabVIEW     │  │
                  │  │  (試験フロー)  │ VI  │  (機器個別制御)  │  │
                  │  │  条件/結果管理 │ Call│  ms単位の制御    │  │
                  │  └───────────────┘     └─────────────────┘  │
                  └───────────────┬────────────────┬────────────┘
                                  │ Ethernet (LAN) │ USB/専用IF
        ┌──────────────┬──────────┼──────────┬─────┴──────┬──────────────┐
        ▼              ▼          ▼          ▼            ▼              ▼
  オシロ DLM5058   ロガー MX100  高圧電源     低圧電源     RAMScope       CANインタフェース
  (電圧/電流)      (温度)        RZ-X2-100K-H PPX36-3      GT170          (USB-CAN / XNET)
```

## 4. 設計の基本方針（要点）

1. **1イベント = 1VI**（例：`RAMScope_Log_Start.vi`）
   並び替え・流用・仕様変更に強い構成にする。
2. **試験条件は TestStand 側で変数管理**（電圧条件・電流条件・制御モード番号・Ramp 時間など）。
   VI 側はハードコードせず、すべて入力端子で受け取る。
3. **待ち時間・同期／非同期は TestStand 側で明示管理**。VI は「即応する最小操作」に徹する。
4. **負荷電流など時間のかかる変化処理は非同期で実行**し、変化中に他処理を割り込めるようにする。
5. **異常系は安全優先のシャットダウン順序を Cleanup で必ず実行**
   （高圧 → データ退避 → 低圧/DUT → RAMScope リセットの順）。

## 5. 注意事項

- 本資料は構築手順・設計指針のテンプレートです。実機の型式・ファームウェア・ドライバ
  バージョンによりコマンド体系や VI 名が異なる場合があるため、必ず各機器のプログラミング
  マニュアル（通信コマンド仕様）と NI のドライバドキュメントを併用してください。
- CAN（CANalyzer/USB-CAN）と RAMScope の実装方式は、**実装前に方式選定（方針決定）が必要**な
  項目です。[09](./docs/09_CAN通信の実装.md) / [10](./docs/10_RAMScope実装方針.md) を参照のうえ判断してください。
